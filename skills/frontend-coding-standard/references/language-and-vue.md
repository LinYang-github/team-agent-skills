# TypeScript、JavaScript 与 Vue 实现规范

本文件服务于 Vue 3 默认技术基线。React 特例的进入条件、隔离方式和记录要求见 [framework-policy.md](framework-policy.md)。

## 语言策略

- 新增边界、共享模块、API 契约和复杂状态优先使用 TypeScript。
- 已有 JavaScript 项目不要求一次性迁移；先从新模块、公共接口和高风险逻辑开始补充 JSDoc、运行时校验或逐文件迁移。
- 不用 any 掩盖不确定性；外部数据使用 unknown 或明确 DTO，再通过校验和映射进入领域类型。
- 开启严格检查的项目不得为了通过构建关闭 strict、noUnused 或 noUnchecked 等既有门禁。
- 类型只描述数据和行为契约，不把运行时逻辑塞进复杂类型中。

## Vue 单文件组件

- 默认使用 script setup；组件按“输入、展示/交互、输出、副作用”组织。
- props、emits、slots 和 expose 的边界显式声明，事件名称和载荷保持稳定。
- 模板负责声明结构和简单表达式；复杂过滤、排序、异步流程和业务判断移到 computed、composable、store 或纯函数。
- 每个组件有清晰职责；页面超过合理复杂度时按领域区域或状态拆分，不以文件行数作为唯一标准。
- v-for 使用稳定 key；避免用数组索引作为会变化列表的 key。
- v-html、动态组件和任意 HTML 注入需要明确来源和安全边界，不直接渲染未经处理的外部内容。
- watch 只用于同步副作用或确实需要监听的外部变化；能用 computed 表达的派生值不要用 watch 复制状态。

## Composable 与 Store

- composable 负责可复用的状态逻辑和生命周期协作，输入输出明确，避免隐式依赖某个页面。
- Pinia/store 负责跨页面共享状态和动作；局部输入、临时弹窗和单个组件状态留在组件内。
- store 不直接操作大量 DOM，不负责渲染细节；服务层负责 API，store 负责协调和缓存策略。
- 异步动作要有 loading、成功、失败和取消/失效语义，避免并发请求互相覆盖旧结果。
- 持久化状态要有键名、版本和恢复失败策略；不把敏感凭据或完整业务对象无边界写入 localStorage。

## JavaScript 兼容写法

- JavaScript 项目保持现有模块系统和构建方式，不引入与项目不兼容的语法或类型运行时。
- 对外函数使用清晰参数约定，必要时用 JSDoc、默认值和运行时断言补足类型信息。
- 不通过动态属性、隐式 this、全局单例和深层对象变异制造不可见的数据流。
- 新增复杂逻辑优先写成可独立测试的纯函数，再由组件或 store 调用。

## 特例模块的框架边界

若经批准的项目同时存在 Vue、React 或 TSX 专用组件：

- 保持各自框架边界，不在一个组件中混合两套生命周期和状态模型。
- 通过宿主组件、明确的 props/回调和适配类型通信。
- 不因少量 React Flow、图表或编辑器代码而迁移整个应用框架。
