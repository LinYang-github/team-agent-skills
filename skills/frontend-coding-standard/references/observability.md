# 前端可观测性

本文件规定前端如何让错误、请求、性能和关键流程可诊断。它不定义组织的监控平台、告警阈值或业务审计制度；采集内容必须遵循安全、隐私和数据最小化要求。

## 观测边界

- 全局异常、路由加载、请求客户端、关键流程和基础设施是主要观测边界；页面不各自接入一套错误上报或日志格式。
- 日志、错误上报、性能事件和用户行为事件使用统一版本、环境、模块和请求关联信息。
- 观测代码不能改变业务结果；上报失败、网络慢或第三方 SDK 不可用时，页面仍保持可用。
- 同一错误在请求层、store 和页面只记录一次，避免重复上报和噪声放大。

## 错误与异常

- 捕获 Vue 全局错误、未处理 Promise、路由异步组件失败、资源加载失败和请求异常，并保留稳定的 error code、cause、版本和请求 ID。
- 区分用户可恢复错误、开发缺陷、会话失效、网络异常、第三方失败和不可预期异常，分别决定提示、重试、降级和上报级别。
- 错误上报包含最小必要上下文：路由、模块、操作阶段、环境、版本、浏览器能力和脱敏后的资源标识。
- 不把完整表单、响应体、token、Cookie、密码、身份信息或敏感业务字段发送到日志和错误平台。
- 采集堆栈、source map 和源码版本时控制访问范围，不因方便定位而公开内部代码和数据。

## 请求与关联

- 请求客户端统一生成或透传 request ID、trace ID、接口名称、状态码、耗时、取消原因和重试次数。
- 请求层记录失败和关键慢请求，业务页面只补充必要的领域上下文，不重复打印完整请求。
- 关联信息在跨页面、轮询、WebSocket/SSE 和后台任务中保持可追踪；页面卸载或会话失效时清理关联上下文。
- 生产环境对日志、错误和性能事件使用可配置级别、采样和限流，避免异常高峰反过来拖慢应用。

## 性能与流程事件

- 观测首屏、关键路由、资源加载、长任务、接口耗时、交互延迟、内存异常和错误率；指标服务于用户任务和排障，不追求无意义的事件数量。
- 关键业务流程记录开始、成功、失败、取消、重试和耗时，事件名和字段保持稳定；不要把业务数据本身当作事件名。
- 复杂流程、算法任务和长任务使用统一任务 ID 关联前端阶段、请求和结果展示。
- 性能事件不应依赖用户输入或敏感内容，必要时只发送长度、类别、摘要或稳定标识。

## 版本与发布

- 每次错误、性能和流程事件带有应用版本、构建标识、环境和发布批次，便于定位回归范围。
- 发布后观察白屏、资源加载失败、路由失败、关键请求错误、错误率和性能变化；发现异常时能关联到具体版本和功能开关。
- 回滚或关闭功能开关后，旧版本客户端和缓存中的事件仍应可识别，不把多个版本混成同一指标。

## 验证与隐私检查

- 测试验证全局异常、错误边界、请求关联、脱敏、采样和上报失败降级；不依赖真实生产观测平台。
- 变更观测字段、事件名、采样率、source map 或第三方 SDK 时记录兼容影响和数据风险。
- 交付前确认开发日志、测试事件和调试上报不会进入生产；生产构建不包含秘密、测试账号和未授权诊断入口。
