# 原生控件与公共组件

本规范不是禁止原生 HTML，而是禁止在核心业务页面直接暴露不可控的浏览器默认视觉和复杂交互。公共组件应保留正确语义，并统一主题、状态、键盘、焦点和数据契约。

## 默认策略

| 控件 | 默认实现 | 说明 |
| --- | --- | --- |
| `select` | `Select`/`SearchSelect` | 原生展开面板跨浏览器差异大 |
| `input[type=date/time/month]` | `DatePicker`/`TimePicker` | 保留文本录入和键盘操作 |
| `input[type=color]` | `ColorPicker` | 原生颜色面板不可统一主题 |
| `input[type=range]` | `Slider` | 轨道、拇指和刻度需统一 |
| checkbox/radio/switch | 公共表单组件 | 保留隐藏的语义元素或正确 ARIA |
| `dialog`、复杂 `details` | `Modal`/`Drawer`/`Collapse` | 统一遮罩、焦点和关闭行为 |
| 浏览器校验气泡 | 表单错误组件 | 错误应可定位、可修复、可测试 |
| `title` 原生提示 | `Tooltip` | 不能承载必须阅读的信息 |

## 语义与实现要求

- 不用 `div` 或 `span` 模拟按钮、输入框、复选框和链接；需要自定义外观时，保留原生元素或完整实现对应 ARIA、键盘和焦点契约。
- 选择器组件至少支持受控值、禁用、加载、空数据、错误、键盘上下选择、`Enter`、`Esc`、点击外部关闭和焦点返回。
- 自定义列表框、组合框和树选择器必须正确使用 `role`、`aria-expanded`、`aria-controls`、`aria-activedescendant` 或等价语义，并覆盖屏幕阅读器和键盘测试。
- 日期/时间组件支持合法文本输入、格式化、时区约定和错误定位，不把日期只能通过鼠标选择作为隐含前提。
- 文件上传使用自定义触发按钮、进度和错误列表，但文件选择对话框可以保留系统原生能力。
- 原生控件只读、禁用、错误、聚焦和加载状态不得由页面临时覆盖；通过公共组件和主题令牌集中维护。

## 例外条件

以下情况可以使用原生控件，但应记录范围和原因：

- 只有少量静态选项，且浏览器默认样式不会破坏项目主题或任务效率。
- 系统原生能力本身是目标，例如文件选择、打印、系统身份认证。
- 无障碍、触控或特定运行环境经过验证，原生控件明显优于自定义实现。
- 原生控件仅作为自定义视觉组件的语义和输入层，不直接暴露默认视觉表面。

例外不能仅因为组件库默认实现、开发方便或“所有浏览器都能显示”而放行。

## 验证要求

公共控件变更至少验证：默认、悬停、按下、聚焦、禁用、加载、错误、空数据、长文本和键盘路径；涉及主题时同时验证浅色和深色。不得用截图中看起来相似替代行为和无障碍验证。
