# 国际化与内容工程

本文件规定多语言和用户可见内容如何进入前端代码。业务术语、翻译质量和文案风格由产品或内容规范决定，本文件只规定 key、格式化、加载和回退机制。

## 文案与语言包

- 用户可见文案使用稳定的语义 key，不在模板和业务逻辑中散落硬编码；开发调试文本也不要伪装成正式文案。
- 语言包按领域或路由拆分，避免一次加载全部语言和全部页面文案；切换语言时明确加载、失败和回退状态。
- key 反映语义而不是当前中文文案，避免修改文案就大面积重命名 key；删除 key 时检查所有调用方和历史回退。
- 缺失翻译使用可追踪的回退策略，不静默显示空字符串、`undefined` 或内部 key。
- 错误码、状态码和用户展示文案分离；同一错误在不同上下文可使用不同表达，但映射集中维护。

## 格式化与排序

- 日期、时间、数字、百分比、货币、单位和相对时间使用统一的 locale-aware 格式化工具，不在组件内手工拼接。
- 排序、大小写转换、搜索匹配和文本截断考虑当前语言和 Unicode 规则；不要默认所有字符按 ASCII 处理。
- 领域单位和精度遵循产品或系统规范；前端负责调用统一格式化边界，不自行改变数据含义。
- API DTO、领域模型和展示文案分层，不能用翻译后的文字作为后端枚举、权限值或业务判断。

## 布局与输入

- 设计和实现考虑文本长度膨胀、长复合词、数字格式变化、从右到左语言或项目明确不支持的语言边界。
- 不用固定宽度、截断或隐藏文本掩盖翻译溢出；长标题、错误文案和表格列应有可恢复的查看方式。
- 用户输入、导出和复制内容明确语言、格式和编码；解析日期、数字和分隔符不能只依赖浏览器默认。
- 语言切换后保留或清理表单、筛选、路由和缓存状态的规则应明确，避免同一页面出现混合语言。

## 测试与维护

- 至少测试默认语言、英文或最长语言包、缺失 key、格式化边界和异步语言包加载失败。
- 语言包变更配合类型或 key 检查，避免拼写错误只有运行到特定页面才暴露。
- 视觉回归覆盖长文案、长数字、错误提示、表格列和弹窗；工程测试关注 key、格式化和回退行为。
- 翻译内容不应携带未经审查的 HTML；需要富文本时使用受控插槽或安全渲染方案。
