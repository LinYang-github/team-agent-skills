# 企业前端框架策略

## 默认基线

企业级新前端项目默认采用：

- Vue 3。
- Composition API 与 `<script setup>`。
- TypeScript 作为新代码默认语言。
- Vite 作为默认构建工具，Vue Router 负责路由，Pinia 仅用于跨页面或跨组件共享状态。
- 组件库沿用组织已选定的实现；不要因框架规范擅自替换现有组件库。

这是一条工程默认基线，不要求所有存量项目一次性重写，也不把具体组件库的视觉选择扩展为本技能的硬约束。

## React 特例机制

React 不是与 Vue 并列的默认选项。只有满足下列至少一项，并完成记录后，才可以新建或保留 React 模块：

1. 项目已经是成熟的 React 主应用，迁移成本和风险明显高于收益。
2. 关键专用库、编辑器或宿主平台只有 React 生态，且没有可接受的 Vue 替代方案。
3. 交付、运行时或团队约束明确要求 React。

特例记录至少包含：选择原因、影响范围、宿主边界、通信方式、测试责任、长期维护人或团队、复评时间，以及可以删除特例的条件。

以下情况不能作为特例理由：个人偏好、短期赶工、某个普通 UI 组件暂时缺少封装，或仅仅因为一个局部依赖使用 React。

## 混合框架隔离

- Vue 应用中原则上不新增 React 页面；React 只能放在明确隔离的宿主边界内。
- Vue 与 React 之间通过稳定的 props、回调、适配器或 Web Component 通信，不共享对方的生命周期、组件实例或内部状态。
- 不在同一组件中混合两套生命周期、状态模型和模板语法。
- 局部 React 编辑器、图形或流程库不改变主应用的 Vue 架构。
- 混合框架引入额外构建体积、调试复杂度和测试矩阵，方案评审时必须显式评估。

## 存量项目与渐进迁移

- 先读取项目真实基线，再判断哪些约束是已批准的存量事实，不能把技能中的默认值误当成现状。
- 存量 Vue 项目按默认基线持续收敛；新增模块直接遵循 Vue 3、Composition API 和 TypeScript。
- 存量 JavaScript 项目不要求一次性改写，优先在公共接口、请求响应、复杂状态和高风险逻辑中补充类型或运行时校验。
- 存量 React 项目不因技能加载而强制重写；新模块遵循项目既有边界，同时评估迁移到 Vue 的收益、风险和交付窗口。
- 触碰旧模块时做小步迁移，记录兼容层、未迁移范围和删除兼容层的条件。
