# 无障碍工程实现

本文件规定无障碍要求如何落到 Vue 组件、DOM、焦点和测试中。`ui-ux-standards` 负责交互意图和界面表达，本文件负责实现不破坏语义、键盘和辅助技术行为。

## 语义与控件

- 优先使用原生 HTML 语义元素和浏览器已有行为；只有原生控件无法满足需求时才创建自定义控件。
- 自定义按钮、链接、菜单、树、列表框、对话框和标签页必须明确角色、名称、状态、键盘行为和焦点边界。
- 不用 `div`、`span` 或点击事件伪装按钮和链接；如果不得不使用自定义宿主，应完整补齐键盘、焦点和可访问名称。
- 图标按钮、仅图标操作和状态徽标提供稳定的可访问名称；装饰图标标记为隐藏，避免屏幕阅读器重复读取。

## 焦点与键盘

- `Tab` 顺序与任务顺序一致，不通过大量 `tabindex` 正值强行重排焦点。
- 弹窗、抽屉、菜单和浮层打开时将焦点移入合理位置，关闭后恢复到触发控件或可解释的后续位置。
- 组件卸载、路由切换和异步加载不能让焦点落到不可见或已删除的节点。
- 键盘快捷键、方向键和 `Esc` 行为遵循 `ui-ux-standards` 的作用域约定，不覆盖输入框和浏览器原生编辑行为。
- 拖拽、悬停、颜色或手势操作必须有键盘或其他可完成任务的替代方式。

## 状态与动态内容

- 加载、成功、错误、空数据、权限不足和实时更新状态要以适当的文本、角色或 live region 告知辅助技术，避免只改变颜色或图标。
- 错误信息与对应字段建立可访问关联；提交失败后将焦点放到错误摘要或第一个可修复字段，并保留用户输入。
- 禁用、只读、选中、展开、折叠和进度状态使用正确的 DOM 属性或 ARIA 状态，不只通过 CSS 类表达。
- 高频实时更新控制播报频率，不让日志、轮询和表格刷新持续打断用户。

## 表单和自定义组件

- 表单控件有明确 label、说明、必填和错误关联；占位符不能替代标签。
- 自定义选择器、日期、树、表格和流程编辑器应先定义键盘模型，再实现事件处理和焦点移动。
- 组件公开 props、事件和状态时保持语义稳定，避免由内部 DOM 结构决定调用方的无障碍行为。
- 主题、缩放、系统字体和高对比设置不应导致内容被裁切或控件不可用。

## 测试与验收

- 组件测试覆盖键盘进入、移动、确认、取消、焦点恢复和错误关联；不要只测试鼠标点击。
- 使用自动化规则检查作为基线，但不能替代真实键盘操作、屏幕阅读器抽查和目标浏览器验证。
- 修改公共组件、页面壳、弹窗、表格、树和导航时，扩大无障碍回归范围。
- 无障碍修复不应通过隐藏内容、删除语义或阻止浏览器默认行为来“消除”检查错误。
