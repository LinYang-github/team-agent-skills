# 配置、构建与发布

本文件规定前端如何区分环境、构建产物和发布行为。它不替代组织的 CI/CD、基础设施或发布审批制度，但要求前端项目对运行约束保持显式和可验证。

## 环境与运行配置

- 环境变量、运行时配置和默认值集中定义并在启动或构建早期校验；缺少关键配置应尽早失败，不能等到用户点击页面才暴露。
- 区分构建时配置和运行时配置，明确哪些配置会进入浏览器；前端可见配置默认不是秘密。
- API 地址、应用基础路径、静态资源前缀、认证端点、功能开关和日志级别不得散落在业务组件中。
- 不通过隐式的开发机文件、全局变量、个人代理或本地服务假设完成构建；项目脚本应能说明真实依赖。
- 配置对象按领域和生命周期拆分，禁止把整个 `import.meta.env` 或全局配置对象无边界传入页面。

## 功能开关与兼容

- 功能开关有明确的默认值、类型、作用范围、启用条件、观测方式和删除条件；短期开关不得永久留在代码中。
- 前端开关只控制界面和请求编排，不替代后端权限、数据隔离或安全判断。
- 新旧接口、路由和组件并存时集中维护兼容层，记录迁移边界和删除条件，避免在每个页面复制版本判断。
- 浏览器、操作系统、语言、基础路径和部署模式的支持矩阵写入项目可发现的文档或脚本，不依赖开发者记忆。

## 构建产物

- 生产构建检查环境地址、调试日志、Mock 处理器、测试数据、内部域名、密钥样式字符串和意外依赖。
- 构建输出包含可追踪的应用版本、提交标识或发布批次；错误上报和诊断日志使用同一版本标识。
- source map、压缩、缓存头和静态资源命名按安全与诊断需求决定；不因为方便排错就无条件公开敏感 source map。
- 静态资源、路由回退、基础路径、刷新直达和 CDN/代理前缀在真实部署形态中验证。
- 生产构建默认不依赖 CDN 或其他未锁定的在线资源；如部署平台必须使用 CDN，应将资源纳入版本化发布清单并提供不可用时的失败或降级策略。
- 修改共享包、构建入口或分包策略时，分别检查包构建、应用消费、产物体积和运行时加载。

## 发布与回滚

- 发布前至少完成类型检查、测试、构建和必要的浏览器验证；实际命令和未执行项目如实记录。
- 破坏性接口、路由和配置变更优先采用可兼容的渐进发布，避免前端先上线后无法回滚。
- 每次发布明确影响范围、依赖版本、开关状态、数据迁移前置条件和回滚方式。
- 回滚不仅恢复静态文件，也要确认缓存、运行配置、接口兼容和错误上报版本不会继续指向失效资源。
- 发布后观察资源加载失败、关键请求错误、白屏、路由失败和性能异常，达到阈值时按项目流程止损。
