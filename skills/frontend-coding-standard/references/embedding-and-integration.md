# 页面嵌入与宿主集成

本文件规定业务页面被其他前端系统复用时的工程边界、接入契约和验证方式。它不规定页面视觉风格；主题、密度和交互表达按 ui-ux-standards 执行。

## 目标与适用范围

当一个页面需要被其他系统打开、嵌入或组合时，先定义稳定的页面边界和宿主契约，再选择交付方式。适用于：

- 业务页面提供独立 URL、深链接或降级访问入口。
- Vue 页面以 npm 包或组件库供其他 Vue 宿主复用。
- 页面需要跨框架运行时交付为 Web Component。
- 完整子系统需要独立部署、独立发布并由宿主组合。
- 遗留系统只能通过 iframe 接入。
- 为上述接入方式提供可运行的 Integration Portal，并在 CI 中验证真实集成链路。

不要为了“支持嵌入”复制一套业务页面，也不要为了形式创建项目当前不支持的技术方案。

## 三个维度先分开

这些选项不在同一维度，设计时分别决策：

| 维度 | 选项 | 解决的问题 |
| --- | --- | --- |
| 访问方式 | 独立 URL、深链接 | 用户如何打开页面、刷新和分享上下文 |
| 交付方式 | npm 包、构建产物、远程入口 | 宿主如何获得页面代码 |
| 运行时组合 | 组件、Web Component、微前端、iframe | 页面如何与宿主进程、样式和生命周期协作 |

独立 URL 是基础访问和降级入口，不因采用组件包或微前端而删除。一个页面可以同时拥有独立 URL 和组件交付方式，但必须明确两者的能力差异。

## 方式选择

默认优先级如下，实际选择需记录宿主框架、隔离要求、部署边界、性能预算和团队维护能力：

| 场景 | 首选 | 适用边界 | 主要代价 |
| --- | --- | --- | --- |
| Vue 宿主、深度交互、共享状态或主题 | Vue npm 包/组件库 | 页面边界稳定，宿主可提供约定的依赖和能力 | 依赖 Vue 宿主与版本兼容，隔离较弱 |
| 跨框架、组件级嵌入 | Web Component | 需要 DOM 级标准边界，组件交互不应依赖宿主框架 | 复杂表单、路由和类型共享成本更高 |
| 完整子系统、独立部署和团队自治 | 微前端 | 子应用拥有较完整路由和发布生命周期 | 运行时、鉴权、依赖和故障治理复杂 |
| 强隔离、遗留系统或跨技术栈快速接入 | iframe | 需要 CSS/JS/依赖和安全边界隔离 | 通信、无障碍、性能和路由体验较弱 |
| 直接访问、刷新、分享或故障降级 | 独立 URL | 所有模式都应保留 | 需要维护应用壳和入口状态 |

默认采用 Vue 3 的项目，优先抽取 Vue 组件包；只有跨框架要求、独立部署要求或强隔离要求成立时，才引入 Web Component、微前端或 iframe。不要因为宿主使用 React 就把整个业务项目迁移为 React。

## 页面边界与应用壳

将完整应用壳与可嵌入业务页面分离：

- 应用壳负责全局路由、登录跳转、顶层布局、全局错误边界和独立 URL 入口。
- 业务页面负责领域数据、局部路由状态、表单和业务事件，不直接假设存在某个顶层导航、侧栏或全局 store。
- 可嵌入页面使用明确的 props/输入、事件/输出和异步状态；不要通过 window、隐式 DOM 查询或深层组件事件链与宿主耦合。
- 页面离开或组件卸载时必须清理请求、订阅、定时器、事件监听、对象 URL 和临时存储。
- 页面内部需要路由时，将路由基路径、参数解析和导航适配抽成可替换适配器；嵌入到无路由宿主时仍能完成核心任务。

建议为领域页面提供稳定的公开入口，例如 packages/experiment-design 的 ExperimentDesignPage，应用路由只负责把独立 URL 的参数映射到该入口，不让宿主直接引用 src/views 深层路径。

## 宿主集成契约

每个可嵌入页面都要声明一份版本化契约。契约可以由 TypeScript 类型、README 和运行时校验共同表达，至少包括以下内容。

### 输入与上下文

- 资源上下文：资源 ID、项目/试验上下文、只读或编辑模式，以及必填参数和默认值。
- 宿主能力：请求客户端、认证令牌获取、当前用户或权限查询、日志和遥测适配器；能力通过 props、provide/inject 接口或显式 adapter 注入。
- 主题与语言：支持的主题值、语言值、变更通知和默认行为；不要读取宿主私有的 CSS class 或全局变量作为唯一协议。
- 功能开关与配置：只接受经过类型校验的白名单配置，不把整份宿主配置对象透传给页面。

### 生命周期与输出

- 明确 mount、ready、error、unmount 等生命周期时点；异步初始化失败必须能被宿主感知和重试。
- 业务动作通过命名空间事件或回调输出，例如 experiment:saved、experiment:dirty-change，不要发送无语义的 change。
- 事件载荷使用稳定、最小的 DTO，不传递 Vue 响应式对象、组件实例、完整接口响应或敏感信息。
- 需要宿主导航时发出意图事件，由宿主决定实际路由；页面不能强制修改宿主的 history，除非契约明确允许。
- 暴露 destroy/卸载能力并保证幂等；重复挂载、快速切换和初始化取消必须有测试覆盖。

### 请求、鉴权与错误

- 业务包不自行猜测 token 存储位置；通过宿主注入的请求或认证适配器访问后端。
- 请求层统一携带请求 ID、取消信号和错误映射；页面区分加载、空数据、无权限、会话失效、校验失败、网络失败和服务端异常。
- 认证失效、无权限和资源不存在由统一错误契约表达，宿主可选择登录、提示、切换上下文或降级到独立 URL。
- 不把真实生产密钥、账号、Cookie 或完整响应写入 Portal、Mock、日志或示例代码。

### 主题、样式和隔离

- 组件公开的样式入口、CSS 变量和主题属性要有明确前缀或命名空间，避免污染宿主全局样式。
- 不依赖宿主具体组件库的内部选择器；若必须使用宿主组件，声明 peer dependency 和兼容版本。
- 主题切换通过受控属性或适配器完成，至少验证亮色、暗色和跟随系统策略；不在组件内复制另一套主题系统。
- iframe 使用 postMessage 时校验 origin、消息类型和载荷版本；禁止接收任意消息执行导航或代码。

## 交付方式约束

### Vue npm 包/组件库

- 公开导出集中在包入口，导出类型、组件、适配器和版本信息；禁止宿主引用源码深层路径或 dist 内部文件。
- Vue、组件库和宿主能力适合设为 peer dependency；明确支持的 Vue/组件库版本范围。
- 同时生成适合项目规范的 ESM/类型产物；UMD 仅在确有传统宿主需求时提供。
- 包内不执行模块导入即发起请求、跳转、注册全局 store 或修改全局样式。
- 构建包后必须由真实宿主或 Portal 消费一次，不能只在源项目内部运行测试。

### Web Component

- 对外使用属性、特性、标准 DOM 事件和自定义元素生命周期；事件名称、冒泡策略和载荷类型要文档化。
- 不把 Vue 响应式对象或框架实例暴露给宿主；跨边界数据使用可结构化克隆的 DTO。
- 明确 Shadow DOM、字体、弹层容器、焦点管理和表单提交策略；不能假设宿主 CSS 可穿透组件内部。
- 提供元素卸载、重新连接和属性变更测试，覆盖重复注册和版本并存风险。

### 微前端

- 只有当子系统确实需要独立部署、独立路由或独立团队发布时采用；不要把单个按钮或简单页面微前端化。
- 先定义路由前缀、资源加载失败、鉴权续期、主题/语言、跨应用事件、依赖共享和版本回滚协议。
- 子应用不得直接修改宿主全局 store、路由表或 DOM；通过平台适配器和命名空间事件通信。
- 明确同域与跨域、静态资源缓存、CSP、source map、监控归属和故障隔离策略。

### iframe

- 仅用于强隔离、遗留集成或暂时无法组件化的系统；应保留独立 URL 作为同一页面的可访问入口。
- 使用 sandbox、允许列表和 CSP 限制能力；通过 postMessage 建立版本化通信协议并校验消息来源。
- 明确高度调整、加载超时、网络错误、登录过期、键盘焦点和窗口尺寸变化；不能把 iframe 内部 DOM 当作宿主 API。
- 需要共享主题、语言或业务状态时，优先评估组件包/Web Component 是否更合适。

## Integration Portal 标准交付物

Integration Portal 是“可运行的参考宿主系统”，不是面向最终用户的演示模式，也不是第二套生产业务系统。凡项目声明支持某种嵌入方式，就应为实际支持的方式提供 Portal；不支持的方式不创建空目录或伪实现。

推荐目录：

    examples/
    └── integration-portal/
        ├── package.json
        ├── README.md
        ├── src/
        ├── mock/
        └── e2e/

同一项目确实支持多种方式时，再按方式拆分：

    examples/integration-portal/
    ├── vue-library/
    ├── web-component/
    ├── iframe/
    └── microfrontend/

Portal 必须尽量消费已构建包、npm pack 生成的 tarball 或内部制品版本，不能直接引用业务项目源码路径、内部 alias 或未发布的全局变量。它至少验证：

1. 正常加载、刷新、路由切换、重复挂载和卸载。
2. 上下文参数、认证注入、请求适配和权限失败。
3. 加载、空数据、校验失败、网络异常、超时、重试和资源不存在。
4. 主题切换、语言切换、窗口尺寸变化和焦点/键盘行为。
5. 表单草稿、未保存离开、重复提交、保存失败和恢复。
6. 事件载荷、宿主导航意图、错误边界、请求 ID 和关键遥测字段。
7. Mock 与真实接口的切换；Mock 仅用于本地和测试，不能携带生产凭据。

Portal README 说明运行命令、制品来源、宿主注入能力、支持的版本范围、环境变量、Mock 开关和已知限制。Portal 的目标是让其他系统按文档复制接入方式，而不是复制业务代码。

## CI 与版本治理

- 发布前先完成类型检查、包构建和 Portal 构建；Portal 必须安装并消费本次构建产物。
- 对公开 props、事件、适配器和路由契约做类型或契约测试；破坏性变更必须提高主版本或提供迁移适配层。
- 至少保留一个真实宿主的冒烟测试，验证构建产物而非源码别名可用。
- 记录 Vue/组件库 peer dependency、浏览器支持范围、主题/语言能力和宿主适配版本。
- 发现宿主能力缺失时返回结构化错误并提供降级路径，不用隐式全局变量“凑合运行”。
- 删除、重命名公开入口或事件前，先搜索 Portal、示例宿主和其他项目的消费点，提供迁移说明。

## 现有 SPA 的渐进改造顺序

1. 先保留独立 URL，识别页面输入、输出、数据服务和应用壳依赖。
2. 抽取领域类型、API 服务、错误映射和可测试 composable，移除页面对全局壳的隐式依赖。
3. 为 Vue 宿主提供组件包入口和最小适配器，先在 Portal 中消费构建产物。
4. 根据真实跨框架或隔离需求，再评估 Web Component、微前端或 iframe；不要预先实现所有模式。
5. 将 Portal 冒烟测试接入 CI，再逐步扩大真实宿主和版本兼容矩阵。

## 交付检查

- [ ] 已说明独立 URL、交付方式和运行时组合方式，未把三个维度混为一谈。
- [ ] 页面与应用壳边界清晰，输入、输出、生命周期和清理策略有契约。
- [ ] 认证、请求、错误、主题、语言、事件和可观测性没有依赖隐式全局状态。
- [ ] 选择的嵌入方式与宿主框架、隔离、部署和维护边界匹配，并记录了未选择其他方式的原因。
- [ ] Portal 消费真实构建产物，覆盖正常、失败、刷新、卸载、主题和未保存状态。
- [ ] 已运行包构建、Portal 构建和至少一条真实宿主/契约冒烟测试，并记录未覆盖风险。
