# 表单、草稿与未保存数据

本文件规定复杂表单、分步向导和编辑页面如何管理模型、校验、草稿与离开保护。字段顺序、文案、确认方式和视觉层级由 `ui-ux-standards` 决定，本文件负责数据生命周期和工程可靠性。

## 表单模型

- 区分后端 DTO、领域模型、表单模型和草稿模型；不要把接口响应对象直接双向绑定到模板。
- 表单默认值、可空性、枚举、单位和转换集中定义；加载已有数据时显式映射，提交时再映射回 API 契约。
- 表单状态至少区分初始、加载、编辑、校验失败、提交中、提交成功、提交失败和只读/无权限，不用一个 `loading` 覆盖所有状态。
- 复杂表单按领域分组，分步向导定义步骤顺序、步骤完成条件、可回退范围和跨步数据依赖。

## 校验与提交

- 校验规则尽量由可复用 Schema、纯函数或领域服务承载，组件只负责触发和展示结果。
- 区分字段校验、分组校验、跨字段校验、服务端校验和权限/冲突错误；错误保留稳定 code 和可定位字段路径。
- 提交失败保留用户输入，聚焦可修复错误或错误摘要；网络失败、鉴权失效和业务校验不能显示为同一种字段错误。
- 提交按钮、快捷键和重复触发共用同一提交状态；副作用请求需要幂等策略或明确禁止重复提交。
- 成功后明确清理、保留或更新草稿，不能让旧草稿覆盖刚保存的数据。

## 草稿生命周期

- 草稿有明确的所有者、作用域、版本、创建/更新时间和过期策略；键名和存储版本稳定，恢复失败可以安全清理。
- 只持久化必要字段，不把 token、完整用户对象、超大附件或不可序列化实例写入草稿。
- 进入编辑、定时、字段变化或步骤切换时的保存策略应明确；自动保存必须防抖、可取消并避免旧响应覆盖新草稿。
- 草稿保存失败保留本地输入并提供重试、导出或放弃路径；不能无提示地静默丢失。
- 服务端草稿与本地草稿同时存在时，明确版本比较、冲突提示、覆盖和合并策略。

## 未保存离开保护

- `dirty` 状态基于规范化后的表单模型比较，而不是简单比较对象引用或输入事件次数。
- 路由离开、浏览器刷新、关闭窗口、切换试验/项目或切换步骤时，按风险触发项目内确认组件或浏览器允许的离开保护。
- 已成功提交、已保存草稿、只读页面、自动保存进行中和保存失败的离开语义分别处理。
- 离开确认应说明影响范围，并提供继续编辑、保存/重试或放弃修改的明确选择；不要用重复弹窗阻断无风险导航。
- 多标签页或多个编辑入口同时修改时，至少检测版本变化或提示潜在覆盖。

## 恢复与测试

- 刷新、网络断开、会话失效、权限变化和服务端冲突后，恢复路径保留用户可理解的上下文和下一步。
- 测试覆盖默认值、回填、字段/跨字段校验、步骤回退、重复提交、自动保存竞态、保存失败、刷新恢复和放弃修改。
- 大型表单和附件处理检查内存、序列化体积、对象 URL 清理和性能，不为了恢复而无限缓存完整页面状态。
