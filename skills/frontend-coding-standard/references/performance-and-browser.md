# 性能、资源与浏览器运行

本文件规定性能优化如何基于真实基线和用户任务实施。不要以微优化替代对包体积、请求瀑布、渲染阻塞、内存泄漏和大数据量场景的处理。

## 基线与预算

- 先记录首屏、关键路由、主要交互和大数据量场景的基线，再决定优化目标；至少区分开发环境和生产构建结果。
- 关注构建体积、首屏资源、关键请求、长任务、交互延迟、内存增长和错误率，不只看单个 Lighthouse 分数。
- 为关键应用设定可执行的包体积、首屏请求和性能回归预算；超出预算时说明依赖、功能和收益取舍。
- 不因追求指标删除必要状态、降低可读性或绕过错误处理；性能优化必须保持功能和可访问性。

## 加载与构建

- 路由页面、重量级编辑器、图表和非首屏模块默认懒加载；公共壳和首屏必要资源保持明确的加载边界。
- 组件库、图标、语言包和大型数据按需引入，避免一个页面导入完整集合；定期检查重复依赖和异常 chunk。
- 图片、字体和静态资源选择合适格式、尺寸和缓存策略；不把大型二进制直接塞进 JavaScript 包。
- 预加载、预取和缓存只用于有证据的高概率路径，并明确失效条件；不要用缓存掩盖接口或状态设计问题。

## 渲染与大数据

- 模板保持轻量；复杂过滤、排序、映射和聚合移到可测试的纯函数、computed 或服务边界，并避免不必要的重复计算。
- 大表格、树、时间线、日志和图形数据按分页、窗口化或虚拟滚动处理；同时保留键盘、选中和定位语义。
- 控制响应式范围，避免把巨大原始对象和不可变数据全部深度代理；大型只读数据按项目实际情况使用浅层响应或非响应引用。
- 搜索、联想、筛选和实时刷新需要防抖、节流、取消、去重和结果顺序保护；不要让过期响应覆盖当前状态。

## 网络、并发与内存

- 合并或并行请求要基于依赖关系，避免串行请求瀑布；对幂等请求和有副作用的请求分别设计重试。
- 页面卸载、参数切换或新请求替代旧请求时，取消或忽略旧结果；请求、订阅、定时器、事件监听和对象 URL 必须清理。
- WebSocket、SSE 和轮询明确重连、退避、心跳、停止条件和页面隐藏时的行为，避免后台持续消耗资源。
- 观察内存快照和长时间运行场景，重点检查事件监听、闭包、缓存、图表实例、编辑器实例和 DOM 引用泄漏。

## 浏览器兼容

- 先定义项目支持的浏览器、操作系统和内核范围，再决定语法、API、polyfill 和降级策略；不默认支持所有浏览器。
- 使用特性检测和可恢复降级，不通过 UA 字符串分支掩盖能力差异；浏览器不支持时提供明确状态和替代路径。
- 触碰剪贴板、文件、下载、ResizeObserver、IntersectionObserver、Web Worker 等能力时检查兼容性、权限和失败路径。
- CSS、字体、滚动、弹层和焦点行为在目标浏览器中验证，不能只依赖开发机渲染结果。

## 性能验证

至少覆盖：生产构建体积、关键路由加载、大数据量渲染、慢网络、低性能设备、重复导航、长时间运行和资源失败；实际运行过的工具与命令必须记录。
