# 前端工程编码规范

## 目标

让多个前端项目在可维护性、可测试性、可演进性和故障可定位性上形成共同的工程习惯。企业级前端以 Vue 3 为默认框架基线，新代码优先使用 Composition API、`<script setup>` 和 TypeScript；其他框架只有在记录充分理由后作为受控特例引入。技能负责代码如何组织和实现；页面视觉、交互语义、布局、颜色、圆角、密度和工作台形态交给 ui-ux-standards。

## 适用范围

当前本技能覆盖的前端项目均为桌面端，不做移动端适配，也不安排移动端测试；只有未来明确声明移动端范围时才另行扩展。

前端构建和运行默认不使用在线资源：不引入 CDN、远程字体、远程图标、远程图片或运行时在线脚本，优先使用仓库内资源和已锁定的本地依赖；业务系统明确需要访问的后端 API 不属于此限制。

当用户要求以下事项时启用本技能：

- 新增或重构 Vue 3 页面、组件、路由、状态、接口和工具模块；以及已批准的 React 特例模块。
- 统一 TypeScript/JavaScript 约定、目录结构、模块边界、命名和导入关系。
- 处理请求封装、鉴权、错误、加载、重试、缓存、并发和取消。
- 设计前端路由、路由守卫、页面级代码分割和导航状态。
- 建立 API 边界的前端 Mock、测试夹具和开发数据方案。
- 统一样式组织、设计令牌、主题变量、组件库覆盖和层叠边界。
- 规范日志、`console` 使用、脱敏、级别和生产环境输出。
- 处理前端安全、敏感数据、文件、依赖供应链和安全边界。
- 优化页面性能、资源加载、渲染、内存、浏览器兼容和运行时稳定性。
- 实现语义化 HTML、焦点管理、ARIA、键盘行为和可访问状态。
- 处理国际化、日期/数字/单位格式化、内容长度和语言包。
- 统一环境配置、功能开关、构建产物、发布检查和回滚准备。
- 建立 lint、格式化、类型检查、依赖审查和持续集成质量门禁。
- 实现复杂表单、分步向导、草稿、自动保存和未保存离开保护。
- 建立前端错误、请求、性能、版本和关键流程的可观测性。
- 增加或修复单元测试、组件测试、端到端测试、构建和类型检查。
- 设计业务页面被其他系统访问、嵌入、复用和组合的方式，并建立宿主集成契约与 Integration Portal。
- 对 VibeCoding 产生的重复代码、超大组件、隐式依赖和临时方案进行渐进式治理。

不要因为视觉改造而自动重构业务代码；不要因为一次局部问题而替换整个框架、组件库或构建系统。

## 与 ui-ux-standards 的边界

两项技能可以同时使用，但职责不同：

- ui-ux-standards 决定用户任务、信息层级、组件语义、布局、主题和视觉验收。
- frontend-coding-standard 决定组件如何拆分、数据如何流动、接口如何封装、状态如何管理、错误如何处理、测试如何编写和构建如何验证。

当 UI/UX 方案要求公共组件、设计令牌或页面壳时，本技能负责其代码边界和复用方式；不重新判断视觉方案是否好看或是否符合业务体验。

## 不可违背的原则

1. **先建立工程基线。** 先读取 package.json、构建配置、类型配置、入口、路由、公共组件、状态和测试，再决定改法。
2. **Vue 是企业默认基线。** 新项目和新增主应用默认使用 Vue 3、Composition API、`<script setup>`、Vite；TypeScript 是新代码默认语言，Vue Router、Pinia 和现有企业组件库按项目需要采用。
3. **React 必须经过特例判断。** 只有成熟存量 React 项目、关键专用生态确实仅支持 React，或宿主/交付约束明确要求 React 时才可使用；必须记录原因、范围、影响、维护责任和退出或复评条件。不得因单个 React 库把整个 Vue 应用改成 React，也不得在同一组件内混合两套生命周期和状态模型。
4. **尊重现有技术栈并渐进收敛。** 存量项目先保证兼容和可交付，新代码遵循 Vue 默认基线；迁移按触碰范围推进，不为局部问题贸然换栈。
5. **依赖方向清晰。** 页面可以依赖业务组件和领域模块；底层工具不能反向依赖页面、路由或具体业务视图。
6. **单一事实来源。** API 契约、领域类型、主题令牌、权限判断和共享状态不得在多个页面重复维护。
7. **显式优于隐式。** 让输入、输出、错误、加载、权限和副作用可读、可测试、可追踪；避免依赖全局可变变量和未声明的运行时约定。
8. **小步可验证。** 每次改动保持可构建、可测试、可回滚；先修复边界和契约，再做抽象和优化。
9. **渐进式一致。** 新代码遵循目标规范，旧代码按触碰范围逐步迁移；不因追求全局整齐而进行无关的大规模重写。
10. **不吞异常。** 能处理的错误要转换为稳定的领域错误或用户可理解状态，不能用空 catch、静默 fallback 或 console 输出掩盖失败。
11. **运行时边界可控。** 路由、Mock、样式和日志都必须有明确入口、生命周期和环境边界；不得把临时调试方案、页面内请求或全局样式扩散成隐式基础设施。
12. **默认安全和可恢复。** 不信任外部数据，不把前端校验当作权限边界；关键错误、配置缺失、资源失败和会话失效必须有明确的失败与恢复路径。
13. **性能可度量。** 只有基于真实基线、用户任务和构建数据的优化才进入规范；不以抽象或微优化掩盖包体积、请求瀑布、渲染阻塞和内存泄漏。
14. **嵌入边界显式。** 独立 URL、npm 包、Web Component、微前端和 iframe 是不同维度的访问、交付或运行时方案；按宿主、隔离、部署和维护边界选择，不为形式预先实现所有模式。支持嵌入的页面必须有版本化宿主契约和可运行的 Integration Portal。
15. **资源来源可控。** 构建、测试和生产运行不依赖未锁定的在线资源；字体、图标、图片、脚本和样式优先随包交付并可离线复现，业务后端 API 按项目接口契约处理。

## 决策优先级

用户当前明确要求
> 企业 Vue 默认基线与已批准的框架特例
> 项目现有运行约束和发布方式
> 项目已有公共模块与依赖
> 跨项目工程规范
> 本技能的默认建议
> 框架或脚手架生成的默认代码

若项目现状与规范冲突，优先保证已批准的存量约束和可交付性，同时记录兼容策略、特例边界和迁移计划，不静默破坏已有行为。

## 工作模式

### 基线审查

识别项目框架、语言比例、构建入口、模块边界、依赖层级、请求封装、状态管理、测试和发布脚本，输出事实、风险和优先级。

### 方案设计

为新功能确定模块归属、数据流、状态边界、错误契约、测试范围和迁移策略。先确定依赖方向，再确定文件位置。

### 实现重构

优先抽取稳定的类型、纯函数、请求服务、组合式函数和公共组件；保持公开接口兼容，避免把页面逻辑全部搬进一个万能工具模块。

### 质量回归

运行与改动相关的类型检查、构建、单元/组件测试和端到端测试；检查错误路径、刷新恢复、权限失效、重复提交、空数据和网络异常。

## 标准工作流

1. **确认范围**：明确项目、包、页面或功能，以及是否允许改变公开 API、依赖和目录。
2. **读取基线**：检查 package.json、锁文件、tsconfig、Vite/测试配置、入口、路由、状态、请求层和现有测试。
3. **画出依赖关系**：区分基础工具、基础设施、领域服务、状态、业务组件和页面；禁止低层模块依赖高层实现。
4. **定义契约**：为输入、输出、错误、加载、空值、权限和副作用确定明确类型或文档契约。
5. **实施最小改动**：优先复用现有模块；新增模块只承载一个稳定职责；跨页面复用前先确认抽象边界。
6. **补充验证**：先运行受影响测试和类型检查，再运行构建；共享契约或基础设施变化时扩大回归范围。
7. **记录迁移**：说明修改文件、兼容策略、验证命令、未覆盖风险和后续迁移项。

## 输出契约

每次执行结束时至少给出：

处理模式：审查 / 设计 / 实现 / 回归
目标范围：项目、包、路由、组件或模块
工程决策：模块边界、数据流、错误契约、路由/Mock/样式/日志、安全/性能/配置、表单/草稿/可观测性、页面嵌入/宿主契约/Integration Portal 边界和兼容策略
修改内容：文件、公共接口和迁移影响
验证结果：实际运行的类型检查、测试、构建或替代验证
遗留风险：未覆盖的边界和后续迁移建议

## 禁止事项

- 不为一次页面问题建立无法复用的万能组件、万能请求函数或万能 store。
- 不在页面中重复定义 API 地址、鉴权头、业务错误解析和权限判断。
- 不用 any、全局变量、隐式 window 状态或深层组件事件链掩盖类型和数据流问题；旧 JavaScript 项目允许渐进迁移，但新增边界应尽量显式。
- 不在未验证的情况下升级核心依赖、改变构建产物、删除测试或关闭严格检查。
- 不把 lint、类型错误、测试失败和运行时异常改成静默忽略。
- 不把 UI/UX 偏好写成工程硬规则，也不把工程折中伪装成视觉规范。
- 不直接引用可嵌入页面的源码深层路径、隐式全局状态或宿主私有实现；不把 Integration Portal 做成复制业务代码的第二套生产应用。
