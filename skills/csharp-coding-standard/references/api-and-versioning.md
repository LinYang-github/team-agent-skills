# API 与版本兼容

## 企业默认结论

- 先明确交付的是源码接口、同框架程序集接口，还是跨框架、跨语言、长期稳定的接口；三者不能共用模糊承诺。
- 仅供同仓库构建的模块优先提供类型安全的 C# API；跨框架、插件或长期稳定边界默认采用接口、DTO 和版本化数据结构。
- 公共 API 必须说明所有权、生命周期、可空性、线程安全、错误模型、单位、编码和兼容策略。
- 程序集默认 `internal` 可见性，仅显式 `public` 承诺的公共入口。
- 异常、`Task`、内部可变状态和运行时特有类型不得跨越不受控 ABI/序列化边界。

## 区分 API 与版本

- API 兼容指已有调用方源码无需修改或只需重新编译即可继续工作。
- 二进制兼容指已有程序集无需重新编译即可加载、绑定并保持行为（.NET 程序集默认强名称/版本绑定）。
- 修改名称、签名、默认行为、异常保证和语义可能破坏 API。
- 修改公共类型成员、接口方法、基类、序列化字段或泛型参数可能破坏二进制/行为兼容。
- 评审公共变更时必须分别给出 API 和二进制影响，不用“向后兼容”笼统代替。

## 公共 C# API

- 公共类型自包含、依赖最小，不暴露内部命名空间、私有类型和非必要第三方类型。
- 参数与返回类型表达所有权和缺省语义；不得要求调用方猜测释放方法或有效期。
- 公共枚举保留未知值处理策略；新增枚举值时，调用方不应因穷尽 `switch` 假设进入未定义行为。
- 接口的线程安全级别明确为线程兼容、实例可并发、只读可并发或完全线程安全。
- 不轻易在公共接口中暴露具体集合、`Task`、`IAsyncEnumerable` 和执行器；确需暴露时，将其视为长期契约。
- 公共内联方法（`[MethodImpl(MethodImplOptions.AggressiveInlining)]`）和泛型实现的语义变化应纳入版本和重编译策略。

## 程序集版本与签名

- 程序集版本（`AssemblyVersion`）、文件版本（`FileVersionVersion`）和包版本（`PackageVersion`）分别管理，遵循语义版本号。
- `AssemblyVersion` 通常锁定主版本，仅在破坏性变更时递增主版本号，避免绑定重定向负担。
- 强名称签名用于身份标识和防篡改，不提供安全信任；是否使用由组织策略决定。
- `InternalsVisibleTo` 用于测试和友元程序集，不作为公共 API 的替代。
- `dotnet`/NuGet 包发布时记录目标框架、依赖范围和最低运行时版本。

## 稳定接口边界

- 使用接口和 DTO 导出稳定入口，采用版本化数据结构。
- DTO 携带版本字段；新增字段只追加，读取前检查调用方提供的结构版本。
- 明明字符串编码（UTF-8/UTF-16）、是否包含终止符、缓冲区容量、实际写入长度和截断行为。
- 内存由分配方释放。跨运行时返回动态内存时，必须提供同模块释放函数，或由调用方提供缓冲区。
- 不在边界传递 `Task`、`Span<T>`、`ref struct`、匿名类型、`Expression` 和运行时特有布局类型。
- 导出函数捕获全部异常，返回稳定状态码；诊断信息通过显式错误查询或调用方缓冲区获取。
- 回调接口说明调用线程、是否可重入、调用时机、用户上下文生命周期和注销后的在途回调行为。

## 序列化与协议兼容

- 不通过 `BinaryFormatter` 或直接序列化对象布局建立持久化和网络协议（已废弃，不安全）。
- 协议明确字节序、字段宽度、编码、对齐、版本、缺省值、未知字段和最大长度。
- 优先 `System.Text.Json`、`protobuf` 等显式序列化器；自定义序列化集中处理，不散落业务代码。
- 解析所有外部数据时执行长度、范围、数量、递归深度和资源预算校验。
- 版本升级优先采用可忽略新增字段的扩展方式；字段删除、改义和复用编号属于破坏性变更。
- 可序列化类型默认不可变；可变状态不参与序列化，避免反序列化后状态不一致。

## 版本、弃用与插件握手

- 公共接口采用一致版本策略，区分兼容新增、行为修正和破坏性变更。
- 弃用使用 `[Obsolete]` 标记，必须提供替代方案、迁移说明和移除版本；不能只加标记后无限保留。
- 插件加载首先完成 ABI 版本、结构大小、能力集和必要运行时条件握手，不直接假定兼容。
- 不兼容时返回清晰错误并拒绝加载，不尝试带病运行。
- MEFE/`AssemblyLoadContext` 插件隔离边界明确；不依赖全局 `AppDomain` 状态。

## 验证要求

- 公共类型在最小调用方工程中独立编译。
- 程序集执行导出符号检查、版本差异检查、跨版本加载和创建/销毁冒烟测试。
- 发布包至少在每个受支持框架和运行时标识执行安装后消费测试，而不只验证源码树内构建。
- 兼容性测试保存上一受支持版本的程序集或协议样本作为基线。
- PublicApi.Shipped/Unshipped 文件配合 `PublicApiGenerator` 守护公共 API 表面。

## 审查清单

- 当前边界需要源码兼容、同框架二进制，还是跨框架稳定接口？
- 谁创建和释放对象，字符串、缓冲区和回调能存活多久？
- 是否泄露了 `Task`、异常、内部可变状态或第三方实现细节？
- 此变更是否影响公共签名、序列化字段、接口方法或运行时绑定？
- 是否有旧版本消费方和真实发布包的兼容性验证？
