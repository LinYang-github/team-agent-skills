# 项目结构与构建

## 目录职责

按实际项目组织目录，不要求空目录齐全。新项目默认采用：

    <Solution>.sln
    src/                    库与应用实现
    tests/                  单元与集成测试
    Directory.Build.props   仓库级 MSBuild 公共属性
    Directory.Packages.props   中央包版本管理（CPM）
    .editorconfig           格式化与分析器配置
    Directory.Packages.props   锁定的 NuGet 版本
    .gitignore             排除 bin/obj 与本机文件

- 公共类型与实现放在同一项目；需要拆分时，公共契约项目只放稳定接口。
- `Program`/入口点只负责启动编排、配置、依赖装配和退出码，不承载业务算法（顶级语句或显式 Main 均可）。
- 不建立含义宽泛的 Common、Utils、Helpers 目录；公共代码按明确职责归属项目。
- 构建产物（bin/obj）、下载缓存、生成文件和临时数据不写入源码目录。

## MSBuild 基线

- 使用 SDK 风格 .csproj；不使用旧式复杂 .csproj 与 packages.config。
- 每个库、可执行程序、插件和测试是独立项目；项目名称在解决方案内稳定且可搜索。
- 依赖通过 `<ProjectReference>`（项目内）和 `<PackageReference>`（NuGet）传播。
- `Public`、`Private`、`Publish` 属性按真实传播关系选择；不为“先编过”全部暴露公共 API。
- 禁止使用全局 `Directory.Build.props` 注入与业务无关的私有路径、凭据或机器专用 SDK。
- C# 语言版本通过 `<LangVersion>` 显式声明；不依赖 SDK 默认值。
- 中央包版本管理（CPM）使用 `Directory.Packages.props`，包版本统一管理，不在各项目重复声明版本。

## 项目类型

- 业务库优先标准类库项目；是否发布为 NuGet 由部署和版本策略决定。
- 可执行程序使用控制台应用或 ASP.NET Core 项目；Web 入口保持最小。
- 测试项目独立于业务项目，引用被测项目；不复制编译同一批源码。
- 共享契约库只放接口、DTO 和枚举，不包含实现，避免循环引用。
- 源生成器项目与消费项目分离，构建顺序明确，不依赖 IDE 手工设置。

## 解决方案与配置

- 解决方案文件 .sln 纳入版本控制，覆盖开发 Debug、发布 Release 和 CI 验证配置。
- 配置（Debug/Release）通过 MSBuild 属性和条件控制；不假设仅 Debug 可调试。
- 本机私有路径、凭据和机器专用 SDK 位置进入 `Directory.Build.props` 的条件分支或 `user secrets`，不提交仓库。
- 输出目录和发布布局由 MSBuild 统一管理，不依赖 IDE 默认路径或手工复制。

## 依赖管理

- NuGet 依赖名称、来源、版本、校验值/锁文件、许可证和目标框架可追踪；默认支持离线缓存或内部制品源。
- 优先使用组织既有且可锁定的包管理方案；CPM 锁定版本，不在业务项目散布浮动版本。
- `dotnet restore` 使用本地缓存或内部 NuGet 源；不在普通构建中从公网拉取浮动版本。
- 第三方源码记录来源、版本、补丁和许可证；修改第三方代码使用可重放补丁，不直接混入业务修改。
- 第三方警告与分析器规则通过单独配置隔离，不能通过全局关闭警告降低自有代码质量。
- 预览版包默认不引入生产；必须使用时锁定版本并记录理由和升级路径。

## 配置与生成文件

- 编译期配置只包含平台能力、版本和确实影响类型的选项；运行时可变配置不写成预处理宏或编译常量。
- 配置文件使用 `appsettings.json`、`IConfiguration` 或环境变量；敏感配置进入 `user secrets` 或受控密钥管理。
- 协议、IDL 和源生成声明完整输入、输出和依赖；生成器版本受控，增量构建不会漏执行。
- 生成文件不手工修改；是否提交仓库由离线构建和发布需求决定，并保持来源可验证。
- 源生成器输出不手工编辑；需要调整时修改生成器、模板或输入。

## 发布与打包

- 类库项目定义 `<IsPackable>` 与 NuGet 元数据；公共 API、运行时和调试符号分别成组。
- 发布产物包含版本、目标框架、运行时标识、依赖清单和许可证，不用文件名猜测兼容性。
- `dotnet publish` 后在干净目录运行消费者构建或冒烟测试，避免只在源码树中可链接。
- 可执行程序的运行时依赖布局、动态库搜索路径和配置位置由发布规则确定，不依赖用户修改全局环境。
- ReadyToRun、Trimming、AOT 等发布选项按目标平台选择，并验证与依赖的兼容性。

## 构建验收

至少验证：

1. 从干净目录完成 `dotnet restore`、`dotnet build` 和 `dotnet test`。
2. Debug 与 Release 均可配置，不依赖本机 IDE 状态。
3. 自有项目无编译警告，依赖可从本地缓存或内部来源恢复。
4. 发布后消费者可以找到公共 API 和运行时程序集。
5. 修改公共选项、生成输入或依赖版本时能触发正确重建。
