# 源码分析规则

## 架构识别

只分析用户选定的前端子目录，依据包括：

- `package.json` 中的依赖和 scripts
- 前端框架及构建配置
- 路由 API 和路由文件位置
- `.vue`、`.jsx`、`.tsx`、`.js`、`.ts` 源码文件
- 页面组件引用的本地组件、组合式函数、Store、服务和模板

如果工作区包含多个前端应用，必须由用户选择目标目录，不能合并不同应用的
路由树。

## Vue 路由处理

识别常见 Vue Router 写法：

- `createRouter({ routes })`
- `const routes = [...]`
- `routes: [...]`
- 静态组件 import
- `() => import('../views/Users.vue')` 等懒加载
- 嵌套 `children` 路由

嵌套路由按源码声明顺序展开。将路由路径和对应组件写入
`manifest.json`。例如 `/users/:id` 这样的动态路由，只有源码能够提供明确
字面量参数时才能生成具体 spec，否则记录为跳过。

## 功能点证据

每条生成的测试步骤都必须能够回溯到源码。可接受的证据包括：

- 带标签的按钮、链接、输入框、下拉框、表单、表格和列表
- `@click`、`@submit`、`@change`、键盘事件和 router-link 绑定
- `onMounted`、`mounted` 或 `created` 中的数据加载，以及明确的列表、表格或
  详情渲染状态
- 模板中的字面量文案和明确的条件渲染状态
- 具体路由路径和本地组件关系

依赖运行时数据、无法解析的函数、未知权限、外部配置或业务含义推断的内容，
不得生成。

## 业务场景契约

如果项目包含 `src/test-contracts/**/*.scenario.{json,js,ts}`，先解析其中的静态
业务场景。契约可以明确表达登录前置、页面导航、填写、点击、选择、接口等待和
结果断言；契约优先生成完整业务场景，未关联契约的路由继续使用页面功能点模式。

契约文件不能执行函数或读取运行时状态。账号密码只能引用环境变量或测试夹具名，
不能写入真实敏感信息。契约声明之外的接口结果、成功提示、权限和数据变化不得
推断。契约解析或渲染失败时，将文件、场景和错误写入 `manifest.json` 的
`unresolved`，不生成猜测步骤。完整字段和示例见
[business-contract.md](business-contract.md)。

页面即使没有点击操作，只要源码明确存在生命周期请求，并明确渲染列表或详情
状态，也可以作为页面初始化功能生成可见性断言。

## 输出约定

每个路由按顺序生成一个文件：

```text
001-login.spec.ts
002-users.spec.ts
```

文件使用 `test.describe()` 表示页面，每个已确认功能点使用一个 `test()`。
公共组件在实际渲染它的每个页面中分别展开。生成器不得覆盖已有时间戳目录。

`manifest.json` 应包含：

- 生成时间
- 用户选定的项目目录
- 识别出的前端架构
- 路由顺序
- 每个 spec 对应的组件源码
- 生成文件名和功能点数量
- 跳过路由及准确原因
- 扫描到的业务契约、场景数量及解析错误
- 未解析的定位、值、接口等待或断言

## 文档渲染映射

| 用户请求 | 渲染器 |
| --- | --- |
| 测试用例、测试设计、测试规格 | `test_case` |
| 用户手册、操作说明 | `user_manual` |
| 执行记录 | 只有提供真实执行报告时使用 `case_log` |
| 只说转换 Markdown | `test_case` |

本源码分析流程不执行测试。因此用户要求 `case_log` 时，必须说明当前没有真实
执行结果；只有用户提供 Playwright JSON 报告后，才能形成实际执行记录。
