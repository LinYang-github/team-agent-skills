# 流式 IO、文件与存储适配

- 业务层依赖小而稳定的存储接口，具体文件系统、对象存储或数据库适配器在基础设施层实现。
- 大文件使用 io.Reader、io.Writer 或流式 API；设置大小、超时和并发上限，避免一次性读入内存。
- 文件名、对象 key、归档条目和用户提供的路径必须规范化并校验根目录边界，防止路径穿越和 Zip Slip。
- 写入重要文件采用临时文件、完整写入、必要的同步和原子替换；失败时清理临时文件且不破坏旧版本。
- 所有 ReadCloser、文件、响应体、目录遍历、事务和对象存储流都覆盖正常与异常释放路径。
- 内容寻址或缓存数据应有完整性校验、不可变约束、过期/清理策略和磁盘预算；不要仅凭文件名信任内容。
- 上传/下载授权链接限制有效期、权限和对象范围；错误响应不暴露物理路径、凭据或内部存储拓扑。

## 验证

- 测试空文件、超大文件、短写、磁盘满、权限不足、非法路径、并发写入、断点失败和恢复。
