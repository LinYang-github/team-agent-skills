# 配置与启动校验

- 配置来源和覆盖优先级必须文档化，例如命令行、环境变量、配置文件和默认值；不要让不同入口使用不同优先级。
- 解析、规范化和校验分阶段进行：先反序列化，再转换路径/时长/大小，最后校验范围、互斥项和必填项。
- 配置结构使用明确类型和稳定字段；不要把未校验的 map[string]any 传入核心业务。
- 密钥、密码、Token 和证书通过受控注入，禁止提交示例生产密钥；敏感配置不写入普通日志和错误响应。
- 相对路径需明确基准目录；目录创建、权限和磁盘可用性在启动阶段验证。
- 静态启动配置与运行时可变配置分离；动态配置必须定义生效范围、并发更新、回滚、审计和默认行为。
- 缺失或非法配置应快速失败并指出安全的修复方向；只有明确安全的默认值才允许自动兜底。

## 验证

- 测试来源覆盖、环境变量覆盖、非法类型、范围边界、缺失密钥、路径规范化和配置热更新失败。
