# Go API 错误契约

- API 错误至少区分参数校验、认证、授权、资源不存在、冲突、限流、超时、依赖失败和内部错误。
- 对外返回稳定的 HTTP 状态和机器可读错误码；用户消息与内部诊断信息分离。
- 内部错误保留根因和上下文，可使用 fmt.Errorf 包装、errors.Is 和 errors.As；错误类型需要 Unwrap 时保持错误链。
- 不向客户端返回堆栈、SQL、文件路径、Token、完整第三方响应或原始错误字符串。
- 错误响应结构保持版本化和一致；成功响应、分页、空数据和部分成功也要有明确契约。
- 记录错误日志的位置应靠近能够补充完整上下文的边界，避免 handler、service、repository 多层重复记录同一错误。
- 请求取消、超时和客户端断开应能传递到下游，不能继续执行无意义的昂贵操作。

## 验证

- 测试错误码和 HTTP 状态映射、错误链判断、脱敏、超时、取消、重复请求和依赖异常。
