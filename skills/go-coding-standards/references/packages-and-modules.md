# Go 包结构与模块

- 以职责和稳定依赖组织包，入口、领域、基础设施和适配器边界清晰；避免所有代码集中在 main 或一个 common 包。
- 包名简短、稳定、无复数和无下划线；避免 package 名称与导出类型、标准库概念产生歧义。
- 接口由使用方定义，保持小而稳定；不要为了“未来可能复用”提前抽象大接口。
- 公共导出必须有明确用途、文档和兼容策略；内部实现优先放在 internal 或非导出符号中。
- go.mod/go.sum 与构建脚本纳入版本控制；依赖升级检查 API、许可证、漏洞、构建和运行时影响。
- 包之间只能通过稳定 API 或接口协作，不通过全局变量、未声明初始化顺序或深层内部路径耦合。
