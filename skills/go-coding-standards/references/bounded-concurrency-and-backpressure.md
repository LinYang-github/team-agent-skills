# 有界并发与背压

- goroutine 数量、任务队列、连接数、请求体、缓存和批量输入都应有上限；默认不创建无界资源。
- 队列满时明确采用阻塞、拒绝、超时、丢弃低优先级任务或降级策略；不能让内存增长成为隐式背压。
- 并发限制按资源和职责设置，避免用一个全局锁或一个万能协程池覆盖所有业务。
- 每个任务应携带 context、超时、取消和错误归属；任务执行结果不能只靠日志判断。
- 关闭时明确停止接收、排空队列、取消等待中任务、等待运行中任务的顺序；Stop 应幂等且不会与 Submit 产生 panic。
- 使用 WaitGroup、errgroup、信号 channel 或等价机制等待任务；不让后台 worker 在测试和进程退出后继续运行。
- 监控排队数、活跃数、完成数、失败数、拒绝数、取消数和等待/执行耗时。

## 验证

- 测试队列满、提交超时、关闭并发提交、任务 panic、任务取消、长任务退出和资源泄漏。
- 通过基准或压力测试验证上限、吞吐、延迟和内存曲线，而不是只验证少量成功请求。
