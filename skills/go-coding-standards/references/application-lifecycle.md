# Go 应用生命周期

## 组成与启动

- 在入口或 Composition Root 读取配置、初始化日志和基础设施，再按依赖顺序组装服务；业务包不负责发现全局依赖。
- 初始化函数返回错误，不在库包中直接调用 os.Exit；入口负责决定记录错误、重试或终止进程。
- 启动顺序和关闭顺序相反：先停止接收新请求，再停止调度/后台任务，等待进行中操作，最后关闭连接、存储和文件资源。
- 初始化阶段应验证必填配置、目录权限、依赖可用性和版本兼容性，避免服务启动后才发现不可恢复配置错误。

## 运行与退出

- 使用根 context.Context 管理应用级取消；每个后台组件注册启动、停止和错误报告边界。
- 信号处理只负责触发取消和协调退出，不把业务清理散落在信号回调中。
- Shutdown 设置明确的截止时间；到期后记录未完成组件和任务，进入有界的强制关闭路径。
- 关闭方法应幂等，重复调用不 panic；启动失败或部分初始化失败时释放已创建资源。
- HTTP Server、Worker、Ticker、Scheduler、数据库、连接池和临时资源都纳入生命周期清单，不只关闭 HTTP 监听器。

## 验证

- 测试正常启动、配置失败、依赖初始化失败、SIGINT/SIGTERM、重复 Shutdown、超时退出和后台任务取消。
- 记录启动耗时、关闭耗时、未完成任务数量和最终退出原因；不把 os.Exit 作为常规业务错误处理。
