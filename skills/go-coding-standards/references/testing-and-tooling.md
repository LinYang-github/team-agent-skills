# Go 测试与工具链

- 提交前至少运行 gofmt、go vet 和受影响包的 go test；公共包或基础设施变化时扩大到 go test ./...。
- 并发、共享状态、取消和资源释放变化运行 go test -race；性能敏感代码以基准测试和真实基线为依据。
- 测试覆盖错误包装、context 取消、超时、重复关闭、资源失败和边界退出码等场景。
- 使用临时目录、可控时钟和测试替身隔离文件、网络、数据库和环境变量；测试结束清理资源。
- 构建发布前验证 CGO、目标 OS/架构、嵌入资源、配置和证书边界；记录实际命令，不笼统声称“已验证”。
- 第三方静态检查工具按项目现状选用，不为追求工具数量而重复或降低官方工具链的作用。
