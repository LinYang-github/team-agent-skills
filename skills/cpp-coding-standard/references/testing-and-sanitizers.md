# 测试与 Sanitizer

## 企业默认结论

- 新建 C++ 项目默认使用 GoogleTest 编写单元与组件测试，使用 CTest 统一发现、执行、超时、标签和报告；项目已有成熟框架时可保持一致，但必须接入 CTest 或等价统一入口。
- 每个可独立验证的库或组件具有对应测试目标，默认构建开关遵循 CMake 的 BUILD_TESTING。
- Debug 流水线启用 AddressSanitizer 与 UndefinedBehaviorSanitizer；并发代码另设 ThreadSanitizer 流水线，不把它与 AddressSanitizer 混用。
- 项目自有代码的编译警告、格式检查和静态分析属于质量门禁；第三方和生成代码隔离处理。
- 覆盖率用于发现缺口，不以单一百分比替代边界、失败路径和风险验证。

## 测试分层

| 层级 | 关注点 | 默认要求 |
| --- | --- | --- |
| 单元测试 | 纯逻辑、状态转换、边界和错误路径 | 快速、隔离、确定性，可高频执行 |
| 组件测试 | 库接口、线程协作、文件与适配器 | 使用真实组件，外部依赖受控 |
| 集成测试 | 动态库、数据库、进程、协议和系统接口 | 固定环境、显式超时、可重复清理 |
| 契约与兼容测试 | API、ABI、序列化和历史样本 | 覆盖旧版本消费方和异常输入 |
| 系统与安装测试 | 发布包、配置、启动、核心流程 | 从安装产物执行，不依赖源码树 |

- 测试重点覆盖边界值、空输入、超大输入、损坏数据、超时、取消、失败注入和资源耗尽。
- 安全关键解析器、协议、状态机和数值算法增加属性测试、模糊测试或模型对照。
- 不为了易测而暴露内部实现；通过公共契约、受控依赖注入和窄适配层建立测试点。

## 测试结构与命名

- 测试文件与被测组件对应，测试套件命名表达类型或场景，测试名称表达前提和可观察结果。
- 测试遵循准备、执行、验证的清晰结构，一项测试聚焦一个行为，但允许验证该行为的完整结果。
- 优先验证对外行为和不变量，避免对私有调用次数、内部容器顺序等非契约细节过度耦合。
- 断言信息包含必要上下文；浮点、时间和并发结果使用领域允许的容差与不变量，不进行脆弱的精确比较。
- 死亡测试只用于明确的不可恢复契约，不用来替代普通错误处理测试。

## 确定性与隔离

- 测试不访问在线资源、公共服务、CDN 或开发者个人环境；依赖数据、证书和工具在仓库、测试包或受控离线环境提供。
- 文件测试使用框架或标准库生成的独立临时目录，结束时清理，不写固定全局路径和用户主目录。
- 不依赖测试执行顺序、共享可变全局状态、真实墙上时间和随机调度。
- 随机测试记录种子；失败时输出可复现种子和最小化输入。
- 等待异步事件使用屏障、条件变量、锁存器、future 或可控时钟，不用任意 sleep 作为同步手段。
- 每项可能阻塞的测试设置合理超时；超时后保留线程、栈、日志或队列状态等诊断。

## Sanitizer

- AddressSanitizer 检查越界、释放后使用和部分生命周期问题；UndefinedBehaviorSanitizer 检查未定义行为，两者默认组合运行。
- ThreadSanitizer 检查数据竞争，使用独立构建与任务；它不能证明没有死锁、活锁和高层并发协议错误。
- LeakSanitizer 在工具链支持时纳入 AddressSanitizer 配置；有意进程级分配需最小范围抑制并说明原因。
- MemorySanitizer 仅在依赖均可用同一工具链插桩的环境启用，不作为所有平台强制默认。
- Sanitizer 使用 Debug 或带调试信息的优化构建，保留符号化能力，并把报告视为失败。
- 禁止大范围关闭检查。第三方已知问题使用精确到库、符号或调用点的抑制，登记负责人和清理条件。

## 编译器警告与静态分析

- 项目自有目标启用高等级警告并视为错误；第三方目标通过 SYSTEM 头或独立目标隔离，不全局降低警告等级。
- clang-tidy 配置纳入版本控制，至少覆盖错误易发规则、现代化、安全和性能类别，再根据误报逐条调整。
- clang-format 结果在 CI 校验，不依赖开发者手工记忆格式规范。
- 静态分析发现的问题要修复、精确抑制或形成有期限的技术债；禁止批量用 NOLINT 掩盖。
- 编译数据库由 CMake 生成并供分析工具使用，确保检查参数与实际构建一致。

## 覆盖率与模糊测试

- 覆盖率按模块和变更风险观察，重点审查新增分支、错误路径和关键算法，而非追求全仓统一数字。
- 生成代码、第三方代码和不可执行声明从覆盖率统计中排除，但不得借此排除项目自有难测逻辑。
- 解析器、反序列化、文件格式、协议入口和复杂状态机优先建立模糊测试。
- 模糊测试设置单输入大小、递归深度、运行时间和内存限制；崩溃样本去敏后纳入回归语料库。

## CI 质量门禁

- 快速门禁：配置、编译、格式、静态分析、单元测试。
- 深度门禁：ASan+UBSan、TSan、覆盖率、模糊测试种子、组件与集成测试。
- 发布门禁：Release 构建、安装、消费方构建、包内容、符号、架构和核心流程冒烟。
- 支持多编译器或多平台时，至少保留一个主平台快速门禁和受支持矩阵的定期或合并前验证。
- 不允许仅在本地 IDE 中才能运行的测试；所有测试有可脚本化、可重复的命令入口。

## 审查清单

- 新行为的成功、失败、边界、取消和资源路径是否都有验证？
- 测试能否离线、并行、乱序和重复运行？
- Sanitizer、警告和静态分析是否覆盖项目自有代码？
- 是否从真实安装产物验证了库、插件或可执行程序？
- 覆盖率缺口是否集中在高风险逻辑，是否需要属性或模糊测试？
