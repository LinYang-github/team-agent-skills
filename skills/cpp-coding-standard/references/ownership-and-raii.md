# 所有权与 RAII

## 默认所有权模型

- 首选值语义：对象由作用域、容器或成员直接拥有，编译器生成复制/移动/析构。
- 需要动态独占所有权时使用 std::unique_ptr，并通过 std::make_unique 创建。
- 只有多个独立所有者确实需要共同延长同一对象生命周期时使用 std::shared_ptr。
- std::weak_ptr 只用于观察共享对象和打破环，不把 lock 失败当作不可能。
- 裸指针、引用、span 和 string_view 都是非拥有视图；接口必须保证来源和有效期可理解。
- 不在业务代码中直接使用 owning raw pointer、new/delete、malloc/free 或平台配对释放函数。

## RAII 覆盖范围

以下资源必须由不可复制或语义正确的 RAII 类型管理：

- 内存、文件、目录句柄、socket、数据库/设备连接。
- 互斥锁、读写锁、信号量和临界区。
- 线程、任务执行器、定时器和回调注册。
- 动态库、图形/驱动资源、映射内存和平台句柄。
- 临时文件、事务、状态切换以及必须成对恢复的设置。

RAII 包装器在构造或工厂中建立有效状态，在析构中无异常释放；释放操作需要报告失败时提供显式 close/commit，并让析构执行安全兜底。

## 智能指针规则

- std::unique_ptr 是动态所有权默认；按值传入表示转移，返回值表示交付所有权。
- 非拥有访问传 T&/const T&；可空观察使用 T*，并在接口命名或文档中说明可空。
- 不为“避免拷贝”把普通值改成 shared_ptr；先确认对象大小、生命周期和复制成本。
- shared_ptr 不跨越不兼容运行库或稳定 C ABI；共享控制块的分配器和析构边界必须一致。
- 禁止从同一裸指针构造多个独立 shared_ptr；需要 enable_shared_from_this 时对象必须始终由 shared_ptr 创建。
- 自定义 deleter 必须与资源来源配对，并验证目标平台调用约定。

## 复制与移动

- 优先 Rule of Zero；资源成员本身负责生命周期，拥有类不手写析构、复制和移动。
- 手写任一析构/复制/移动操作时审查完整 Rule of Five，并明确对象移出后的有效状态。
- 独占资源类型禁用复制、允许 noexcept 移动；不能安全移动时明确禁用。
- 不无条件对返回局部变量使用 std::move，以免阻止返回值优化。
- move 后对象只能依赖标准或类型文档保证的有效状态；不要读取未定义的业务字段。

## 工厂与构造失败

- 构造完成后对象应满足类不变量；不能产生“构造成功但必须再 init”的半成品。
- 可能失败且无法用异常表达的创建过程使用命名工厂并返回项目统一 Result 类型。
- 工厂返回值或 unique_ptr；不通过输出裸指针转移所有权。
- 多步资源获取依赖局部 RAII 对象，任一步失败都自动回滚已获取资源。

## 回调与注册

- 注册接口返回 RAII subscription/token，析构时解除注册；不要求调用者记忆配对 unregister。
- 异步回调不得无条件捕获 this；根据执行器与对象生命周期选择值捕获、弱引用或显式取消。
- 对象析构前停止新回调、取消任务并等待正在执行的回调退出，避免回调访问已销毁成员。
- shared_ptr 环必须在设计中识别；发布者、订阅者、定时器和 lambda 捕获是重点审查位置。

## 审查问题

1. 每个资源由谁创建、拥有、释放，异常路径是否一致？
2. 接口中的裸指针和引用是否明确非拥有、可空和有效期？
3. shared_ptr 是否确实表达共享所有权，而不是修补设计？
4. 移动、取消、关闭和析构能否并发发生，结果是否定义？
5. 资源释放是否发生在创建它的模块、运行库或平台边界内？

## 历史存量兼容

- 历史存量代码中功能较重的类可能仍存在需要 init、clean 的两阶段写法；迁移完成前应把有效状态、失败传播和清理责任显式收敛到类型或 RAII 包装器，并记录移除条件。
- 新类和新增资源不得继续引入两阶段初始化；应通过构造函数或命名工厂建立完整可用状态，并由 RAII 类型负责释放。
