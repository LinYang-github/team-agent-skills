# 错误处理与异常

## 企业默认结论

- 普通应用和服务默认启用 C++ 异常；禁用异常必须由目标平台、实时性、二进制约束或既有 ABI 证明，并形成项目级决策记录。
- 预期内、调用者经常需要分支处理的失败，使用显式结果类型或稳定错误码；无法在当前层恢复的构造失败、资源失败和不变量破坏，可使用异常。
- 一个接口只采用一种主要失败通道，不同时混用返回码、空值、全局错误和异常。
- 异常绝不跨越 C ABI、插件 ABI、线程入口、事件循环、回调框架或进程边界；边界处捕获、记录并转换。
- 清理完全依赖 RAII，不使用成对手工清理路径维持异常安全。

## 错误模型选择

在模块或层级设计时先统一以下选择：

| 场景 | 默认方式 | 要求 |
| --- | --- | --- |
| 参数校验、未找到、冲突等预期失败 | 结果类型或错误码 | 调用者必须显式处理，错误类别稳定 |
| 构造、分配、文件打开等无法局部恢复的失败 | 异常 | 提供上下文，边界统一转换 |
| 可选数据不存在 | optional | 不携带失败原因时使用 |
| 程序不变量被破坏 | 断言、契约失败或终止 | 不伪装成可恢复业务错误 |
| C、插件、RPC 或进程边界 | 稳定状态码和数据契约 | 不传播语言运行时对象 |

- 不使用 -1、0、空字符串或空指针同时表达多个错误含义。
- 结果类型必须保证“值”和“错误”互斥，并支持调用者无法忽略的检查方式。
- 错误码应稳定、可枚举、适合程序判断；面向人的消息用于诊断，不作为分支条件。
- 在保留原始错误类别的同时追加操作、资源标识和关键参数上下文，不重复记录同一错误链。

## 异常使用

- 异常表达异常失败，不用于正常循环、普通条件判断和协议分支。
- 抛出具体异常类型，按 const 引用捕获；重新抛出当前异常使用 throw;，避免切片。
- 捕获范围保持最小，只捕获能够恢复、补充上下文或转换的异常。
- 禁止空 catch。确需忽略某类失败时，必须限定异常类型、说明原因，并保留必要的诊断或指标。
- 析构函数不得抛出异常；清理失败通过显式 close、提交操作、日志或状态查询报告。
- 不直接抛出裸字符串、整数或不具备稳定语义的内部类型。
- 标准 C++ 异常能力不依赖 Windows 或 Linux；不得把特定旧工具链限制误写为操作系统不支持异常。

## noexcept

- 仅当函数在所有支持配置下确实不传播异常时声明 noexcept。
- 析构、释放、交换和移动操作应尽可能满足 noexcept，但不能通过吞掉不可忽略错误来伪造保证。
- 回调、虚函数或模板接口添加 noexcept 前，应确认所有可替换实现都能满足；违反 noexcept 会直接终止进程。
- 条件性保证使用 noexcept 表达式推导，不复制依赖实现的假设。
- 修改已发布函数的 noexcept 属于接口兼容性变化，需纳入 API/ABI 审查。

## 异常安全保证

- 资源操作至少提供基本保证：失败后对象仍有效、没有泄漏、不变量不破坏。
- 事务式更新、容器替换和配置切换优先提供强保证：失败后对外可见状态不变。
- 析构、释放、回滚和交换等基础操作力求提供不抛异常保证。
- 多步修改优先采用先构造后提交、临时对象加 swap 或明确回滚对象，不在半完成状态逐项暴露结果。
- 文档明确关键接口提供的保证级别，测试失败注入路径而非只测成功路径。

## 边界处理

- 每个线程入口、任务执行器入口、框架回调和事件循环顶层必须有异常屏障，防止异常逃逸导致未定义的框架行为或进程终止。
- C ABI 和插件导出函数捕获所有异常，转换为稳定状态码，并将诊断写入调用方提供的缓冲区或受控错误对象。
- RPC、消息和进程边界只传递稳定错误码、可安全展示的信息和关联标识，不传递 C++ 类型名、栈对象或敏感路径。
- 第三方库错误在适配层转换为项目领域错误，不让调用方依赖第三方异常层次和数值错误码。
- 顶层兜底 catch (...) 仅用于隔离边界；它必须执行安全收敛、留下诊断并返回明确失败，不得让程序假装成功。

## 契约与断言

- 断言用于开发期发现程序员错误和内部不变量破坏，不用于处理不可信输入、网络数据和用户操作。
- 对外输入始终执行运行时校验，并返回定义良好的失败结果。
- 断言表达式不得包含改变程序状态的副作用，Release 构建移除断言后行为必须保持一致。
- 不可恢复错误的终止策略、崩溃信息和敏感数据处理遵循通用规范与部署环境要求。

## 审查清单

- 调用者是否能从签名识别全部失败方式？
- 当前失败属于预期分支、异常失败还是不变量破坏？
- 异常是否可能越过线程、C ABI、插件或进程边界？
- 失败后资源、对象状态和外部副作用是否一致？
- 错误上下文是否足够定位，同时避免重复记录和敏感信息泄露？
