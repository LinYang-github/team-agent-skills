# 语言版本与代码风格

## 语言基线

- 新项目默认 C++20，并通过 target_compile_features 声明，不依赖编译器默认值。
- 遗留项目使用更低标准时记录受限特性、目标工具链和迁移条件；不能因个别旧模块把所有 target 降级。
- C++23 特性只有在编译器、标准库、静态分析、调试器和目标平台矩阵全部支持后启用。
- 禁止依赖非标准扩展而不加隔离；必须使用时限制在适配层，并对其他编译器提供实现或明确失败。

## 格式化

- 仓库提交统一的 .clang-format，格式化结果由工具决定，不在代码审查中反复争论个人排版。
- 默认 4 空格缩进，不使用 Tab 表达代码层级；行宽默认 120，生成代码和不可分割标识符除外。
- 大括号、指针/引用绑定、初始化列表和 include 排序统一由配置控制。
- 格式化只作用于本次修改范围；大规模机械格式化使用独立提交，避免掩盖语义变更。

## C++ 命名默认

| 元素 | 默认形式 |
| --- | --- |
| namespace | lower_snake_case |
| 类型、类、枚举、concept | PascalCase |
| 函数、方法、局部变量、参数 | lower_snake_case |
| 私有数据成员 | lower_snake_case_ |
| 编译期常量 | kPascalCase |
| 宏 | UPPER_SNAKE_CASE，仅限预处理用途 |
| 文件名 | lower_snake_case.h/.cpp |

- 同一代码库已有一致且成熟的命名约定时优先渐进保持，不在功能修改中全量重命名。
- 不使用匈牙利命名法，不把类型编码进变量名；单位或语义差异应进入名称或强类型。
- 布尔值使用可判断真假的名称，如 is_ready、has_value、can_retry；避免否定叠加。
- 缩写按普通单词处理，保持跨项目一致；领域缩写只有在团队词汇表中明确时使用。

## 初始化与类型

- 对象在定义处完成初始化；优先花括号初始化，并警惕 initializer_list 重载改变语义。
- 使用 auto 消除重复类型或承接迭代器、lambda、模板结果；当类型影响单位、符号、所有权或精度时显式书写。
- 协议、文件和 ABI 使用固定宽度整数；容器大小和索引使用容器 size_type 或经检查转换后的领域类型。
- 禁止未检查的窄化、符号混用和浮点转整数；集中使用可诊断的检查转换。
- 使用 enum class，不使用无作用域枚举污染命名空间；序列化值与枚举显式映射。
- 使用 nullptr，不使用 NULL 或整数 0 表示空指针。
- 使用 constexpr、consteval 和 constinit 表达真正的编译期与初始化约束，不为“现代化”机械添加。

## 函数与控制流

- 函数保持单一职责；参数过多或多个布尔开关时使用命名选项类型，不用位置参数猜测语义。
- 优先早返回降低嵌套；复杂条件提取为命名函数。
- 默认按值返回，依赖返回值优化和移动语义；不返回指向局部对象的引用或视图。
- 有返回值的函数必须保证所有控制流分支都返回有效值，不允许存在没有返回值的分支；将返回路径相关告警（如 GCC/Clang 的 -Wreturn-type、MSVC 的 C4715）视为错误。
- 输入参数按值、const 引用、span 或 string_view 选择，所有权和生命周期必须清楚。
- 输出优先使用返回值；多个结果使用命名结构体，不使用无语义 tuple 或大量输出指针。
- 单参数构造函数和转换运算符默认 explicit。
- 不使用宏定义函数、常量或控制流；优先 constexpr、inline 函数、模板或 concept。

## 注释与文档

- 通用注释原则遵循 common-coding-standards。
- 公共接口说明所有权、可空性、异常/错误、线程安全、单位和生命周期，不重复函数名。
- 非直观的模板约束、内存序、ABI 布局和平台差异必须说明“为什么”；临时兼容代码记录移除条件。
- 不保留注释掉的代码、IDE 自动生成说明或已经失真的实现叙述。

## 历史存量兼容

以下差异仅对历史存量代码生效；新代码仍按本文件默认规则执行，迁移时应优先保持模块内一致，避免机械混排：

- 历史存量代码允许使用 Tab 表达代码层级；新增或重构范围逐步改为 4 空格，不在同一文件中无边界混用 Tab 与空格。
- 历史存量代码的行宽不是强制红线；不因超长进行无意义的全文件重排，但在本次修改范围内仍应避免明显过长和可读性下降。
- 历史存量代码的函数、方法、参数使用 PascalCase，局部变量使用 pascalCase；保持存量模块一致性，新代码在已迁移或新模块中遵循 lower_snake_case。
- 历史存量代码的文件名使用 PascalCase；不因命名风格单独重命名文件，避免破坏 include 关系和构建链。
