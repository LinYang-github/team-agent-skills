# 性能、实时性与确定性

本文件只在任务具有明确性能、时延、内存或确定性约束时使用。通用“先测量再优化”原则遵循 common-coding-standards。

## 性能契约

- 优化前记录工作负载、数据规模、硬件、运行模式、指标基线和目标；不能用开发环境结果推断生产性能。
- 区分吞吐、平均时延、尾时延、启动时间、峰值内存、GC 暂停、分配次数和二进制体积，不以单一“更快”替代目标。
- 基准测试固定输入、预热、采样和统计方式，使用 `pyperf`/`pytest-benchmark` 避免测量陷阱；结果进入可重复的性能回归流程。
- 性能变化同时检查正确性、资源上限和最坏路径，不用平均值掩盖长尾。
- CPython 的 GIL 影响多线程 CPU 并行；吞吐瓶颈评估 `multiprocessing` 或 C 扩展释放 GIL。

## 数据与分配

- 优先改善算法复杂度、数据布局和不必要拷贝，再考虑微观语法优化。
- 热路径避免无界分配、隐式字符串构造、生成器多次迭代和重复列表扩容；已知规模时预分配。
- 默认值语义；只有测量证明拷贝成本显著且生命周期清楚时引入视图、共享对象或对象池。
- 列表/字典预分配（`[None] * n`/`{k: v for ...}`）用于已知规模；但不把猜测容量永久固化。
- `__slots__` 用于减少内存占用和属性访问；不可变对象优先 `frozen dataclass`/`NamedTuple`。
- `array.array`/`bytes`/`memoryview` 用于紧凑数值和二进制数据，替代对象列表。
- `functools.lru_cache`/`cache` 用于纯函数缓存，但需评估大小上限、线程安全和内存增长。
- 全局可变缓存使用 `WeakValueDictionary` 或受控上限，避免无界增长。

## 字符串与序列

- 字符串拼接使用 `"".join(parts)`，避免 `+` 在循环中重复分配。
- `str.format`/f-string 用于格式化；f-string 在 CPython 中最快。
- `bytes`/`bytearray` 用于二进制 I/O；`memoryview` 用于零拷贝切片。
- 列表推导优先于 `for` 循环 append；但避免过度嵌套推导降低可读性。
- 生成器（`yield`）用于流式处理大数据，避免一次性物化全部数据。
- `collections.deque` 用于队列操作，`list` 头部插入/删除为 O(n)。

## GC 与延迟

- CPython 使用引用计数 + 循环检测 GC；引用计数归零立即回收，循环引用由 GC 定期回收。
- GC 暂停可能影响低延迟场景；`gc.disable()` 仅在已证明的瓶颈中使用，并承担循环引用泄漏风险。
- 长生命周期对象用于缓存；短生命周期对象分配在 Gen0 快速回收，避免循环引用提升到 Gen2。
- `__del__` 可能延迟回收和影响 GC；优先上下文管理器显式释放。
- 循环引用对象优先 `weakref` 断环或显式 `close`/`__exit__`。
- 大对象（>512 字节，CPython 阈值）可能影响 GC 效率；批量处理评估分块。
- `gc.set_threshold` 调整 GC 频率仅用于已证明的瓶颈，并记录理由和风险。

## 实时与确定性

- “实时”必须明确是软实时还是硬实时，并给出周期、截止时间、抖动、丢帧/降级和超限行为。
- 实时路径禁止未界定的动态分配、阻塞 I/O、无界锁等待、延迟导入和不可控日志格式化。
- 资源在初始化阶段预分配并验证容量；容量耗尽时采用已定义的失败或降级路径，不静默扩容破坏时限。
- 使用 `time.monotonic()`/`time.perf_counter()` 测量间隔；`time.time()` 受系统时钟影响，不用于间隔测量。
- 调度优先级、CPU 亲和性和平台实时 API 属于平台适配层，不能散落到算法代码。
- 硬实时场景评估 C 扩展释放 GIL 或 `multiprocessing` 隔离；不依赖解释器线程保证。
- `PyPy` 的 JIT 可能改善吞吐但增加启动时间和预热抖动；硬实时路径优先 CPython 或 C 扩展。

## 数值与可复现

- 对结果可复现有要求时，明确浮点模型、舍入、并行归约顺序、随机种子、编译优化和硬件差异。
- 不假设不同 CPython 版本和硬件路径产生逐位相同浮点结果；需要逐位一致时必须设计专门算法和测试。
- 随机算法显式传入 `random.Random`/`numpy.random.Generator`，不在核心计算中隐式使用全局随机状态。
- `random.seed()` 显式设置种子；测试中固定种子确保可复现。
- `hash()` 随机化（`PYTHONHASHSEED`）影响字典顺序；需要稳定哈希时使用 `hashlib`。
- `decimal` 模块用于精确十进制运算；不用于普通数值路径，避免性能开销。
- `numpy` 用于批量数值运算；优先向量化操作替代 Python 循环。

## C 扩展与性能边界

- C 扩展/`cython`/`numba` 用于已证明的性能瓶颈，并定义接口、内存安全和 GIL 释放策略。
- `numpy` 向量化优先于 Python 循环；`numpy` 的广播和 ufunc 利用 C 层优化。
- `multiprocessing` 用于 CPU 密集并行；评估序列化开销和进程启动成本。
- `concurrent.futures.ProcessPoolExecutor`/`ThreadPoolExecutor` 用于任务池；GIL 限制线程 CPU 并行。
- `asyncio` 用于 I/O 密集并发；不用于 CPU 密集并行。
- C 扩展释放 GIL（`Py_BEGIN_ALLOW_THREADS`）用于 CPU 密集计算，但需保证不访问 Python 对象。

## 性能代码审查

- 复杂优化代码必须说明基线、收益、适用规模和退化条件。
- 关键基准进入 CI 或定期性能流水线（`pytest-benchmark` + 报告），并设置能容忍环境噪声的回归阈值。
- 删除已经失去收益的缓存、池化、手写 C 扩展和平台分支，不让历史优化永久增加复杂度。
- 对象池、`lru_cache` 和缓存必须配置上限、回收和线程安全策略，避免成为内存泄漏源。
- `tracemalloc` 用于追踪分配热点；`cProfile`/`py-spy` 用于定位 CPU 瓶颈。
