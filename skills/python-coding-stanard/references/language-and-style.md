# 语言版本与代码风格

## 语言基线

- 新项目默认 Python 3.11，通过 `pyproject.toml` 的 `requires-python` 显式声明，不依赖解释器默认值。
- 遗留项目使用更低版本时记录受限特性、目标解释器和迁移条件；不能因个别旧模块把所有目标降级。
- Python 3.12+ 特性只有在 CPython、PyPy、mypy、ruff 和目标平台矩阵全部支持后启用。
- 禁止依赖实验性或 `__future__` 特性而不加隔离；必须使用时限制在适配层，并对其他目标版本提供实现或明确失败。

## 格式化

- 仓库提交统一的 ruff format 配置（或 black 兼容），格式化结果由工具决定，不在代码审查中反复争论个人排版。
- 默认 4 空格缩进，不使用 Tab 表达代码层级；行宽默认 88（ruff/black 默认），公司规范要求每行最大 79，换行可以使用反斜杠，最好使用圆括号，换行点要在操作符后边。
- 引号、导入排序、尾随逗号和空行统一由配置控制。
- 格式化只作用于本次修改范围；大规模机械格式化使用独立提交，避免掩盖语义变更。

## Python 命名默认

| 元素 | 默认形式 | 示例 |
| --- | --- | --- |
| 模块 | lower_snake_case | sample_module |
| 包 | lower case（无下划线） | mypackage |
| 类（公开） | PascalCase | HTTPServerError |
| 类（内部） | _PascalCase | _Internal |
| 异常类 | PascalCase + Error/Exception 后缀 | ValueError |
| 函数、方法 | lower_snake_case | parse_config |
| 变量 | lower_snake_case | buffer_size |
| 常量 | UPPER_SNAKE_CASE | MAX_RETRY_COUNT |
| 私有属性 | _lower_snake_case | _buffer |
| 名称改写属性 | __lower_snake_case | __internal_state |
| 类型变量 | PascalCase（T/TypeVar） | TElement |

- 同一代码库已有一致且成熟的命名约定时优先渐进保持，不在功能修改中全量重命名。
- 不使用匈牙利命名法，不把类型编码进变量名；单位或语义差异应进入名称或强类型。
- 布尔值使用可判断真假的名称，如 `is_ready`、`has_value`、`can_retry`；避免否定叠加。
- 缩写按普通单词处理，保持跨项目一致；领域缩写只有在团队词汇表中明确时使用。
- 尽量单独使用小写字母 `l`、大写字母 `O` 等容易混淆的字母。
- 类的属性若与关键字名字冲突，后缀加下划线，尽量不要使用缩写等其他方式。
- 为避免与子类属性命名冲突，在类的一些属性前加两条下划线（名称改写），如 `Foo.__a` 访问为 `Foo._Foo__a`。

## 代码编排

- 空行规则：
  - 顶级函数和类定义之间留两行空行。
  - 类内部的函数之间留一行空行。
  - 函数内逻辑无关段落之间空一行。
- 函数长度保持单一职责；过长函数拆分为命名辅助函数，不在单函数内堆叠多职责。
- 空格规则：
  - 各种右括号前不要加空格。
  - 逗号、冒号、分号前不要加空格。
  - 函数的左括号前不要加空格，如 `Func(1)`。
  - 序列的左括号前不要加空格，如 `list[2]`。
  - 操作符左右各加一个空格，不要为了对齐增加空格。
  - 函数默认参数使用的赋值符左右省略空格。
  - 不要将多句语句写在同一行，尽管使用 `;` 允许。
  - `if`/`for`/`while` 语句中，即使执行语句只有一句，也必须另起一行。

## 注释与文档

- 通用注释原则遵循 common-coding-standards。
- 模块、函数、类和方法编写文档字符串（docstring），以 `"""` 开始，写在 `def` 行后面：

```python
def add_report_paragraph(report_paragraph):
    """
    增加报告段落
    :param report_paragraph: 报告段落信息
    :return:（执行状态，提示信息，数据）
    """
```

- 行注释使用 `#` 号开始，`#` 号和注释文本之间插入一个空格；单行注释不要放在代码末尾。
- 块注释在一段代码前增加，`#` 后加一空格，段落之间以只有 `#` 的行间隔。
- 公共接口说明所有权、可空性、异常/错误、线程安全、单位和生命周期，不重复函数名。
- 非直观的协议约束、内存序、序列化布局和平台差异必须说明“为什么”；临时兼容代码记录移除条件。
- 不保留注释掉的代码、IDE 自动生成说明或已经失真的实现叙述。

## 文件头与模块编排

- 模块内容顺序：模块说明和 docstring → import → globals & constants → 其他定义。
- import 部分按标准库、第三方、本仓库顺序依次排放，之间空一行。
- 不要在一句 import 中导入多个库，比如 `import os, sys` 不推荐，应拆分为独立语句。
- 如果采用 `from XX import XX` 引用库，可以省略 `module.`，但可能出现命名冲突，这时就要采用 `import XX`。
- 不使用 `import *`，避免命名空间污染和静态分析失效；确需大量符号时显式导入或使用 `__all__`。

## 初始化与类型

- 对象在声明处完成初始化；优先默认参数与 `dataclass` 字段默认值，避免可变默认参数陷阱（`def f(x=[]):`）。
- 使用类型注解（PEP 484）表达参数与返回类型；运行时动态类型只在适配层使用。
- 协议、文件和二进制接口使用固定宽度整数（`int` 无限精度，但序列化使用固定字节）；容器大小和索引使用领域类型或经检查转换。
- 禁止未检查的窄化与符号混用；关键路径使用 `int` 显式校验范围。
- 使用 `enum.Enum`（需要标志位使用 `enum.IntFlag`）；序列化值与枚举显式映射，不依赖数值顺序。
- 使用 `None` 与 `Optional[T]` 表达可空性，不使用哨兵值。
- 使用 `dataclass` 和 `frozen=True` 表达值语义数据；使用 `property` 保护不变量。
- 使用 `Final` 与 `Literal` 表达常量与封闭取值，不为“现代化”机械添加。

## 函数与控制流

- 函数保持单一职责；参数过多或多个布尔开关时使用选项对象或参数对象，不用位置参数猜测语义。
- 优先早返回降低嵌套；复杂条件提取为命名局部函数或方法。
- 默认按值返回不可变对象；大对象按引用或视图返回时必须保证生命周期。
- 输入参数按值、引用（可变默认）、`Sequence`/`Protocol` 选择，所有权和生命周期必须清楚。
- 输出优先使用返回值；多个结果使用具名 `NamedTuple` 或 `dataclass`，不使用无语义大量输出参数。
- 不使用 `bool` 参数切换多个行为；使用 `Enum`、选项对象或拆分函数。
- 类的方法第一个参数必须是 `self`，静态方法/类方法使用 `cls`。
- 尽可能使用 `is`/`is not` 取代 `==`，比如 `if x is not None` 优于 `if x`；但比较值相等仍用 `==`。
- 使用 `startswith()`/`endswith()` 代替切片进行序列前缀或后缀检查：

```python
# Yes
if foo.startswith("bar"):
# No
if foo[:3] == "bar":
```

- 使用 `isinstance()` 比较对象的类型：

```python
# Yes
if isinstance(obj, int):
# No
if type(obj) is type(1):
```

- 判断序列空或不空使用真值测试：

```python
# Yes
if not seq:
    ...
if seq:
    ...
# No
if len(seq):
    ...
if not len(seq):
    ...
```

## 自动验收

- CI 运行 `ruff format --check` 与 `ruff check` 检查格式与 lint。
- `ruff.toml`/`pyproject.toml` 配置在 CI 中校验，不依赖开发者手工记忆格式规范。
- 公共 API 变更通过 mypy `--strict` 与 `__all__` 守护。
- 导入排序由 ruff 的 `I` 规则统一，不依赖手工维护。
