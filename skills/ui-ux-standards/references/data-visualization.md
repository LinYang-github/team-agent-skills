# 数据可视化规范

本文件规定图表和分析结果如何被界面清晰表达，不定义业务指标、统计方法、算法结论或数据治理规则。图表不能替代数据契约和领域解释，必要时应同时提供表格或详情。

## 图表选择与结构

- 先明确任务是比较、趋势、分布、关系、组成还是定位异常，再选择图表类型；不要为了“丰富”叠加无任务图表。
- 标题、时间范围、筛选条件、单位、数据版本和更新时间靠近图表表达；用户不应依赖悬停才能知道图表在展示什么。
- 坐标轴、刻度、基线、范围和精度保持可解释；不通过截断坐标或过度缩放夸大差异。
- 图例与数据系列一一对应，系列命名使用业务已确认的术语；同一页面相同语义使用稳定颜色和线型。
- 使用 ECharts 时，为深色主题提供统一的深色配置；折线、雷达、柱状和环形等图表的文字、图例、坐标轴、数据标签、节点与连线均需在深色背景上清晰可辨。

## 数据状态与不确定性

- 缺失、无效、延迟、估算、异常和零值分别表达，不能统一画成 0、空白或正常线段。
- 当系统提供置信区间、误差范围、样本量或数据质量时，在图表或邻近详情中保持可理解，不隐藏关键限制。
- 加载、空数据、无筛选结果、部分失败和刷新中的图表保持容器稳定，并说明原因与下一步。
- 数据来源、版本、时间和筛选上下文如果由系统提供，应与图表结果保持关联，不能只在页面底部隐藏。

## 颜色、可读性与主题

- 颜色不是唯一的数据编码；同时使用位置、形状、线型、标签或表格支持区分。
- 树图、拓扑图、流程图和层级关系图使用颜色区分层级、类型或状态时，必须同时提供层级标签、文字、形状、位置或连线关系中的至少一种；去除颜色后，核心关系仍应可辨识。
- 颜色数量保持克制，避免无语义彩虹色；连续数值、分类、状态和强调色使用不同语义策略。
- 浅色、深色、色觉差异、低对比度环境和打印/导出场景下都要检查图表可读性。
- 网格线、背景、阴影和装饰不应压过数据；强调只用于当前比较重点、异常或用户主动选择。

## 交互与替代表达

- 悬停提示用于补充精确值，不能承载唯一的关键结论；选中、聚焦和详情查看应有键盘或按钮入口。
- 缩放、平移、筛选、图例开关和时间范围变化保持当前上下文，并提供重置或恢复入口。
- 复杂画布的缩放、平移、适应视口、复位、定位、布局和导出等画布级操作应靠近画布放置，并在同一产品内保持稳定分组和顺序；不要与页面级提交、删除或导航操作混入同一工具栏。
- 画布工具可以采用图标按钮，但必须提供可访问名称和悬浮提示；高频操作持续可见，低频操作可以收纳，关键能力不得只依赖鼠标滚轮、拖拽或右键菜单。
- 复杂图表、高密度点云和流程图提供表格、列表、摘要或导出等替代表达，避免用户只能依赖视觉定位。
- 导出图片、数据或报告时明确导出范围、筛选条件、单位、版本和时间，不能让导出结果脱离上下文。

## 性能与验收

- 大数据量图表采用分段加载、聚合、降采样或视口渲染；交互不能因全量重绘阻塞页面。
- 图表加载失败、组件不支持或数据版本不兼容时，提供可理解的错误和表格/原始数据替代。
- 验收至少覆盖短/长标签、极值、缺失值、异常值、深浅色、窄窗口、键盘操作、导出和刷新状态。
