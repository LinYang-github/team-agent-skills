# 弹层与反馈规范

本文件统一桌面端企业应用中的加载、进度、模态框、抽屉、Popover、Toast、Notification、Banner 和确认提示。组件宽度、圆角、内边距与按钮尺寸由 [正文组件规格](component-specifications.md) 定义；用户可见术语、错误文案和帮助遵循 [界面文案、术语与帮助规范](content-and-guidance.md)；本文件只规定选型、时机、遮罩、焦点、键盘、关闭方式、按钮顺序和反馈时长。

## 统一原则

- 反馈强度与用户是否必须立即决策相匹配，不用模态框表达普通成功，不用短暂 Toast 承载必须处理的信息。
- 同一种结果在不同项目中使用相同反馈层级、状态语义、按钮顺序和关闭行为；项目品牌只能调整令牌映射，不能改变交互含义。
- 反馈尽量靠近操作对象。字段错误放在字段旁，局部加载失败放在局部面板，全局异步结果才使用全局通知。
- 正常加载、页面进入和后台数据读取不弹成功提示；只有用户需要知道、判断或采取行动的结果才主动打扰。
- 不使用浏览器原生 alert、confirm 和 prompt。

## 响应时延与状态反馈

交互反馈按用户感知时长分级，不为每次点击机械显示 Spinner：

| 预计时长 | 默认反馈 |
| --- | --- |
| 小于 100ms | 直接更新界面，不显示加载动画 |
| 100ms～1s | 立即显示按下、选中、禁用或局部状态变化，避免短暂闪烁的 Loading |
| 超过 1s | 显示与操作对象对应的局部加载状态 |
| 超过 10s | 显示阶段或真实进度，并提供取消、后台运行或离开后的状态入口 |

- 点击、选择、拖拽、键盘命令和提交等有业务结果的操作必须给出可观察反馈；浏览器原生滚动等自身已可见行为不重复增加提示。
- 加载范围与任务范围一致：局部请求不遮罩整页，整页初始化也不让多个组件同时无序闪烁。
- 快速操作避免 Spinner 一闪而过；可以通过按钮按下、禁用、骨架稳定或内容占位表达进行中。
- 超时只是失败类型之一，不能一直显示无期限加载；达到系统超时后转为可恢复错误并保留当前上下文。
- 页面和工作台刷新尽量保留现有数据，以轻量“更新中”表达后台刷新，不清空内容制造跳动。

## 真实进度与长任务

- 只有总量和完成量可可靠计算时才显示百分比；不能计算时使用阶段、步骤、已处理数量或不确定进度，不伪造精确百分比。
- 进度条与阶段文字必须来自同一任务状态，不能出现百分比完成而阶段仍停留在开始状态。
- 长任务说明当前阶段、已完成量、剩余状态和失败项；能够取消时提供明确取消，不能取消时不显示无效按钮。
- 用户离开页面后任务仍继续时，应提供可恢复的任务入口、当前状态和完成反馈；是否支持后台任务由产品能力决定。
- 多任务并行时显示各自状态或汇总，不用一个全局进度条掩盖部分失败。
- 完成后结果已经在页面明显呈现时不重复成功提示；完成发生在其他页面或后台时使用 Notification 或持久入口。
- 进度更新不应让布局、按钮宽度和面板高度持续跳动。

## 弹层选型

| 类型 | 适用任务 | 不适用任务 |
| --- | --- | --- |
| Tooltip | 图标名称、快捷键、短提示 | 必须阅读的业务说明、操作结果 |
| Popover | 与触发点相关的少量详情或轻量操作 | 复杂表单、危险确认 |
| 下拉菜单 | 一组低频命令或选择项 | 长说明、多阶段任务 |
| 抽屉 | 保留主工作区上下文的详情、编辑和辅助任务 | 必须阻断背景操作的决策 |
| 模态框 | 用户必须完成、确认或取消后才能继续的局部任务 | 普通信息展示、长期监视 |
| Alert Dialog | 风险、冲突、不可逆操作或必须立即确认的异常 | 一般成功和低风险提示 |

- 能在当前页面或当前弹窗内清楚完成的任务，不额外打开弹层。
- 需要同时查看背景内容时优先抽屉；需要用户集中决策并阻断背景交互时使用模态框。
- 弹层不能代替页面层级。复杂、多阶段、需要保存工作状态的任务优先使用独立页面或向导。

## 模态框结构与位置

模态框按以下结构组织：

    标题区：任务标题、必要状态、关闭按钮
    内容区：说明、表单、影响范围或结果
    页脚区：辅助操作、取消、主要操作

- 标题使用具体任务或问题，例如“删除指标？”“保存方案”，不用“提示”“温馨提示”或“系统消息”。
- 短确认框在视口中视觉居中；长表单水平居中并从视口顶部约 8～10% 开始，避免内容重心过低。
- 高度原则上不超过可用视口的 80%；超过后只有内容区滚动，标题和页脚保持可见。
- 弹窗打开和内容加载不得造成位置大幅跳动；错误信息出现时优先在内容区预留或扩展空间。
- 右上角关闭按钮只在任务允许取消时显示，其语义与“取消”一致。

## 遮罩与背景

- 模态框打开后，背景进入不可交互状态：禁止鼠标点击、键盘聚焦和辅助技术误访问，并锁定背景滚动。
- 遮罩颜色使用设计令牌。默认浅色主题采用 rgba(15, 23, 42, 0.45)，深色主题采用 rgba(0, 0, 0, 0.60)。
- 默认点击遮罩不关闭模态框，避免表单、配置和确认任务意外丢失。
- 纯预览、无编辑且无损失风险的轻量模态框可以允许点击遮罩关闭，但必须与关闭按钮和 Esc 保持同一取消语义。
- 二级弹层不得重复叠加遮罩造成背景越来越黑；同一模态链视觉上只保留一层主遮罩。
- 遮罩不使用模糊、强渐变和发光作为默认效果。

## 初始焦点

打开弹层后的焦点遵循以下优先级：

| 场景 | 初始焦点 |
| --- | --- |
| 普通表单 | 第一个可编辑且有效的字段 |
| 存在校验错误的表单 | 第一个错误字段 |
| 普通确认 | 主要操作按钮 |
| 删除、覆盖等危险确认 | “取消”按钮或最安全操作 |
| 纯信息弹窗 | 关闭按钮或内容标题容器 |
| 抽屉详情 | 标题或第一个可操作控件 |

- 不把焦点默认放在危险操作按钮上，避免 Enter 误触。
- 初始焦点不能落到隐藏、禁用、滚动区域之外或仅装饰元素。
- 弹层标题与说明建立可访问关联；模态框使用 dialog 语义，必须立即确认的风险提示使用 alertdialog 语义。

## 焦点陷阱与恢复

- 模态框打开时，Tab 和 Shift+Tab 只在当前模态框内循环，背景控件不能获得焦点。
- Popover、菜单和非模态抽屉根据组件语义管理焦点，但关闭后都应返回触发控件。
- 关闭模态框后，焦点返回打开它的原控件；原控件已被删除或隐藏时，返回最近的可理解上级入口。
- 二级弹层打开时，父弹窗保持挂载但进入不可交互状态；只有最上层拥有焦点陷阱。
- 焦点环必须在浅色、深色和高 DPI 下可见，不被 overflow、圆角或遮罩裁剪。

## 键盘与关闭行为

- Esc 默认执行当前最上层弹层的取消或关闭，不同时关闭父弹窗。
- 提交中、不可中断操作或业务明确要求强制处理时可以暂时禁用 Esc，但界面必须显示原因和进行中状态。
- 普通表单可以使用 Enter 提交，但文本域、组合输入、下拉菜单和输入法候选状态不得触发提交。
- 危险操作只有危险按钮已获得焦点时，Enter 才能执行；禁止弹窗打开后直接按 Enter 删除或覆盖。
- 关闭按钮、取消按钮、Esc 和允许的遮罩点击必须走同一取消流程，包括未保存检查、清理和焦点恢复。
- 用户存在未保存内容时，优先在当前弹窗内切换为离开确认状态；无法合并时才使用受控的二级确认。

## 页脚与按钮顺序

企业桌面 Web 应用统一采用右对齐页脚：

    [取消] [主要操作]

- 取消在左，确定、保存、继续、删除等主要操作在右；所有项目、普通弹窗和危险弹窗保持一致。
- 危险操作不反转按钮顺序，也不通过扩大按钮诱导点击；右侧主要按钮改用危险语义样式。
- 两个按钮默认间距 8px，高度、圆角和字号遵循正文组件规格。
- 主要按钮使用具体动作名称，如“保存”“删除”“覆盖”“继续”，不用含义模糊的“确定”。
- 取消按钮统一使用“取消”；纯信息弹窗的单一按钮使用“关闭”或“知道了”，根据实际语义选择。
- 同一弹窗原则上只有一个主要操作。第三个辅助操作放在页脚左侧，与右侧决策按钮分组：

      [查看影响]                         [取消] [继续]

- 不同时提供右上角关闭、页脚关闭和多个含义相同的取消入口；允许取消时可以保留右上角关闭与页脚取消，但二者必须同义。
- 页脚按钮顺序不能因组件库、页面作者或危险状态而变化。

## 危险确认

- 标题直接提出具体问题，例如“删除指标‘命中概率’？”。
- 内容说明操作对象、影响范围、是否可恢复以及必要的后续影响，不使用只写“是否确认”的空泛文案。
- 危险按钮使用动作名称，不使用“确定”；取消保持普通次要样式。
- 可恢复、低影响操作使用一次确认即可；高影响、批量、跨范围或不可恢复操作可以要求输入对象名称、确认范围或执行原因。
- 确认强度必须与风险匹配，不能所有删除都要求输入名称，也不能关键覆盖只用短暂 Toast。
- 执行中禁用重复提交并保留弹窗；失败时在弹窗内说明原因和修复方式，不关闭后只弹一条模糊错误。

## 二级弹窗与嵌套弹层

- 默认禁止模态框上再打开普通模态框。
- 选择对象、查看详情、填写补充信息等任务优先在父弹窗内切换步骤、展开区域，或使用不会形成第二模态层的局部面板。
- 只有凭据/权限验证、不可逆操作确认、未保存离开确认和无法在父弹窗表达的冲突处理可以使用二级 Alert Dialog。
- 最多允许两层模态，禁止三级弹窗。
- 二级弹窗应比父弹窗更小，任务单一，不与父弹窗形成两个近似大小的工作区。
- 二级弹窗打开时不重复加深遮罩；父弹窗可见但不可交互，最上层独占 Esc、Enter 和焦点陷阱。
- 关闭二级弹窗后，焦点返回父弹窗中的触发控件；关闭父弹窗后再返回页面触发控件。
- Toast、Tooltip、下拉菜单不计为二级模态，但必须处于正确层级，不得被遮罩覆盖或浮在无关弹窗之上。

## 异步提交与关闭

- 提交开始后，主要按钮进入加载状态并保持原宽度，相关字段和重复提交入口按任务需要禁用。
- 可取消请求提供明确取消入口；不可取消请求不得伪装成可关闭后继续安全运行。
- 成功后若弹窗关闭且页面变化足以表达结果，不重复弹成功 Toast；结果不明显时使用一次轻量成功反馈。
- 失败时优先在弹窗内容区或对应字段附近反馈，保留用户输入和当前滚动位置。
- 弹窗关闭前清理临时事件、计时器和焦点状态；UI/UX 规范只要求可观察行为，具体实现由前端工程规范约束。

## 反馈层级

| 反馈类型 | 适用场景 | 默认位置 | 是否自动关闭 |
| --- | --- | --- | --- |
| 字段反馈 | 校验、格式、必填和字段级错误 | 字段附近 | 修复后消失 |
| 局部反馈 | 面板、表格、图表或局部请求结果 | 对应区域内 | 状态恢复后消失 |
| Toast | 保存、复制、导出等短暂操作结果 | 全局右上方 | 按状态时长 |
| Notification | 异步任务、跨页面结果、可执行通知 | 全局右上方 | 视是否需要处理 |
| Banner | 当前页面持续生效的限制、异常和风险 | 页面内容顶部 | 条件解除或用户关闭 |
| Modal / Alert Dialog | 必须立即决定、阻断继续的任务 | 视口模态层 | 用户操作后关闭 |
| 通知中心 | 需要保留、回看和处理的事件 | 全局入口 | 按产品数据保留 |

- 重要告警和需要追踪的事件不能只以 Toast 出现，应进入持久入口；本技能不定义告警业务等级。
- 同一错误不同时使用字段错误、Toast 和模态框重复轰炸。选择离问题最近且强度足够的一层。
- 页面可见变化已经明确表达成功时，不再追加成功 Toast。

## Toast 与 Notification

- Toast 与 Notification 默认位于应用壳下方的右上区域，距内容区顶部和右侧各 16～24px，不遮挡全局工具、当前任务和主要操作。
- 默认宽度 320～400px，最多同时显示 3 条；超过时合并同类消息或进入通知中心，不无限向下堆叠。
- 相同来源、相同错误码和相同对象的重复消息在短时间内合并，并显示次数或最新状态。
- 默认时长：

| 状态 | 默认时长 |
| --- | --- |
| 成功 | 3 秒 |
| 普通信息 | 4 秒 |
| 警告 | 6 秒 |
| 无需处理的错误 | 6 秒 |
| 需要用户处理的错误 | 不自动关闭 |

- 鼠标悬停、键盘聚焦或用户正在选择文本时暂停自动关闭计时。
- 包含“重试”“查看详情”“撤销”等操作时使用 Notification，并保持到用户处理或明确关闭。
- Toast 原则上不放多个操作按钮；需要决策时升级为 Notification、Banner 或模态框。
- 关闭按钮具有可访问名称，关闭后焦点不跳到不可预测位置。

## 提示文案

- 标题、按钮、状态、错误信息、支持编号和常见失败场景统一遵循 [界面文案、术语与帮助规范](content-and-guidance.md)。
- 本文件只补充反馈容器要求：短 Toast 保留一句明确结果，Notification 可以增加下一步操作，模态框必须说明决策对象和影响。
- 同一结果在字段、局部面板和全局反馈之间只选择足够的一层，不复制相同文案反复打扰。

## 层级、主题与动效

- 弹层层级由全局令牌统一管理，至少区分页面、固定壳、下拉/Popover、遮罩、模态框和全局反馈；页面不得使用任意超大 z-index 抢占层级。
- 属于当前模态框的下拉菜单、日期面板和 Tooltip 显示在该模态框之上，但不得越过更高层二级 Alert Dialog。
- Toast 和全局 Notification 位于普通模态层之上，但只显示与当前上下文相关的反馈，不遮挡关键确认按钮。
- 浅色、深色和跟随系统主题都要验证遮罩、弹层边界、正文、状态图标、焦点环和危险按钮。
- 打开和关闭动效快速克制，不缩放到引起内容跳动；减少动效设置下关闭非必要过渡。

## 验收清单

1. 当前任务是否真的需要模态阻断，能否改用页面、抽屉或局部反馈。
2. 遮罩是否使背景不可点击、不可聚焦并锁定滚动，点击遮罩是否按默认规则不关闭。
3. 初始焦点是否符合任务风险，危险按钮是否未被自动聚焦。
4. Tab 是否限制在当前弹层，关闭后焦点是否返回正确触发控件。
5. Esc、Enter、关闭按钮、取消按钮和未保存检查是否语义一致。
6. 页脚是否右对齐、取消在左、主要操作在右，危险状态是否未反转顺序。
7. 是否避免普通嵌套模态；允许的二级 Alert Dialog 是否不超过两层、不重复加深遮罩。
8. 响应反馈是否匹配实际时长；超过 1 秒是否有局部加载，超过 10 秒是否有阶段、真实进度或可恢复入口。
9. Toast/Notification 的位置、时长、堆叠、去重和操作是否符合统一规则。
10. 错误是否优先靠近问题，重要通知是否有持久入口，普通加载是否未弹成功提示。
11. 百分比是否真实可计算，长任务是否说明阶段、取消能力和部分失败。
12. 两种主题、窄窗口、长内容、键盘和高 DPI 下是否仍可阅读、关闭和完成操作。
