# 数据密集型工作台模式

本文件适用于表格、树、矩阵、日志、时间线和分析结果等高信息密度界面。目标是支持持续观察、比较、定位和批量处理，不是把所有字段堆成卡片或把每个数据点都突出显示。

表格、树、工具栏、筛选和行操作的紧凑/默认密度统一使用 [正文组件规格](component-specifications.md)；本文件只决定何时使用紧凑模式，不重新定义尺寸。

## 任务与结构

- 先明确用户是在浏览、比较、定位、编辑、批量处理还是追踪变化，再决定表格、树、分栏或矩阵结构。
- 页面保持稳定上下文：当前对象、筛选范围、数据时间、刷新状态和主要操作不要随着局部刷新消失。
- 表格用于横向比较和批量处理，树用于层级浏览和节点管理，详情面板用于深入查看；不要让多个组件在同一位置重复承担相同职责。
- 主工作区优先保留数据和当前任务，低频说明、辅助统计和历史信息放入详情、侧栏或可展开区域。

## 表格与列

- 列按用户任务排序，核心识别字段和状态字段保持稳定位置；低频字段可隐藏、分组或放入详情。
- 支持明确的排序、筛选、分页、列宽、列显示/隐藏和固定列语义；当前条件和排序方向必须可见。
- 长文本、代码、路径和数值提供合理截断、完整查看、复制和对齐方式；不能为了整齐隐藏关键差异。
- 表格密度可控但层级有限；行高、表头、选中、悬停、禁用和错误态在两种主题下都可区分。
- 批量选择说明作用范围（当前页、筛选结果或全部数据），批量操作反馈成功、失败和部分成功，不用一条模糊提示覆盖结果。

## 树、筛选与导航

- 树节点的展开、选中、定位、新增、编辑、删除和更多操作就近出现，并保持当前路径和父子关系可理解。
- 深层树提供搜索、定位、面包屑或路径信息；搜索结果说明匹配范围，不能只把节点平铺成失去层级的列表。
- 多条件筛选按任务分组，显示已生效条件、结果数量和清空/恢复入口；筛选无结果与没有数据使用不同状态。
- 筛选、分页、列配置和视图模式是否写入 URL 或用户偏好，按可分享、可恢复和安全要求决定。

## 刷新、变化与大数据

- 刷新或实时更新尽量保持筛选、选中、滚动和当前详情；数据过期、更新中和更新失败要有轻量但可发现的状态。
- 数据量较大时使用分页、虚拟滚动、分段加载或服务端筛选；加载中不能让整个工作台跳动。
- 空数据、部分加载、部分失败、权限不足和无搜索结果分别表达原因和下一步，不显示一堆不可操作的空控件。
- 用户正在编辑或批量选择时，外部刷新不能静默覆盖；需要提示冲突、保留本地修改或提供恢复路径。

## 工作台验收

至少检查：

1. 用户能否快速判断当前数据范围、更新时间和主要操作。
2. 长文本、大数字、缺失字段和异常值是否仍可比较。
3. 筛选、排序、分页、列设置和批量操作是否可发现、可恢复。
4. 刷新、实时变化、空/失败/无权限状态是否保持上下文。
5. 键盘、主题、窄窗口和大数据量下的焦点、滚动与性能是否可靠。
