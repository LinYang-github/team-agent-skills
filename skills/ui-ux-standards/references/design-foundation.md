# 设计基础规范

本文件是颜色、字体、间距、形状、层级、密度和主题的基础令牌唯一来源。默认数值用于没有成熟设计系统的新项目；已有项目先建立语义映射并渐进收敛，不在页面和其他规范文件中复制一套近似数值。

## 令牌分层

推荐将令牌分成三层：

1. **原始值**：色板、字号、间距、圆角、阴影和动效曲线。
2. **语义值**：页面背景、内容面、主要文字、次要文字、分隔线、主操作、成功、警告、危险、信息。
3. **组件值**：按钮、输入框、表格、导航、标签、弹窗等组件如何引用语义值。

页面和业务组件尽量只使用语义值，避免直接写 #409EFF、#303133 之类的原始颜色。

令牌治理遵循以下规则：

- 基础字号、行高、间距、圆角、控件高度、图标尺寸和边框宽度只在本文件定义。
- 按钮、输入框、表格、树、弹窗等如何组合基础令牌，统一由 [组件规格](component-specifications.md) 定义。
- 应用顶栏、导航和上下文栏的专属尺寸由 [应用壳与导航规范](application-shell-and-navigation.md) 定义，但其字体、圆角和图标应尽量映射本文件的基础阶梯。
- 交互模式和页面模式只描述职责、场景与状态，不重新创造尺寸。
- 新增数值必须说明现有阶梯为何不能表达新语义，并进入令牌层或明确的组件专属令牌；禁止页面内临时增加相近值。

## 颜色

- 主色用于主要操作、当前导航、链接和关键选中态，不要把整页背景或所有按钮都染成主色。
- 成功、警告、危险、信息是语义色，不等同于四种品牌色；同一状态在标签、图标、文字和边框中保持一致。
- 背景至少区分页面背景、内容面、浮层面和输入区域；相邻区域有层级即可，不要用大量边框制造层级。
- 文字至少区分主要、常规、次要和禁用；辅助文字不能承担唯一的关键信息。
- 颜色不能是唯一的状态表达方式，同时使用文字、图标、形状或位置。
- 图表颜色需要考虑相邻色可区分、深色模式和色觉差异，避免无语义的彩虹色。

### 无品牌规范时的默认企业蓝

当项目没有既有品牌色、设计令牌或主题配置时，使用以下语义令牌作为默认起点：

    :root {
      --primary: #2563eb;
      --primary-strong: #1d4ed8;
      --primary-soft: #eff6ff;
      --overlay-mask: rgba(15, 23, 42, 0.45);
    }

    :root[data-theme='dark'] {
      --primary: #60a5fa;
      --primary-strong: #3b82f6;
      --primary-soft: #172554;
      --overlay-mask: rgba(0, 0, 0, 0.60);
    }

这组颜色是默认主题基线，不是强制品牌标准。项目已有品牌色时，优先保留项目品牌，并只要求映射到主操作、选中态、链接、焦点和相关组件令牌。状态色（成功、警告、危险、信息）仍按各自语义维护，不因主色为蓝而全部改成蓝色。

遮罩属于语义层令牌，不与品牌主色绑定。项目调整遮罩时必须同时验证背景隔离、弹窗边界和深浅主题，不在单个页面直接写不同透明度。

## 字体与信息层级

- 优先使用项目已有字体；中文界面优先保证字形覆盖和数字可读性。
- 页面标题、区块标题、正文、表格、辅助信息和标签使用以下有限层级，不为了“丰富”而增加相近字号。
- 正文默认 14px，数据密集型表格可使用 13px；任何正文和可操作文字不得低于 12px。
- 12px 只用于时间、计数、标签和不承担关键含义的辅助信息，不能用来隐藏复杂说明或压缩重要内容。
- 数字、时间、代码和标识符可使用等宽字体，但不要把业务正文全部改成等宽字体。

默认排版阶梯：

| 语义 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 20px / 28px | 700 |
| 区块标题 | 16px / 24px | 600 |
| 小标题、强调正文 | 14px / 22px | 600 |
| 正文、表单值、按钮 | 14px / 22px | 400～500 |
| 表格、树和紧凑正文 | 13px / 20px | 400～500 |
| 辅助信息、标签 | 12px / 18px | 400～500 |

默认字体令牌：

    --font-size-caption: 12px;
    --font-size-compact: 13px;
    --font-size-body: 14px;
    --font-size-section-title: 16px;
    --font-size-page-title: 20px;
    --line-height-caption: 18px;
    --line-height-compact: 20px;
    --line-height-body: 22px;
    --line-height-section-title: 24px;
    --line-height-page-title: 28px;
    --font-weight-regular: 400;
    --font-weight-medium: 500;
    --font-weight-semibold: 600;
    --font-weight-bold: 700;

## 间距、尺寸与密度

- 统一使用 2、4、8、12、16、20、24、32px 间距阶梯；除 1px 边框、3px 导航指示条等专属值外，不新增零散间距。
- 同一页面内同类组件的内边距、控件高度和行高保持一致。
- 先通过留白和分组建立层级，再使用边框；卡片不是所有内容的默认容器。
- 管理后台可以保持中高密度，但表格、表单和操作区不能拥挤到难以点击。
- 弹窗、抽屉和操作栏应根据任务复杂度确定宽度，不用固定大尺寸套用所有场景。

默认间距与尺寸令牌：

    --space-1: 2px;
    --space-2: 4px;
    --space-3: 8px;
    --space-4: 12px;
    --space-5: 16px;
    --space-6: 20px;
    --space-7: 24px;
    --space-8: 32px;
    --control-height-compact: 28px;
    --control-height-default: 32px;
    --control-height-large: 36px;
    --icon-size-small: 14px;
    --icon-size-default: 16px;
    --icon-size-large: 18px;
    --icon-size-emphasis: 20px;

- 32px 是正文区域按钮、输入框、选择器、分页和普通工具控件的默认高度。
- 28px 仅用于表格行操作、紧凑工具栏和空间受限的高密度工作区。
- 36px 仅用于低密度表单、向导关键操作或需要更大点击区的场景，不作为页面内普通按钮的默认值。
- 同一操作组原则上只使用一个控件高度；不得用尺寸大小表达主次操作。

## 边框、圆角与阴影

- 边框用于分隔和交互边界，不用于装饰每一个区块。
- 同一产品使用固定圆角阶梯：2px、4px、6px、8px 和完全圆形，不使用 3px、5px、7px、10px 等临时近似值。
- 军工软件的桌面任务界面默认使用小到中等圆角，避免大圆角和胶囊型按钮造成消费产品或营销页面的视觉倾向。圆角应服务于控件边界识别，不作为装饰性风格。
- 胶囊形优先保留给标签、状态、筛选条件等具有标记语义的元素；圆形优先用于明确的图标操作或状态指示。品牌组件和明确的用户任务可以例外，但应保持同一页面内的层级一致。
- 阴影用于浮层、拖拽、悬浮和焦点，不给所有卡片加重阴影。
- 深色模式优先通过背景、边框和文字层级表达，不依赖发光效果。

默认形状令牌：

    --radius-xs: 2px;
    --radius-sm: 4px;
    --radius-md: 6px;
    --radius-lg: 8px;
    --radius-full: 999px;
    --border-width-default: 1px;
    --focus-ring-width: 2px;

默认映射关系：

| 元素 | 默认圆角 |
| --- | --- |
| 普通按钮、输入框、选择器、分页按钮 | 4px |
| 图标按钮、下拉菜单、浮出面板 | 4～6px |
| 卡片、面板、树或表格外容器 | 6px |
| 模态框、较大浮层 | 8px |
| 小型状态标签 | 2～4px |
| 筛选条件、明确的胶囊标签 | 完全圆角 |

- 主按钮、次按钮和危险按钮使用相同圆角；操作层级由颜色、边框、字重和位置表达。
- 普通按钮、工具按钮和导航项不得使用完全圆角。
- 卡片嵌套时不逐层增加圆角和边框，内部区域优先使用间距、标题和背景层级。

## 军工桌面视觉倾向

- 控件默认紧凑、矩形、层级明确；不要用大面积实心色、大圆角或夸张尺寸制造强调。
- 不默认使用大面积渐变、玻璃拟态、强发光、装饰性插画、巨型标题或营销式首屏。
- 面板层级优先通过背景差异、间距、对齐和轻量阴影表达；边框只承担明确的分隔或交互边界。
- 同一工作台内按钮、输入框、选择框和工具栏控件保持有限的高度层级，避免多套密度混杂。

## 主题

- 使用语义 CSS 变量或主题配置切换，不在组件中分散写死浅色和深色值。
- 主题选项默认包含“跟随系统、浅色、深色”；首次访问和清除本地偏好时默认跟随系统。
- “跟随系统”应读取操作系统的 `prefers-color-scheme`，并在系统主题变化时实时同步；用户明确选择浅色或深色后才覆盖系统偏好。
- 主题选择器明确显示当前偏好（跟随系统/浅色/深色）和当前生效主题，不能只用太阳/月亮图标让用户猜测。
- 首屏在应用挂载前解析主题，避免从默认主题闪烁到系统主题；浏览器地址栏/标签页的主题色也同步当前生效主题。
- 深色背景不应直接使用纯黑，层级差异也不应依赖极细边框。
- 检查输入框、下拉菜单、表格斑马纹、图表、滚动条、弹窗和空状态等容易遗漏的区域。
- 深色主题滚动条使用与深色工作台一致的深蓝色轨道和可辨识滑块，不保留浏览器默认灰色滚动条。
- 切换主题后不改变布局和信息层级，只改变视觉令牌。

## 图标与动效

- 选择项目已有图标库；图标用于识别操作或状态，不能替代必要的文字说明。
- 只图标按钮必须有可访问名称和悬浮提示，危险操作应有明确语义。
- 动效服务于状态变化、空间关系和反馈；默认快速、克制、可被减少动效设置关闭。

## 任务型界面的基础原则

以下原则已针对军工软件的长期值守、任务操作和高信息密度场景重新解释，不能脱离上下文机械套用：

- **从功能开始，而不是先画外壳**：先列出当前任务的输入、判断、主要动作、结果和异常，再决定导航、面板和卡片。页面壳不能先于任务关系。
- **先建立层级，再装饰**：用位置、间距、字重、对比度和容器关系建立优先级，不依赖更大的标题、更多颜色或粗边框。
- **限制选择**：颜色、字号、间距、圆角、阴影和控件高度从有限令牌中选择；新值必须能解释为新增语义，而不是临时微调。
- **弱化竞争元素**：主操作不突出时，先降低次要操作、非当前导航和辅助信息的对比度，避免所有东西同时抢注意力。
- **彩色背景上的文字要重新配色**：不要把灰色辅助文字直接放到主色、状态色或图像上；根据背景重新选择可读的同色相或中性色。
- **控制尺寸和阅读宽度**：固定任务面板、表格列和操作区的合理最小/最大宽度，不让所有区域随屏幕无限伸缩；连续阅读文本保持适合阅读的行长。
- **减少边框**：优先尝试留白、不同层级背景、轻量阴影和对齐关系，只有确有分隔或交互边界时才使用边框。
- **元素有意图尺寸**：图标、状态标记、按钮和面板应使用与其语义匹配的尺寸；不要放大普通小图标充当大型插图，也不要缩小到难以识别。
- **空状态是任务状态**：无数据、未配置、等待采集和无权限分别说明原因和下一步，不展示一堆暂时不可操作的空组件。
