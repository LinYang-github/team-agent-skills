# 交互模式规范

本文件只规定组件的职责、操作层级和交互语义。正文控件的字号、高度、内边距、圆角和图标尺寸统一遵循 [正文组件规格](component-specifications.md)；模态框、遮罩、焦点、按钮顺序和全局提示遵循 [弹层与反馈规范](feedback-and-overlays.md)，不得在页面模式或局部样式中另建一套近似规则。

## 页面导航与上下文

- 产品身份、一级导航、上下文栏、阶段导航、页面标题和面包屑遵循 [应用壳与导航规范](application-shell-and-navigation.md)。
- 页面操作区优先展示主要操作，次要操作放入更多菜单；危险操作与普通操作有明显区分。

## 按钮与图标操作

- 主操作每个视图原则上只有一个；同级操作按主次、危险程度和频率排序。
- 按钮默认规格、紧凑/默认/大型的适用边界和圆角规则以 [正文组件规格](component-specifications.md) 为准；普通操作不得通过临时放大、胶囊化或改变圆角表达主次。
- 高频且语义明确的操作可以使用图标；低频、危险或容易误解的操作保留文字。
- “编辑、删除、新增、更多、复制、下载、筛选、刷新”等操作优先使用项目统一图标，图标和文字不重复表达。
- 加载中禁用重复提交并提供进行中状态；成功、失败和网络异常提供与操作相关的反馈。
- 删除、清空、覆盖、发布、提交等操作按风险选择确认强度，具体遵循 [弹层与反馈规范](feedback-and-overlays.md)。

## 可用、禁用、只读与隐藏

控件状态根据用户是否需要理解能力存在、当前能否执行以及是否允许查看来选择：

| 状态 | 使用条件 | 界面要求 |
| --- | --- | --- |
| 可用 | 当前条件和权限满足 | 正常操作并提供即时反馈 |
| 禁用 | 能力存在，但前置条件、状态或临时限制未满足 | 保留位置，说明不可用原因和恢复条件 |
| 只读 | 允许查看、选择或复制，但不允许修改 | 与禁用明确区分，不伪装成可编辑输入 |
| 隐藏 | 当前任务完全无关，或权限/安全策略要求不暴露 | 不留下空位、空分组和不可达选中态 |

- 不把所有无权限操作一律禁用，也不把所有暂时不可用操作直接隐藏。
- 用户需要学习流程或判断下一步时，优先保留禁用入口并说明前置条件。
- 按业务状态暂时不可用的按钮保持稳定位置，避免状态变化造成操作区跳动。
- 禁用原因通过就近说明、Tooltip 或状态提示表达，不能只显示灰色让用户猜测。
- 隐藏由权限和产品策略决定；UI 技能只约束隐藏后的布局和当前状态仍然可理解。

## 防错、可恢复与确认强度

- 优先从源头限制错误：合理默认值、受控选项、范围限制、格式提示、冲突预警和重复提交防护。
- 前端校验用于即时反馈，不能代替后端权威校验；安全、权限和数据完整性不依赖界面限制。
- 用户输入、筛选、选择和滚动位置在可恢复失败后应尽量保留。
- 可撤销且影响较低的操作可以直接执行并提供撤销，不机械增加确认弹窗。
- 不可逆、批量、跨范围和高影响操作使用逐级增强确认：

| 风险 | 默认处理 |
| --- | --- |
| 低风险、可撤销 | 直接执行＋就近撤销 |
| 普通不可逆 | 一次明确确认，说明对象与后果 |
| 高影响、批量或跨范围 | 确认影响范围，必要时输入对象名称或执行原因 |
| 紧急且业务已有专属规则 | 使用专属确认与反馈，不被普通流程无差别阻塞 |

- 确认强度不能低于风险，也不能让所有操作都承担最高确认成本。
- 删除、清空、覆盖、发布和终止等动作的具体弹窗遵循 [弹层与反馈规范](feedback-and-overlays.md)。

## 识别优于记忆

- 持续显示完成当前任务所需的对象、作用域、筛选、单位、状态和当前步骤，不要求用户跨页面记忆。
- 少量稳定选项使用单选或下拉；大量选项使用可搜索选择器；允许新建值时使用组合输入；用户掌握精确标识时可以保留直接输入。
- 最近使用、合理默认值、历史选择和模板只在系统已有可靠来源时使用，并允许用户检查和修改。
- 自动填充必须说明来源或可验证结果，不静默覆盖用户输入，也不把不确定推断伪装成确定事实。
- 一级界面可以预告下一级的关键状态或数量，但不把所有二级、三级详情同时堆叠到首屏。
- 图标、快捷键和右键操作是效率增强，关键能力仍需可发现的文字或常规入口。

## 表单与向导

- 表单控件、标签、说明、字段间距和分组标题统一使用 [正文组件规格](component-specifications.md)，同一表单行保持控件等高。
- 按用户决策顺序组织字段，而不是按数据库字段顺序堆叠。
- 必填、默认值、格式要求和错误原因在字段附近表达；不要用一段小字解释整个页面。
- 复杂新增流程可以采用“类型/核心参数/其他信息/确认”的分步结构；每一步只保留当前决策所需内容。
- 编辑页面按业务分组，保留已填写内容，避免把向导重新变成一张超长表单。
- 校验错误可定位、可修复；提交失败保留用户输入，并说明是字段问题、权限问题还是服务异常。

## 表格与树

- 表格行高、单元格间距、行操作尺寸，以及树节点高度、缩进和节点操作统一使用 [正文组件规格](component-specifications.md)。
- 表格用于比较和批量处理；树用于层级浏览、选择和管理。两者不要在同一位置承担相同职责。
- 表格列按任务排序，低频列可隐藏或放入详情；长文本使用省略和可访问的完整内容查看。
- 空数据、加载、失败、分页、筛选无结果和批量选择都要有明确状态。
- 树节点的新增、编辑、删除、展开和更多操作应就近出现；节点操作不会因为右键菜单或折行而不可发现。
- 删除树节点时明确影响范围，并按可恢复性和影响程度采用撤销、普通确认或增强确认。

## 状态反馈

界面应能区分初始、加载、成功、空数据、无搜索结果、部分成功、失败、权限不足和离线/网络异常等已由系统定义的状态；具体状态集合和业务含义由产品或系统规范确定。

字段反馈、局部反馈、Toast、Notification、Banner、模态确认和通知中心的选型与统一行为遵循 [弹层与反馈规范](feedback-and-overlays.md)。

- 不把“已加载后台数据”这类正常过程作为打扰性提示；只提示异常和用户需要采取行动的关键结果。
- 状态标签使用统一语义色和文字；不要让颜色本身承担全部含义。
- 长任务使用进度、阶段或可取消状态；短任务使用轻量反馈。
- 错误信息说明发生了什么、影响范围和下一步动作，避免只显示内部异常文本；具体用语遵循 [界面文案、术语与帮助规范](content-and-guidance.md)。
- 不使用持续闪烁或大面积动画表达普通状态；告警或实时变化不能只依赖闪烁，数据刷新也不应导致整个工作区频繁跳动。

## 浅色/深色与可访问性

- 聚焦态、悬停态、禁用态和选中态在两种主题下都可识别。
- 键盘用户可到达主要导航、表单控件、表格操作和弹窗关闭。
- 图标按钮、表单控件、状态消息具有可访问名称或文本替代。
- 不通过极细边框、极低对比度文字或仅颜色差异表达交互状态。
