# UI/UX 审查与验收清单

## 审查顺序

按以下顺序检查，避免一开始陷入像素细节：

1. 任务是否清楚：用户能否理解当前页面、对象和下一步。
2. 信息层级是否清楚：标题、上下文、内容、主要操作和状态是否分层。
3. 操作是否可发现：新增、编辑、删除、筛选、提交和返回是否放在符合预期的位置。
4. 状态是否完整：加载、空、失败、权限、成功和进行中是否有合适反馈。
5. 视觉是否一致：令牌、组件、间距、图标、边框、圆角和密度是否重复可复用。
6. 控件是否克制：按钮是否避免大圆角、胶囊化和不必要的大尺寸，装饰是否服务于任务。
7. 主题是否可靠：浅色、深色、悬停、聚焦、禁用和弹层是否都可读。
8. 极端内容是否可用：长标题、长文本、空数据、多列、深层树和窄窗口。
9. 工作台是否适合持续任务：上下文、主工作区、辅助面板、告警和日志是否互不干扰。
10. 浏览器外部识别是否一致：标签页标题是否能识别当前页面，favicon 是否为产品图标，是否没有口号、重复说明或默认框架图标。

## 严重程度

- **阻塞**：关键操作不可完成、数据含义误导、状态不可恢复、文字/背景无法阅读。
- **高优先级**：主要操作难以发现、页面层级混乱、主题下明显失真、危险操作缺少确认。
- **中优先级**：重复样式、密度不一致、图标/文字冗余、局部对齐问题。
- **低优先级**：装饰、细微间距或非关键动画优化。

## 视觉回归矩阵

至少覆盖：

| 维度 | 检查项 |
| --- | --- |
| 主题 | 浅色、深色、系统主题切换 |
| 产品身份 | 标签页标题、favicon、theme-color、应用壳品牌标志 |
| 状态 | 默认、悬停、聚焦、禁用、选中、加载、成功、失败、空数据、实时刷新、弹窗 |
| 内容 | 短文本、长文本、中文、数字、缺失字段 |
| 布局 | 常用桌面宽度、较窄窗口、缩放、高 DPI、长列表、弹窗/抽屉 |
| 交互 | 键盘操作、快捷键、确认取消、重复提交、错误恢复、未保存状态 |
| 组件 | 导航、按钮、表单、表格、树、标签、分页、通知、数据图表 |
| 工作台 | 固定上下文、多面板、独立滚动、可收起辅助区、实时状态 |

## 交付前检查

- 是否复用了现有组件和主题令牌。
- 基础字号、间距、圆角、控件高度和图标是否来自统一令牌；按钮、输入框、表格、树、卡片和弹层是否遵循正文组件规格，而不是页面内出现相近的临时值。
- 是否新增了不必要的页面级 CSS。
- 是否存在硬编码颜色、重复状态色或不一致圆角。
- 是否出现大圆角普通按钮、胶囊化工具按钮、重阴影、强渐变或玻璃拟态等不符合军工桌面倾向的装饰。
- 同一操作组、表单行和工具栏中的控件是否等高；普通正文控件是否默认使用 32px、紧凑场景才使用 28px、大型控件是否有明确任务理由。
- 普通按钮和输入框是否默认使用 4px 圆角，卡片/面板是否使用 6px、模态框是否使用 8px；偏离是否来自正式设计令牌而非局部视觉偏好。
- 是否给图标按钮提供名称和提示。
- 是否避免浏览器原生 alert/confirm。
- 模态框是否使用统一遮罩并锁定背景交互和滚动；默认点击遮罩是否不会意外关闭表单或确认任务。
- 弹窗初始焦点、焦点陷阱、关闭后恢复、`Esc` 和 `Enter` 是否符合任务风险；危险操作是否未被自动聚焦。
- 弹窗页脚是否右对齐、取消在左、主要操作在右；危险弹窗是否没有反转顺序，主要按钮是否使用“删除”“覆盖”等具体动作。
- 是否避免普通模态嵌套；必要的二级 Alert Dialog 是否最多两层、不重复加深遮罩，并正确恢复父弹窗焦点。
- 字段反馈、局部反馈、Toast、Notification、Banner 和模态确认是否按强度选型；全局提示的位置、时长、最多三条和重复合并是否一致。
- 操作反馈是否匹配实际响应时长；超过 1 秒是否显示局部加载，超过 10 秒是否提供阶段、真实进度、取消或可恢复入口。
- 百分比是否来自可计算的完成量；不确定任务是否避免伪造进度，刷新是否保留现有内容并避免布局跳动。
- 暂时不可用的能力是否禁用并说明原因，只读是否仍可查看/复制，无关或不应暴露的能力是否按策略隐藏。
- 低风险可恢复操作是否优先提供撤销，高风险、批量和不可逆操作是否采用与影响匹配的确认强度。
- 选项控件是否根据数量、是否可搜索和是否允许新建进行选择；自动填充是否可检查、可修改且不静默覆盖。
- 导航、标题、字段、按钮、状态、弹窗和帮助是否使用同一业务术语，是否避免接口名、枚举和开发缩写。
- 错误文案是否说明对象、结果、已知原因或影响和下一步；是否避免拟人化话术、模糊“操作失败”和仅展示错误码。
- 复杂、高风险和低频任务是否有可发现的上下文帮助或正式文档入口，Tooltip 是否未承载关键业务规则。
- 是否实际运行了项目已有构建、单元测试或浏览器检查。
- 深色主题下是否已检查按钮、下拉、复选框、文本域、上传入口、表格、树、弹窗、图表、画布和滚动条，且不存在白色组件、深色文字或默认灰色控件遗留。
- 是否在最终说明中列出未解决的问题和需要用户决定的品牌差异。
- 产品身份、一级导航、当前上下文、阶段导航、页面标题和页面操作是否职责分离，是否没有重复堆叠同一信息。
- 顶部导航或侧边导航的选型是否符合菜单数量、层级、稳定性和任务关系；顶部导航是否无折行，侧边导航是否有独立滚动和收起状态。
- 顶部、侧边、页面标签、分段选择和阶段导航是否采用各自规定的默认选中结构；当前态是否没有使用凹陷或立体按压效果冒充导航状态。
- 全局工具、页面级操作和工作区操作是否位于正确作用域；用户入口是否稳定，全局工具的相对顺序是否一致。
- 已登录状态是否默认显示规范尺寸的头像和用户显示名；角色是否未冒充人名，长名称、无头像和空间不足时是否按规则降级。
- 产品标志、全局图标、上下文栏、标题和面包屑是否符合默认尺寸与状态规格，偏离是否有明确的品牌或任务原因。
- 页面标题或模块名称是否已直接说明任务；若有副标题，是否只补充必要的作用域、状态、限制条件或下一步动作，而非重复标题含义。
- 主标题和各级小节标题是否均未展示框架自动生成的锚点、复制链接或悬浮链条图标，页面定位是否由稳定 URL、路由或明确业务入口承担。
- 跨页面持续生效的当前任务、项目、试验、方案或指标是否保持可见，名称与实际作用域是否一致，子页面是否避免重复展示相同上下文。
- 若采用长页面，是否说明它对应的是连续阅读/填写任务，而不是因为套用了互联网页面模板。
- 若采用工作台，结构区、主工作区和辅助区是否职责清楚，页面级、工作区级和辅助区级操作是否归属正确；是否验证了面板最小宽度、横向比较、键盘操作和告警可发现性。
- 若面向桌面窗口，是否验证了窄窗口、浏览器缩放、高 DPI、多面板和独立滚动。
- 若采用固定工作台，是否验证页面根节点 scrollHeight === clientHeight（页面本身不滚动），以及列表、详情、日志面板分别承担自己的滚动；是否检查了 Grid/Flex 子项的 min-height: 0 和 min-width: 0。
- 若存在滚动面板，是否给主列表、详情和日志保留最低舒适高度；较矮窗口是否优先压缩非核心区域，极矮窗口是否有明确的外层滚动或收起策略，避免出现“有滚动条但只能看到很少内容”的伪工作区。
- 是否未依赖 CDN、远程字体、远程图标、远程图片或在线脚本，离线加载时仍能完成视觉验收。
- 若存在数据密集型表格或树，是否验证了列/节点管理、筛选、批量操作、刷新保持和大数据量状态。
- 若存在图表或分析结果，是否验证了单位、图例、异常/缺失值、主题对比、键盘/表格替代和导出语义；层级、类型和状态是否未仅依赖颜色表达。
- 若存在复杂画布，画布级工具是否就近放置并与页面级操作分离，是否提供缩放、定位、复位等必要能力及图标提示和键盘/按钮替代。
- 若提供快捷键，是否验证了快捷键提示、作用域、输入框例外、焦点反馈、冲突处理和鼠标操作替代路径。
- 是否验证实时刷新不会造成页面跳动，普通状态没有持续闪烁或大面积动画。
- 是否验证浏览器标签页使用统一的“当前页面 · 产品名”标题、产品 favicon 和随构建产物交付的本地图标资源；是否避免页面自行拼接标题或使用默认框架图标。
