# 军事软件工作台设计原则

本文件是面向军工软件、试验平台、装备管理、仿真系统、运维后台和其他桌面任务系统的通用设计规范。它将一组经过验证的界面设计思想转译为可执行的工作台规则，不依赖外部书籍、链接或本机文件。

## 核心原则

### 1. 从功能和任务开始

先描述用户要完成的任务：输入什么、比较什么、做什么判断、提交什么结果、异常时如何恢复。根据任务关系确定页面壳、面板和导航，而不是先决定顶部导航还是侧边栏。

对军事软件的转译：

- 试验控制先确定控制动作、状态监视、结果确认和应急操作，再决定工作台分区。
- 指标设计先确定指标层级、单位、约束和确认关系，再决定树、表格或流程图。
- 运维页面先识别用户需要查看的告警信息、证据和处置入口，再决定仪表盘卡片；告警等级、触发条件和处置时限由业务或系统规范确定。

### 2. 先验证层级，再引入装饰

在方案阶段先验证结构、间距、对比度和优先级；如果低彩度状态下用户不知道先看什么、先做什么，增加颜色不会解决问题。落地时颜色只承担语义和状态，不承担全部层级。

### 3. 用有限系统降低决策疲劳

建立有限的颜色阶梯、文字层级、间距阶梯、圆角层级、阴影层级和控件尺寸。新增值需要解释用途并进入令牌，不能在页面中临时出现一个相近的字号、间距或灰色。

### 4. 用弱化来突出重点

工作台通常同时存在很多信息。突出当前任务的有效方式，经常是弱化非当前导航、低频操作、辅助文字、已完成区域和不相关统计，而不是把主区域做得更亮、更大、更彩色。

### 5. 用空间关系替代冗余边框

优先使用合理留白、相邻背景差异、对齐、轻量阴影和面板层级分隔内容。边框保留给表格边界、输入控件、可拖拽分隔线和确有必要的区域分隔。工作台可以密集，但不应呈现“每个模块一个框”的视觉噪声。

### 6. 控制宽度和尺寸

不是所有区域都应该按百分比流动：

- 导航、工具栏、属性面板、日志区和操作列设置合理的最小/最大宽度。
- 表格列按数据语义设置宽度，避免窗口变化造成关键字段折行。
- 文本说明和报告内容控制行长；不要用超宽文本列填满工作区。
- 图标按实际使用尺寸准备，不把小图标放大成粗糙的大插图，也不把关键图标缩到不可识别。
- 控件默认保持紧凑、矩形和小到中等圆角；用层级、位置和状态表达重点，不用大按钮、胶囊按钮或强装饰制造视觉噪声。
- 实时数据变化尽量局部更新，保持用户当前的滚动位置、选中对象和面板布局稳定。

### 7. 设计真实状态和空状态

不要只设计“有数据且成功”的理想页面。当系统定义未创建、未配置、等待采集、加载中、无搜索结果、部分完成、失败、无权限或已完成等状态时，界面应保持可区分。空状态应告诉用户原因、影响和下一步；没有内容时可以隐藏暂时无意义的筛选、标签和批量操作。

### 8. 使用有意图的产品个性

军工软件的个性更适合来自稳定的色彩语义、清晰的密度、可靠的状态表达、克制的动效和专业的语言，而不是大面积渐变、装饰插画、营销式留白或夸张圆角。品牌差异可以保留，但必须服从任务可靠性。

## 军事工作台推荐结构

一个典型工作台可以按任务组合以下区域，而不是固定套用：

应用壳 / 全局导航
└─ 当前对象与作用域上下文
   ├─ 阶段导航 / 任务工具栏
   ├─ 主工作区：表格、流程、图表、画布或结果
   ├─ 辅助区：属性、筛选、指标、约束或详情
   └─ 状态区：告警、日志、执行进度、异常与恢复动作

设计时回答：

- 哪些区域必须同时可见？
- 哪些区域可以收起或延后查看？
- 哪些状态必须持续可见，哪些只需操作后反馈？
- 用户切换对象或阶段后，哪些上下文必须保留？
- 哪些操作需要固定在工具栏，哪些可以放入行内或更多菜单？

### 结构、操作区和辅助能力职责分离

当任务同时包含对象或结构选择、主体操作和辅助分析时，可以采用“结构区—主工作区—辅助区”的组织方式，但不强制固定为三栏：

- 结构区负责对象选择、层级浏览和定位，不重复承载主体编辑。
- 主工作区承载当前任务的核心查看、比较、编辑或控制操作，并获得主要空间和视觉优先级。
- 辅助区承载属性、详情、分析、解释或 AI 辅助等依赖当前上下文的能力，不替代主工作区，也不与主要操作争夺层级。
- 页面级操作、主工作区操作和辅助区操作分别归属对应区域；不要把不同作用域的操作混入同一工具栏。
- 可收起或切换的区域应保留当前对象、选择、筛选、滚动和画布状态；恢复后不要求用户重新定位。

这是一种职责关系，不是固定布局模板。区域是否并列、收起、使用抽屉或标签页，应根据同时查看需求、最小可用宽度和任务频率决定。

## 长页面的使用边界

适合长页面：任务书/报告阅读、分组表单、审查清单、向导确认和需要顺序阅读的说明。

不宜默认使用长页面：实时态势、试验控制、指标监视、资源调度、复杂表格、树状管理和需要同时查看上下游关系的工作区。此类场景应优先采用固定工具栏、分栏、标签页、抽屉或可调整面板。

## 不应为了形式牺牲领域可靠性

- 不因留白优先而压缩工作台的必要信息密度；应通过分组、层级和可收起面板获得秩序。
- 当系统提供字段名、单位、状态或审计信息时，不因追求极简而隐藏其必要语义；哪些信息必须提供由业务或系统规范确定。
- 不因跳出固有思维而改变用户熟悉的表格、树、确认和导航行为；替代模式必须证明能提升任务效率和可发现性。
- 不把任何具体颜色、像素值、字体或阴影直接当成跨项目标准；它们必须映射为本项目的语义令牌。

## 评审时的转换问题

1. 这个页面是在帮助用户持续操作，还是帮助用户连续阅读？如果是前者，优先工作台；如果是后者，长页面才有正当性。
2. 页面中是否存在多个同等强调的区域？如果有，先降低次要区域，而不是继续增加强调色。
3. 当前边框是在表达交互边界，还是在弥补信息层级不足？后者应优先改空间和背景。
4. 面板和列宽是否服务于数据语义，还是单纯跟随网格比例？
5. 空状态是否阻止用户误以为系统故障，是否给出可执行的下一步？
6. 如果系统提供追溯、状态或风险信息，设计方案是否让用户能看懂、定位和采取下一步动作？本技能不定义这些能力是否必须存在。
