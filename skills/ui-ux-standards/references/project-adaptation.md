# 已知项目适配基线

这份基线帮助技能快速进入当前几个项目，但不是永久真相。每次实际修改前仍需读取代码并以现场为准。

## designer

- 前端位于项目的 web 目录，主要使用 Vue 3、Vite、Vue Router、Element Plus，并混有 React/React Flow 等专用依赖。
- 已有 src/styles/designTokens.ts、src/style.css、主题 store 和上下文栏/导航等公共组件。
- 重点关注：自定义 token 与 Element Plus 变量是否一致、浅色/深色模式、顶部导航与当前项目/试验/指标上下文、流程向导、表格和树操作。
- 不要因为存在历史局部样式而重新引入一套完全不同的组件库或颜色体系。

## ops-system

- 前端位于 web 目录，主要使用 Vue 3、Vite、Vue Router、Element Plus，并维护 src/styles/theme.css 与 src/style.css。
- 现有变量以 --gdos-* 和 Element Plus 变量映射为主，包含企业蓝、浅色和深色模式。
- 重点关注：主题变量的语义化、页面工具栏和表格卡片的一致性、设置页与终端类工作区的密度、深色模式下的表格和浮层。

## aegis-auth

- 前端位于 web 目录，主要使用 Vue 3、Vite、Vue Router、Element Plus，包含客户端和管理端布局。
- 现有变量以 --app-* 和 Element Plus 变量映射为主，拥有侧边栏、认证页、客户端控制台和管理布局。
- 重点关注：认证任务的简洁性、客户端/管理端导航层级、侧边栏和头部的作用域表达、深色模式下的卡片和表格。

## 跨项目收敛策略

1. 先建立语义映射表，例如“页面背景、内容面、主要文字、主操作、危险操作、边框、焦点态”分别对应各项目已有变量。
2. 优先收敛交互语义和组件层级，再逐步收敛颜色值、密度和圆角。
3. 不要求三个项目立即使用同名变量；变量命名和代码组织属于 frontend-coding-standard 的后续范围。
4. 每个项目保留品牌色和业务专用组件，但新增页面必须遵循共享语义和验收清单。
