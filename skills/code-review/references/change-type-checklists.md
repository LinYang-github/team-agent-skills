# 变更类型路由

先按下表选择专项规范，再结合风险清单审查；混合变更可以加载多个技能。

| 变更类型 | 额外读取/关注 |
| --- | --- |
| `.vue`、`.ts`、`.css` 或前端构建 | `frontend-coding-standard`；涉及视觉/交互时再读 `ui-ux-standards` |
| `.go`、服务启动或协议 | `go-coding-standards`；检查上下文、超时、并发和 API 兼容 |
| `.cpp`、`.hpp`、`.h`、CMake | `cpp-coding-standard`；检查所有权、生命周期、ABI、编译器和 Sanitizer |
| API、消息或公共类型 | 检查兼容策略、版本、错误契约、鉴权、限流和契约测试 |
| 数据库 schema 或迁移 | 检查双写/兼容窗口、幂等、锁、备份、回滚和数据校验 |
| Docker、安装包、CI/CD、编排或脚本 | 检查制品来源、权限、密钥、环境差异、健康检查、发布和回滚 |
| 配置、环境变量或密钥 | 检查默认值、注入、校验、敏感信息泄露、版本化和变更审计 |
| 依赖升级 | 检查锁文件、许可证、漏洞、破坏性变更、构建和运行时兼容 |
| 测试、lint 或生成代码 | 检查门禁是否真实生效、生成过程是否可重复、产物是否被正确使用 |
| README、项目文档或注释 | 读取 `common-coding-standards` 的 `documentation-governance.md`；检查入口、链接、命令、版本、配置和实现是否一致 |

专项技能提供“应遵守什么”；本技能仍负责判断变更是否覆盖、证据是否充分以及能否安全交付。
