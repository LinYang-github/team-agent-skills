# 代码与部署风险清单

按变更实际涉及的领域选择清单，不要求每次逐项填满。

## 代码运行风险

- 输入为空、越界、重复、极值、编码或时区变化时是否正确。
- 错误是否被吞掉，重试是否造成重复副作用，超时后是否能恢复。
- 资源是否成对释放，生命周期是否覆盖异步回调和取消路径。
- 并发访问是否有明确所有权、锁顺序、竞态和背压策略。
- 权限校验是否在服务端执行，日志和返回值是否泄露敏感信息。
- 公共接口、配置、数据格式和依赖升级是否保持兼容。
- 日志、指标、追踪是否足以定位失败、性能退化和发布回归。

## 构建与制品风险

- 构建是否可重复，编译器/运行时/系统库版本是否明确。
- 依赖是否锁定、来源可信、许可证和漏洞状态可追溯。
- 制品是否包含所需资源、迁移、配置模板和调试符号策略。
- 目标架构、字符集、时区、路径和权限是否与运行环境一致。
- 镜像或安装包是否以非特权用户运行，是否包含不必要的工具和密钥。

## 配置与运行风险

- 必填配置缺失时是否快速失败并给出可定位信息。
- 默认值是否安全，密钥是否通过密钥管理或环境注入而非提交到仓库。
- 配置变更是否有版本、校验、审计和回滚方式。
- 启动依赖、探活、就绪、优雅退出和信号处理是否匹配。
- 日志轮转、磁盘上限、连接池、线程数、超时和限流是否有边界。

## 数据迁移与发布风险

- 迁移是否幂等、可分批执行、可观测，并评估锁表和容量影响。
- 应用新旧版本在迁移窗口内是否兼容。
- 发布是否有灰度、分批、暂停和人工确认点。
- 回滚是应用回滚、数据前向修复还是不可逆变更；是否经过演练。
- 发布后是否定义验收指标、告警阈值和责任人。
