# 审查报告模板

根据审查模式选择模板，不要求所有模式使用同一套结构。

## 变更审查

1. 审查范围与基线
2. 问题（按 P0 至 P3）
3. 已执行验证及结果
4. 未覆盖项、假设和遗留风险
5. 合并建议

## 全项目工程审查

### 总体评价

概括项目定位、当前阶段、主要优点和最主要的结构性判断。

### 严重问题

列出必须优先解决的问题，说明触发条件、影响范围、证据以及为何会持续造成事故或阻塞交付。

### 潜在风险

列出中长期风险，区分已确认问题、证据充分的风险和待确认假设。

### 可落地改进建议

按 P0/P1/P2/P3 或“现在/近期/触发后”排序。每项包含具体改动位置、验证方式和完成标准。

### 架构演进建议

说明规模扩大 2～5 倍时的瓶颈、应提前解耦的边界、暂不应做的过度设计，以及触发重构的信号。

### 审查依据与限制

记录检查过的目录、文档、命令、运行环境和未能验证的部分。

## 部署交付审查

1. 构建与制品
2. 配置与环境
3. 启动、健康检查与优雅退出
4. 数据迁移与兼容窗口
5. 发布策略与回滚
6. 发布后观测、验收和责任人
7. 阻断项、遗留风险和交付结论

无论使用哪种模板，问题都必须遵循统一的严重性、证据和误报控制规则。
