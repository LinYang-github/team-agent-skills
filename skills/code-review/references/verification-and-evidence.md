# 证据与验证

## 证据等级

优先使用可直接核验的证据：失败测试或构建日志、可复现步骤、调用链、类型/协议契约、schema 差异、配置解析结果、依赖锁文件和部署脚本。仅凭命名或经验推断的问题应降级为待确认风险。

## 验证原则

- 先读取项目提供的命令和 CI 定义，使用项目已有入口。
- 小改动运行最小相关测试；跨模块、协议、迁移或发布改动扩大到集成测试和构建验证。
- 依赖、容器、安装包或跨平台改动应验证制品内容、目标架构和运行时依赖。
- 部署审查至少验证配置模板、环境变量映射、健康检查和回滚脚本的静态一致性；具备安全的本地环境时再做启动/升级演练。
- 不把计划执行、工具未安装或网络不可用写成“已通过”。

## 报告未验证项

记录命令、结果和限制，例如：

```text
已执行：go test ./...（通过）
未执行：生产数据库迁移演练（当前无隔离数据库）
遗留风险：需在发布前验证迁移锁表时间和回滚窗口。
```

验证失败本身是审查发现，应说明失败原因、影响和是否阻断交付。
