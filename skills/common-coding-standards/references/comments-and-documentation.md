# 注释与代码文档

- 注释解释为什么存在约束、取舍、兼容处理或非显然算法，不逐行翻译代码。
- 公共模块、公共 API、配置项、环境变量、事件和错误契约应有可被调用方使用的文档。
- TODO、FIXME 和临时兼容代码说明背景、责任人或责任团队、风险以及移除条件；没有上下文的 TODO 不应长期保留。
- 代码变更后同步更新受影响文档、示例和迁移说明；不保留与实现矛盾的旧注释。
- 示例不得包含真实密钥、账号、个人数据、生产地址或未经确认的协议。
- 复杂流程优先用结构化说明、状态转换或输入输出表表达，避免堆积长段落注释。
- 项目 README、开发/部署/运维文档的分类、目录、元数据和生命周期遵循 `references/documentation-governance.md`。
- 需求规格、变更提案、任务拆解、验收标准和规格状态流转不属于本文件；由独立的 Spec 框架管理。
