# 日志与可观测性

## 分级

统一使用 debug、info、warn、error 等级别。各级别的具体实现由语言和日志库决定，但语义保持一致：

| 级别 | 通用含义 | 典型内容 |
| --- | --- | --- |
| ERROR | 不可恢复的系统错误、严重状态冲突或关键操作失败 | 数据库连接中断、核心任务崩溃、关键写入失败 |
| WARN | 可恢复的业务/运行异常，或需要关注但不代表系统不可用的状态 | 鉴权失败、节点暂时离线、输入缺失、负载受限 |
| INFO | 系统核心生命周期事件和全局配置变化 | 启动、停止、重载、配置生效、关键阶段切换 |
| DEBUG | 常规成功操作、诊断细节和高频事件 | 查询细节、心跳、单次任务成功、调试上下文 |

生产环境默认关闭 DEBUG，并将高频的“操作成功”日志降级为 DEBUG；INFO 只保留能够帮助判断系统生命周期和关键状态的事件，避免成功日志淹没异常。

## 结构与安全

- 日志采用结构化字段，至少在关键请求或任务边界携带事件名、模块、请求 ID、资源 ID、错误码和耗时等可检索信息。
- 一个错误在最接近能补充完整上下文的边界记录一次；下层传递错误时不要重复刷屏。
- 不记录密码、Token、Cookie、密钥、完整身份信息、完整请求/响应体或未脱敏业务数据。
- 日志不能替代异常处理、用户反馈、指标或测试断言；关键流程应根据项目能力补充计数、耗时和成功率指标。
- 第三方 SDK、脚本和生产环境输出必须使用同一脱敏与级别策略，不能因“开发者工具可见”而放松要求。
- 日志内容应支持关联一次请求从入口到外部依赖的链路，但不强制所有项目引入同一种采集平台。

## 轮转与保留

本地文件日志必须有容量和生命周期边界，不能让单个日志文件无限增长：

- 至少定义最大文件大小、历史文件数量或保留天数，以及是否压缩旧文件。
- 大小轮转和时间轮转按运行负载选择；高频服务通常需要大小上限，低频服务也应设置最长保留期限。
- 轮转策略同时考虑总磁盘预算、文件权限、目录可写性和磁盘空间告警；不能只设置单文件大小而忽略历史文件总量。
- 轮转过程应避免丢失正在写入的记录、重复注册输出器和多进程互相覆盖；并发/多进程安全由专项语言和部署方案验证。
- 轮转失败必须进入可观测的告警或错误路径；不能静默退化为无限增长。必要时提供安全的标准错误或集中采集降级路径。
- 操作审计、合规日志和普通运行日志分别定义保留策略；审计日志不能因普通运行日志的短期轮转规则被静默删除。
- 数据库持久化的操作日志同样需要保留、归档、清理和容量监控；具体数据库清理、压缩和 VACUUM 方式放入数据库或语言专项规范。

## 验收

- 可验证各级别在开发、测试和生产环境的开关行为。
- 可验证轮转触发、压缩、历史保留、磁盘空间不足和轮转失败路径。
- 可验证重启、异常退出、并发写入和长时间运行后不会无限增长或重复输出。
