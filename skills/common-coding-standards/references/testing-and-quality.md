# 测试与质量门禁

- 测试范围与风险匹配：纯规则优先单元测试，模块边界使用集成/契约测试，关键用户流程使用端到端测试。
- 成功之外，覆盖空数据、边界值、异常、权限、超时、取消、重复执行、并发冲突和恢复路径。
- 测试使用隔离数据、固定时间/时区/随机种子和可控外部依赖；不依赖生产服务、用户目录、网络状态或执行顺序。
- 每个测试清理文件、数据库、缓存、临时目录、mock、订阅和全局状态；失败时保留足够诊断信息。
- 提交前按项目能力运行格式化、静态检查、类型检查/编译、单元测试和构建；共享基础设施变化时扩大回归范围。
- 不通过删除测试、降低检查等级、静默忽略错误或只测试“成功世界”来制造绿灯。
- 质量门禁的工具和阈值以项目配置为准，本技能不强制所有语言使用同一工具。
