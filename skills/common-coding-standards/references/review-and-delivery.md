# 代码审查与交付

## 审查顺序

1. 先确认行为、边界和安全影响，再看命名、结构和风格。
2. 检查异常路径、权限、敏感数据、资源释放、并发、重试和幂等。
3. 检查公开接口、配置、依赖、迁移、日志和可观测性影响。
4. 最后检查格式、重复代码、复杂度和可维护性，不用风格问题掩盖阻塞风险。

## 交付记录

- 处理模式：审查、设计、实现或回归。
- 目标范围：项目、模块、接口、配置或提交。
- 事实和问题：证据、严重程度、影响范围和复现条件。
- 工程决策：为何采用当前方案，哪些方案被排除以及兼容策略。
- 验证结果：实际运行的命令和结果，不能把计划执行写成已完成。
- 遗留风险：未覆盖的环境、性能、数据、依赖或发布风险。

## 例外和迁移

专项技术限制导致无法完全遵循通用规范时，交付记录应包含例外原因、适用范围、维护责任、风险控制和复评/移除条件。渐进治理优先于无关的大规模重写。
