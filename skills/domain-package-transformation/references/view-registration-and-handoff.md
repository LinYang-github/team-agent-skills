# 注册视图与宿主交接

## 稳定身份与启动地址分离

通用宿主持久化的是领域语义，不是某次运行的 Web 地址。建议的稳定启动身份包含：

```json
{
  "domainId": "example",
  "viewId": "example.resource-workbench",
  "primaryResourceRef": {
    "domainId": "example",
    "resourceType": "resource",
    "resourceId": "stable-id"
  },
  "domainStage": "optional-domain-stage"
}
```

`viewId`、资源引用和领域阶段属于可持久化契约。服务地址、随机端口、Vue/React 路由、查询参数和 `deepLink` 属于当前实例的瞬时结果。不同领域可拥有不同路由体系，不需为宿主强制统一 URL 形状。

## 领域包注册和解析

对可打开的完整页面，领域包清单应声明视图 ID、资源类型、支持的呈现模式以及一个版本化 `launchResolver`。宿主、CLI 和 MCP 调用同一解析能力，由当前领域实例生成同源、一次性的启动 URL。

宿主不应获得 `routeTemplate` 并替换参数；即使模板本身不包含端口，它仍会把领域内部路由版本、编码和部署前缀扩散到宿主。解析器应直接返回已经校验和编码的完整启动地址。

解析器必须：

- 校验视图已注册，主资源类型和 ID 合法且存在；
- 仅接受领域包声明的阶段、焦点资源和呈现模式；
- 从当前受信实例或部署配置确定基地址，不接受调用方传入 `baseUrl`、任意 path 或 `returnUrl`；
- 保留反向代理前缀并对路径、查询值正确编码；
- 只读执行，不创建领域对象、不改变修订、不持久化宿主关系。

领域包可为旧客户端保留 `deepLink` 兼容读取，但新链路不得从它推导当前部署前缀或组装页面地址。

## standalone 与 hosted 壳层

- `standalone` 是直接访问领域产品时的完整应用壳，可包含领域产品标识、任务中心、全局助手、设置和账户。
- `hosted` 是从通用宿主交接进入时的紧凑壳，隐藏领域产品的全局导航，保留当前领域资源、单任务阶段导航和完整业务编辑区。来源返回是可选宿主能力，只有宿主实际提供版本化可调用桥接时才显示。
- 两种壳复用同一单任务页面、应用服务和领域契约，不复制两套业务前端。
- 呈现模式按白名单解析，未知值默认回到安全的 `standalone`；阶段切换只透传已声明的宿主参数。

## 返回上下文

返回上下文是宿主临时发放的不透明值，领域包只校验类型与长度、原样透传，不解析为 URL、不存入领域数据、不用它生成开放跳转。它也不能证明返回能力存在；返回动作只交给已协商的宿主桥接，否则不渲染返回控件，由宿主容器或浏览器自带导航处理。

## 验证清单

- 清单中的完整页视图都有可解析的启动贡献，解析能力在 API、SDK、CLI 和 MCP 中语义一致。
- 验证未知视图、错误资源、资源不存在、非法阶段、地址注入、编码和代理前缀。
- 实测 `hosted` 不嵌套全局壳、`standalone` 完整可用，且两者不因浏览、刷新或返回而改变领域修订。
- 重启本地实例后解析得到新端口，宿主保存的稳定引用仍然可用，旧 URL 不被当作资源身份。
