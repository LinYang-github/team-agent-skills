# 能力与契约

## 能力是稳定的产品语义

领域包清单应以能力为中心，而不是以当前路由、按钮或函数为中心。公共能力必须有稳定标识；若组织没有既定规范，可采用 `<domain>.<resource>.<operation>`。

对每项公共能力至少声明：

- 稳定 `capabilityId`；
- 资源类型和稳定 ID 字段；
- 操作语义；
- read-only、destructive、idempotent 等风险属性；
- 所需权限与确认策略；
- public、compatibility 或 internal 稳定级别；
- Skill、CLI、MCP、API、Web、event 等贡献渠道；
- 契约版本和弃用策略。

同一能力可以有多个渠道，但渠道不得改变业务语义。MCP tool、CLI command 和页面操作应能追溯到同一个能力 ID 和应用服务。

## 从已有页面找出遗漏的业务规则

改造已有产品时，核对页面控件、提交逻辑、服务端校验和业务文档中的字段要求、默认值、保存条件及完成条件。记录规则的来源、适用资源与范围、当前执行位置，重点查找只有页面执行、接口未公开或多个入口判断不一致的规则。

- 区分业务要求与展示行为：必需业务资料、合法引用、逐项分配与合计关系属于领域规则；表格排版、显示精度和编辑控件状态属于页面。页面自行设置的阈值或默认值也可能是历史缺陷，不能直接作为领域规则照搬。
- 规则冲突时结合领域实现、业务文档及实际数据核实含义；证据不足的产品语义列为待确认，不用某个入口现有行为代替业务决策。
- 确认后的规则由领域服务统一执行。预览、应用、完成判定和下游消费复用同一实现；页面与工具展示服务返回的状态及具体缺项，避免各自重算完成条件。
- 明确草稿保存与业务完成的区别。允许不完整草稿时保留缺项状态；进入提交、发布等正式状态的条件按领域规则校验，不能仅因保存成功就判定完成。

验证时通过公开接口提交缺项、冲突或非法引用，检查拒绝或草稿状态是否符合约定，再核对页面、CLI、MCP 等已选择渠道对同一资源的解释。

## 让机器调用方获得完整规则

机器契约应同时表达可校验的结构与正确填写所需的业务含义：

- 定义实际业务结构中的嵌套对象、数组成员、类型、枚举、条件必填及引用关系。固定结构拒绝未知字段，明确声明的扩展字典、外部原始输出等容器可以开放，不以任意对象替代尚未定义的业务结构。
- 说明业务字段的用途、单位、适用范围、取值来源与填写条件。资源 ID 应来自创建或查询回执；需要版本时取得与该身份配套的版本，不要让调用方从显示名猜身份，或把另一类对象的版本套过来。
- 动态算法参数按算法身份提供可执行的输入 schema 或可发现的版本化 schema 引用；仅有参数名、版本号或数值范围不足以说明如何使用。
- 公共发现与指定对象查询容易混用时，拆分入口或显式区分调用模式。错误响应指出非法字段或原值、正确取值来源和修正方式，不静默丢弃未知字段或改写错误身份。
- 从公共契约生成或校验各适配器的结构与说明。存在 MCP 时检查实际 `tools/list` 中的嵌套字段、联合分支、条件与说明，防止转换过程丢失规则；源码声明或工具数量相同不能替代这一检查。说明存在性检查之外，还需核对关键业务含义是否正确。

## 用领域服务承接完整业务动作

梳理目标用例时，检查调用方是否必须重新抄写本系统已有数据、从显示行还原领域对象，或自行拼接结果与证据。此类工作优先收敛为领域服务的用例入口，而不是要求 Agent 复现页面提交逻辑。

- 依赖本领域已保存事实的生成、汇总等动作，由服务在目标资源及流程声明的依赖范围内读取已确认输入。调用方提供稳定资源引用、选项、参数和真实新增输入；外部领域输入仍遵循版本化引用契约，不跨库取数。
- 服务保留原始数据精度、元数据、证据及输入版本。候选或预览可以按稳定标识引用，限制调用方修改的字段，避免确认时重新传抄整个大型结果；应用时检查依赖是否已变化，变化后旧预览失效。
- 可从保存数据确定的事实与计算结果由领域服务组装。人工或 Agent 的解释、取舍理由及补充说明按契约单独保存，不能替换权威事实和来源证据。
- 独立算法、外部数据导入和字段编辑仍可保留合理的底层接口；完整业务动作不等于把所有步骤合并为一个工具，也不得把宿主或跨领域编排移入领域包。

## 契约分层

```text
领域语义和不变量
        ↓
应用服务 / Use Case
        ↓
版本化 API 与事件契约
        ↓
SDK、CLI、MCP、Web 适配器
```

- API 定义跨进程请求、响应、错误、版本和鉴权边界。
- SDK 是 API 的客户端封装，可以生成，也可以手写；它不是第二套服务端业务层。
- CLI 面向人和脚本，将命令参数转换为公共能力调用。
- MCP 面向 Agent，将工具和资源映射为公共能力调用。
- Web 面向人机交互，通过 SDK 或同一 API 调用应用服务。
- 算法库位于服务端领域实现内部，不能直接访问外部系统数据库。

## 最小清单轮廓

具体 schema 可以按组织标准调整，但应覆盖以下语义：

```yaml
metadata:
  packageId: example.domain
  domainId: example
  version: 1.0.0
ownership:
  domainAggregates: [example-resource]
  hostOwned: [work-item, conversation, cross-domain-relations]
resources:
  - id: example-resource
    stableIdField: resourceId
capabilities:
  - id: example.resource.read
    resource: example-resource
    operation: read
    stability: public
    risk:
      readOnly: true
      destructive: false
      idempotent: true
      confirmation: none
    channels: [skill, cli, mcp, api, view]
contributions:
  skills: []
  cli: []
  api: []
  mcp: []
  views: []
  events: []
runtime:
  modes: [按实际部署声明]
```

清单是发现和一致性检查的事实来源，不应包含机器绝对路径、临时端口、源码工作区假设或真实业务数据。

## 写入协议

高风险、不可逆或会改变正式业务基线的写入优先采用：读取当前状态 → 生成预览 → 用户确认 → 携带预览标识、期望版本和幂等键应用 → 回读验证。普通低风险编辑可以采用更轻的交互，但仍要保留并发控制、错误语义和可追溯性。版本冲突不得静默覆盖。

观察与编辑必须分离：打开页面、切换选项、关闭抽屉、刷新或组件卸载不得隐式改变领域修订。编辑态在本地标记 dirty，取消恢复最近已保存基线，显式保存或确认应用才可调用写入能力。服务端应提供字段级或领域动作级更新，避免一个页面使用过期快照整块覆盖聚合。

## Canonical 表示与旧值兼容

- 每个公共字段只定义一个 canonical 枚举或结构，服务端、Web、SDK、CLI 和 MCP 对外生成相同表示。
- 兼容层可在边界读取旧别名并立即规范化，但新写入、计算分派和返回值不得继续生成旧表示。
- 旧值与 canonical 值必须走同一业务分支；不得因为前端未识别旧值而默认到另一算法或规则。
- 测试至少覆盖旧值读取、canonical 新写入、跨渠道语义一致和兼容层未被绕过。

## 一致性验证

- 存在 SDK 时，从 API 契约生成或校验 SDK，阻止 schema 漂移。
- 比较清单、API operation、MCP tool、CLI command 和页面能力映射。
- 验证 public 能力在源码态和安装态具有相同语义。
- 删除或修改公共能力时执行兼容性检查，并提供弃用窗口。
