# 运行与发行

## 区分“领域包”“东西”和“进程”

领域包通常由以下可见交付物组成：

- 一个统一版本的发行集合，可以由一个或多个制品组成；
- 一个稳定 CLI 命令入口；
- 一个或多个长驻服务进程；
- 按 Agent 连接创建的 MCP Server 进程；
- 被 Web 或 MCP Server 加载的静态资产；
- 随包分发但不单独运行的 Skill、SDK、schema 和清单；
- 独立于程序安装目录的配置、日志、runtime 和业务数据。

页面、SDK、Skill、API 定义、算法库和数据库通常不是独立可执行文件。架构图应使用虚线标出进程边界，并另外标注安装包、命令和非进程资产，避免把每个方框误解为一个 exe。

## 典型进程模型（按需）

- 领域后端：需要独立服务时作为长驻进程，承载 API、应用服务、领域规则、算法调用和持久化适配器。
- MCP Server：由 Agent 客户端按连接启动或托管，可以有多个实例，但复用同一领域后端。
- CLI：一般是短生命周期进程；`start` 可以委托系统服务管理器或受管后台进程。
- Web 与 MCP App：通常是浏览器运行环境中的静态前端，不是独立服务进程。

具体产品可以合并或拆分进程，但必须说明生命周期、监听地址、健康检查、日志、失败隔离和升级单元。

需要跨多次 Agent 对话或浏览器会话存活的本地后端，不得依赖编码代理的临时命令会话。由稳定 CLI、系统服务管理器或组合启动器承担启停和健康确认；MCP 连接流程可启动、复用或明确报告后端未运行，但不得假定父 shell 一直存活。

## 项目隔离与显式共享

若领域包以本地项目模式安装且每个业务项目应有独立事实来源，则默认在项目下隔离配置、runtime、日志和数据。运行时发现必须校验进程身份、健康和工作区归属，不能只相信 PID 或固定端口；并发启动需要互斥，未配置鉴权的网络服务只监听 loopback。

若提供本地与团队共享两种模式，共享模式只能由用户显式选择。共享服务不得复用某个项目的本地数据库，并应把认证、租户、workspace、权限、审计、TLS 和限流作为独立安全边界。只提供集中式服务的产品应直接声明其服务边界，不必虚构本地项目模式。

## 程序资产与业务数据分离

- 程序包只包含版本化、只读、可校验的代码和资产。
- 项目或用户目录保存配置、runtime、日志、锁和业务数据。
- 程序卸载不得隐式删除业务数据；数据清理需要独立显式参数和范围校验。
- 数据库路径、服务地址和端口不得依赖源码仓库或当前命令目录。

## 源码态与安装态

存在可安装客户端资产时，建立单一发行布局解析入口，让 CLI、后端、MCP 和安装器从同一版本定位清单及所需贡献。源码态可以使用明确的开发布局，安装态必须通过包资源发现；两种布局的公共能力投影必须一致。

发行构建应先生成被选择的 Web、SDK、MCP 等资产，再把实际贡献与后端、Skill、schema、清单及摘要组成同一版本的发行集合。不要在用户机器运行时临时编译或从源码目录拼接资产。

源码清单与安装清单可以使用不同物理路径，但构建器只能改写贡献资产的位置。移除物理路径后的资源、能力、权限、风险、版本、通道和贡献语义必须完全一致；安装态重写路径时顺便增删能力或改变稳定级别应直接失败。

## 发行完整性

发行索引至少记录包版本、协议版本、贡献版本、构建标识、运行依赖、受管文件和摘要。验证应覆盖缺失资产、版本漂移、摘要不一致、运行时依赖缺失和客户端投影冲突。

若 Web 源码与部署静态资产位于不同目录，构建必须生成可自动校验的指纹（至少覆盖源文件集和资产文件集）。发行和启动门禁必须阻止“源码已更新、实际运行仍是旧页面”；不手工编辑压缩产物来修复不一致。

发行树应按白名单组装，并拒绝测试、缓存、源码映射、开发依赖目录、业务数据和未声明文件。机器可读发行索引至少记录每个受管文件的相对路径、大小和摘要，以及领域包、协议、贡献、运行依赖和构建标识；归档格式存在原生文件索引时，还要验证其覆盖全部发行文件。

可复现性比较规范化发行语义，而不是只比较归档原始字节。时间戳、压缩参数等容器元数据可以不同，但两次独立构建的领域声明、贡献列表、文件摘要、运行依赖和构建标识必须一致；不一致时发布门禁失败并指出语义差异。

## 客户端投影所有权

- 安装器记录自己创建的 Skill、MCP 配置、命令入口、版本与摘要，并通过稳定集成命令安装、状态检查和卸载。
- 重复安装必须幂等；升级不覆盖用户自定义文件；卸载只删除安装器所有的投影，默认保留领域数据。
- 不同客户端可以有不同的 scope 或能力限制；用明确状态和限制描述差异，不为了形式一致绕过客户端支持边界。
