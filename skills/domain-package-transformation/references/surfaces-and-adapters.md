# 交互表面与适配器

## 各表面的职责

| 表面 | 主要使用者 | 负责 | 不负责 |
| --- | --- | --- | --- |
| Skill | Agent | 领域判断、信息缺口、执行护栏、工具选择 | 实现业务存储和算法 |
| CLI | 人、脚本、安装器 | 稳定命令入口、自动化、运行管理 | 复制应用服务 |
| MCP Server | Agent 宿主 | 工具/资源发现、协议适配、MCP App 交付 | 成为跨领域数据库代理 |
| API | SDK、CLI、MCP、Web、外部系统 | 服务端公共契约、错误和版本边界 | UI 流程编排 |
| SDK | 客户端代码 | 类型、序列化、鉴权、重试和 API 易用封装 | 持有服务端事实或业务判定 |
| 单任务完整 Web | 领域用户 | 一个领域聚合的完整编辑和审查流程 | 多任务和跨领域编排 |
| 嵌入卡片 / MCP App | Agent 对话宿主 | 摘要、就绪、预览、确认、跳转 | 承载复杂全流程编辑器 |
| 多任务完整 Web | 通用宿主用户 | 工作项、会话、资源关系和总体进度 | 重写领域内部流程 |

这些表面不是必选套餐。先列消费者和用例，再保留有真实调用方的贡献；没有程序客户端时不必创建 SDK，没有 Agent 调用时不必创建 MCP，没有复杂人工作业时不必创建完整 Web。

## Skill 拆分决策

不要因为多个 Skill 都要理解同一个系统就合并，也不要因为文件容易拆开就机械拆分。逐项比较：

1. 用户意图是否能清晰区分；
2. 授权与副作用是否不同；
3. 所需上下文是否大部分互斥；
4. 维护责任和发布节奏是否不同；
5. 目标 Agent 是否能可靠发现和组合多个 Skill。

领域专家与设施运维通常适合拆成两个 Skill：前者判断业务方案，后者安装、启动、配置、诊断和迁移。它们应共享能力清单、资源 ID、错误分类和安全规则，由同一个领域包安装器成组管理。

以下情况适合一个 Skill：领域规模很小；两类请求几乎总是连续发生；目标客户端只能登记一个入口。此时顶层 Skill 只做意图路由，详细内容仍分别放在 domain 与 operations references，避免形成巨型手册。

## 页面选择

采用最小充分表面。对话、卡片/侧边栏与完整页面是按当前意图选择的表面；它们可以升级，但不是必须依次经过的向导：

- 一句模糊目标、一到三个普通追问、局部解释或条件化建议：自然语言对话，不调用 render 工具。
- 用户明确要求结构化可视化，或多项权威事实、互斥选择、跨字段冲突、结构化差异与一次确认需要共同审阅：卡片。
- 需要持续可见上下文但交互仍短：侧边栏。
- 多字段编辑、图表对比、反复试算或长流程：单任务完整页面。
- 多任务排程、跨领域关系、对话与总体进度：宿主完整页面。

用户已经明确说“打开完整任务页面”“进入领域工作台”或等价意图时，Agent 直接使用无界面的注册视图解析能力取得临时启动地址，再调用宿主原生打开动作；不得先调用 `render_*` 生成跳转卡片。只有用户尚未决定是否进入页面时，才在对话中简短询问，不用卡片代替询问。

嵌入视图的具体加载、错误和可访问性行为遵循团队前端及 UI/UX 规范；本技能只判断它是否属于领域包、承担什么业务职责以及如何通过稳定资源定位。

卡片是决策表面，不是完整页面的缩小版。默认只展示一个主要问题、必要上下文、关键依据与风险、一个主操作，并保留进入领域完整页面的次操作。稳定 ID、API 地址、运行端口和构建版本只在诊断、冲突或审计上下文显示。

Skill、MCP 工具描述和行为评测必须共同锁定触发阈值；不能一处声明“对话优先”，另一处又把首轮 render 调用列为预期工具。至少用一句模糊目标做真实 Agent 回归，断言普通澄清没有 render 调用；用一次明确打开页面的请求断言只调用无界面的视图解析能力、不调用 `render_*`；另用结构化复核或写入预览场景证明卡片仍可按需触发。

## MCP App 初始化与降级

- 把宿主初始 `toolresult`、有界兜底请求和用户刷新收敛到一个请求协调器，不让各视图维护独立竞态状态。
- 初始结果可能在 `connect()` 完成前或后到达。连接完成后不得依据某个瞬时布尔值立即重复调用工具；确需兜底时等待有界事件窗口，且整个初始化最多触发一次。不用任意长 `sleep` 隐藏竞态。
- 用单调请求序号或等价取消机制保证“最新意图获胜”；初始结果、兜底和连续刷新中的旧请求不得覆盖新结果。
- 已有有效内容时，用户刷新开始及后续 MCP 未关联、API 不可达、业务错误或 schema 错误都不得清空最后成功内容；错误只显示非阻断提示，并保留重试/打开完整页入口。只有从未取得初始内容时才使用全页错误。
- 错误类型必须可区分，并给出与类型匹配的恢复建议；不把领域 API 不可达误报为 MCP 未注册，也不通过无限重试隐藏故障。

## 调用路径约束

```text
Agent → Skill 判断 → MCP → API 或应用服务
人/脚本 → CLI → API 或应用服务
Web → 可选 SDK → API → 应用服务
外部系统 → API / event / snapshot
```

同进程 CLI 可以直接调用应用服务，但必须使用与 API 相同的请求模型、校验和错误语义；不能形成只有 CLI 才能访问的平行业务逻辑。
