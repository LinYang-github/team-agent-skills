# 迁移与验收

## 推荐迁移顺序

1. **基线与边界**：保护现有修改，建立功能基线，盘点对象、数据、接口、页面、算法和交付方式，明确领域包、宿主及外部领域所有权。
2. **契约先行**：建立资源、能力 ID、风险、权限、版本和渠道清单；补齐稳定 ID、错误及并发语义；存在事件或 SDK 时再建立对应契约和漂移校验。
3. **收敛业务实现**：把领域规则和算法调用收敛到应用服务与领域层，让 Web、CLI 和 MCP 逐步改用同一应用服务/API。
4. **分离页面职责**：存在人工作业页面时保留领域单任务流程，将工作项、会话、多任务关系和跨领域编排迁往宿主；只在宿主确有嵌入需求时提供卡片或侧边视图。
5. **建立运行和发行**：分离程序资产与业务数据；按实际部署支持本地隔离、集中服务或显式共享；存在安装态时统一源码态/安装态资产发现并形成可搬运发行物。
6. **收紧兼容层**：为旧 API、固定端口、源码路径和旧配置提供可观测迁移窗口；在真实消费者迁移前不删除兼容入口。

## 自动化验收矩阵

### 领域与契约

- 公共能力可追溯到唯一应用服务，多个渠道返回一致业务语义。
- 写入具备预览、确认、幂等、期望版本和回读验证。
- 页面打开、刷新、切换、取消和卸载不产生修订；显式确认只产生一次写入，版本冲突不覆盖数据。
- 兼容读取的旧枚举或结构在边界规范化为 canonical 形式，各渠道不再生成旧值或选择错误业务分支。
- 旧客户端得到明确兼容结果或可操作的弃用错误。

### 所有权与组合

- 领域包可以脱离通用宿主独立完成一个单任务流程。
- 宿主可以把一个工作项关联到零个、一个或多个领域资源，而不修改领域包内部数据模型。
- 外部领域只能通过 ID、API、事件或快照协作，测试能够发现跨库访问。

### 页面和 Agent（存在相应贡献时）

- 业务问题触发领域专家 Skill，运维问题触发设施 Skill；混合问题可以有序组合。
- 卡片、侧边栏和完整页面在各自复杂度边界内工作，深链接能定位稳定资源。
- 宿主保存稳定视图/资源引用，每次通过当前实例解析启动地址；实例重启、端口变化和不同领域路由不会破坏交接。
- MCP App 初始结果在连接前后到达都只渲染一次，无初始结果时最多一次兜底，旧刷新不覆盖新结果，后续调用失败不清空已有内容。

### 本地项目运行和数据（采用该模式时）

- 两个项目默认产生独立 runtime 和数据库，同一项目的多个客户端复用同一后端实例。
- 失效 PID、端口占用、异常退出、含空格路径和并发启动均有测试。
- 共享服务只有显式 URL 才启用，本地未鉴权服务只监听 loopback。
- 卸载默认保留数据，显式清理只影响经过归属校验的目标。

### 可安装发行（存在安装态时）

- 在不含源码路径、缓存和开发依赖的干净环境安装候选发行物。
- 验证 CLI、后端、Web、MCP、Skill、契约和静态资源来自同一构建版本。
- 源码与静态产物指纹一致，后端与 MCP 可从安装包定位资产，不隐式依赖源码绝对路径。
- 重复安装、升级、卸载和回滚可重复执行，不破坏用户自定义文件。

## 架构评估成熟度

1. **功能孤岛**：页面直接耦合数据库或算法，缺少稳定能力契约。
2. **接口化**：已有 API，但不同客户端仍复制业务逻辑。
3. **能力化**：领域边界、能力清单和统一应用服务基本形成。
4. **可交付领域包**：安装态可搬运，Skill/CLI/MCP/Web 可注册并一致发现。
5. **可组合生态**：宿主能够按稳定 ID、权限、事件和快照安全组合多个领域包。

评级必须附带代码或运行证据；不要用目录名称代替能力完成度。
