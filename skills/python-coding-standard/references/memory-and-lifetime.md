# 内存与生命周期

## 引用、视图与借用

- 变量赋值是引用绑定（可变对象）或值共享（不可变对象）；不延长来源生命周期。
- `memoryview` 表示缓冲区视图，`slice` 表示序列视图；二者不延长来源生命周期。
- 不返回指向局部对象、临时对象、栈缓冲区或即将扩容集合的可变视图。
- 接收视图后需要异步保存或跨调用保留时立即复制到拥有类型（`bytes`、`tuple`、`frozenset`）。
- 不把临时 `memoryview`/迭代器保存为成员，不从临时集合创建长期引用。
- `dict.keys()`/`values()`/`items()` 返回视图对象，随原 dict 变化；需要快照时 `list()` 物化。

## 集合与迭代器失效

- 修改集合时确认迭代器失效规则；`list` 增删、`dict` 修改后相关视图可能失效。
- 遍历过程中删除元素使用列表推导或 `[:]` 切片复制，不直接在 `for` 中修改。
- 不把集合元素引用作为长期标识；需要稳定身份时使用领域 ID 或不可变快照。
- 并发读取集合时，只要任一线程可能修改就必须同步或使用不可变快照/`copy`。
- `map`/`filter`/生成器可能延迟执行；多次迭代重新执行源，必要时物化为 `list`/`tuple`。
- 生成器只能迭代一次；需要多次迭代时显式 `list(gen)` 或重新创建生成器。

## 数组、缓冲区与字符串

- 优先 `bytes`/`bytearray`、`memoryview` 和 `array.array`，不用裸 `ctypes` 指针传递长度不明的缓冲区。
- 边界接口同时携带数据和长度；不接受无法验证长度的 `char*` 或内存块。
- 使用 `len()`、`not seq`，不通过哨兵值猜测容器状态；索引来自外部数据时先校验范围。
- 二进制数据使用 `bytes`/`bytearray`；不依赖字符的有符号性。
- 内存复制只用于 trivially copyable 类型，并检查大小、重叠、对齐和字节序；对象序列化不得直接复制内存布局。
- 字符串默认 `str`（UTF-8 在 I/O 边界）；编码/解码通过 `encode`/`decode`，不按字节截断字符序列。
- 考虑其他 Python 实现（Jython/PyPy）效率差异，运算符 `+` 在 CPython 中高效但 Jython 中低，采用 `"".join()` 方式拼接。

## 异步与闭包生命周期

- 默认显式列出闭包捕获；异步、延迟或跨线程闭包禁止无条件捕获 `self`。
- 捕获 `self` 等同持有引用，不延长对象生命周期；必须证明任务结束早于对象释放，或使用取消/弱引用。
- `Future`、`asyncio.Task`、`threading.Thread`、回调注册和 `queue.Queue` 都可能延长生命周期，设计时画出拥有关系。
- 协程中的可变引用必须在 `await` 期间保持有效；不把调用栈借用跨越 `await` 点后修改。

## GC 与引用循环

- Python 使用引用计数 + 循环检测 GC；对象引用计数归零立即回收，循环引用由 GC 定期回收。
- 循环引用对象必须实现 `__del__` 或使用 `weakref` 断环，否则可能延迟回收或泄漏。
- `__slots__` 用于减少内存占用和属性创建；不可变对象优先 `frozen dataclass`。
- `weakref.ref`/`WeakSet`/`WeakValueDictionary` 用于缓存和观察者，不阻止对象回收。
- `gc.collect()` 用于测试验证泄漏；生产代码不依赖手动 GC 控制。
- `tracemalloc` 用于追踪分配来源，定位内存增长根因。

## 全局与静态生命周期

- 避免可变全局对象和跨模块初始化依赖；优先显式依赖注入。
- 模块级可变状态需评估线程安全、重置和测试隔离；长生命周期缓存使用 `WeakValueDictionary` 或 `functools.lru_cache`。
- `threading.local`/`contextvars.ContextVar` 要评估线程/协程长期存活和上下文传播。
- 单例不是生命周期设计的替代；必须说明初始化、并发、重置和测试隔离方式。
- `functools.lru_cache`/`cache` 用于函数缓存，但需评估大小上限和线程安全。

## C 扩展与内存安全

- C 扩展中的引用计数必须正确（`Py_INCREF`/`Py_DECREF` 配对），引用泄漏导致内存泄漏。
- `ctypes`/`cffi` 调用必须验证参数类型、指针有效性和返回值，不盲传用户数据。
- `mmap` 映射必须 `close`；不依赖进程退出回收。
- `array.array`/`struct`/`ctypes` 结构体布局使用明确格式和对齐，不跨平台假设。
- `unsafe` 操作（`ctypes` 指针运算、`mmap` 越界）集中隔离并审查。

## 验证

- Debug/CI 使用 `tracemalloc`、`gc.set_debug` 和内存压力验证捕获泄漏。
- 并发共享内存使用静态分析和并发测试验证，不能仅靠引用计数正确性假设。
- 静态分析重点检查未关闭资源、循环引用、可空类型和 `ctypes` 代码。
- 修复根因，不通过延长所有对象生命周期、全量弱引用或关闭检查掩盖错误。
