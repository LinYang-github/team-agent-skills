# 类型、接口与泛型

## 企业默认结论

- 优先使用值语义、组合和普通具体类型；只有确有运行时多态需求时才引入继承体系。
- 类必须维护明确的不变量；构造完成后对象即处于可用状态，不保留“半初始化”对象。
- 默认让标准库和上下文管理器成员管理资源，使引用计数处理释放。
- 公共接口保持最小、稳定并表达契约；实现细节、缓存和可变状态不得泄露。
- 泛型应通过 `TypeVar` 与 `Protocol` 限定适用类型，不依赖晦涩的鸭子类型作为日常接口说明。

## 类与数据结构

- 仅承载公开数据且没有不变量的被动聚合可使用 `dataclass`/`NamedTuple`；需要封装、不变量或行为的类型使用 `class`。
- 成员变量默认公开（`dataclass`）或私有（下划线前缀）。除被动聚合外，不公开可变数据成员。
- 构造函数完成所有必要校验与初始化；可能失败且失败原因需要返回时，使用命名工厂（`@classmethod`）。
- 按声明顺序初始化成员，`dataclass` 字段顺序与构造参数顺序一致。
- 不使用 `init`/`reset` 后才能使用的隐式两阶段初始化；确有状态机语义时，应将状态显式建模并限制非法转换。
- getter 不应无条件暴露内部容器的可变引用；优先返回值、只读副本、`MappingProxyType` 或受控操作。
- `property` 不应产生调用者不可见的复杂副作用；只读属性使用 `@property` 无 setter。
- 不要提供公有的或受保护的实例字段；需要外部访问的字段增加 property。

## dataclass 与值语义

- `dataclass` 表达数据容器；`frozen=True` 表达不可变值语义。
- `slots=True`（Python 3.10+）减少内存占用和防止属性创建。
- `dataclass` 的 `field(default_factory=...)` 避免可变默认参数陷阱。
- `dataclass` 默认基于身份相等；`eq=True` 生成值相等，`order=True` 生成排序。
- 需要 `__hash__` 的不可变 dataclass 使用 `frozen=True`；可变对象默认不可哈希。
- 需要 `__del__`/`__exit__` 的类型谨慎使用 `dataclass`；自定义 `__del__` 可能干扰 GC。

## 特殊成员与值语义

- 不可变对象优先 `tuple`/`frozenset`/`frozen dataclass`；可变对象使用 `list`/`dict`/`set`/`dataclass`。
- 重写 `__eq__` 时必须同时重写 `__hash__`，并保证一致性；`dataclass(eq=True)` 自动处理。
- 重写 `__del__` 时必须正确处理引用循环和异常，不依赖稳定的全局状态。
- 上下文管理器实现 `__enter__`/`__exit__`；异步上下文实现 `__aenter__`/`__aexit__`。
- 迭代器实现 `__iter__`/`__next__`；生成器函数自动实现迭代器协议。
- 不使用 `null`/特殊整数/空字符串/魔法值代替类型语义。

## 继承与运行时多态

- 公有继承只表达 is-a 关系；代码复用优先使用组合、委托或自由函数。
- 作为多态基类使用的类型，`__init__`/`__del__` 行为需明确；Python 不支持虚析构函数，使用上下文管理器。
- 重写方法不强制 `override` 关键字（Python 无）；使用 `super()` 调用父类方法。
- 构造期间不调用可重写方法完成业务逻辑，避免子类未初始化。
- 避免深继承树、脆弱基类；多重继承优先通过 mixin 和纯抽象基类（ABC）组合。
- 类型转换应是边界性操作。频繁 `isinstance`/`type()` 检查通常说明模型或接口拆分不清晰，应优先重构。
- 多重继承遵循 MRO（方法解析顺序）；菱形继承需理解 C3 线性化。

## 公共接口设计

- 参数和返回值应通过类型注解表达所有权、可空性、单位、范围、线程安全和失败方式。
- 小型可复制类型按值传递；只读大对象使用 `Sequence`/`Mapping` 协议；可空非拥有对象使用 `Optional[T]`。
- 返回值优先于输出参数。多结果使用 `NamedTuple` 或 `dataclass`，避免调用点难以理解的元组。
- 不使用 `bool` 参数切换多个行为；使用 `Enum`、选项对象或拆分函数。
- 参数较多或容易错位时使用 `kwargs` 或选项对象，并为字段提供安全默认值。
- 使用 `Enum` 代替魔法值；使用领域类型（`NewType`）区分单位、标识符和语义不同但底层类型相同的值。
- `Optional[T]` 表达“可能没有值”；`Literal`/`Union` 表达封闭的互斥状态。
- 接口不返回指向临时对象、局部对象或内部易失效存储的视图。

## 抽象基类与 Protocol

- `abc.ABC` + `@abstractmethod` 用于显式抽象接口，子类必须实现。
- `typing.Protocol`（PEP 544）用于结构子类型（鸭子类型带静态检查），不需要继承。
- `runtime_checkable` Protocol 允许 `isinstance` 运行时检查，但只检查方法存在性，不检查签名。
- 抽象基类避免暴露具体实现和可变状态；接口保持最小。
- 自由函数、辅助类型和常量尽量限制到最小可见范围（`_` 前缀或 `__all__`）。

## 泛型与 TypeVar

- 泛型用于表达真实的类型族、协议或零成本抽象，不为减少少量重复而无边界泛化。
- 对外泛型接口优先使用约束（`bound=`/`Protocol`）表达能力要求，并为失败提供可理解的诊断。
- 泛型参数命名表达角色，如 `TElement`、`TKey`、`TValue`；单字母名称仅用于局部、惯用且显而易见的语境。
- `TypeVar` 约束必须明确：`bound=` 上界、`covariant`/`contravariant` 方向，不依赖隐式假设。
- `Generic[T]` 用于参数化类；`ParamSpec` 用于参数化可调用签名。
- `@overload` 用于表达多个签名重载，配合运行时实现分发。
- 协变/逆变只在确实表达方向语义时使用，并验证赋值兼容性。

## 命名空间与可见性

- 所有库代码置于包命名空间，避免全局命名空间污染。
- 实现细节放入 `_internal` 子包、私有模块或 `_` 前缀名称，不视为稳定公共 API。
- `__all__` 显式声明公共 API 表面；未声明的符号视为内部实现。
- 模块名小写下划线，包名小写无下划线；避免与标准库重名。
- 全局变量尽量只在模块内有效，实现方式有 `__all__` 机制或前缀下划线。

## 编译隔离与稳定边界

- 公共 API 减少不必要依赖，能使用 Protocol 时审慎使用，但不得破坏完整类型需求或可读性。
- 抽象/适配器可用于稳定 API、隐藏重型依赖和降低重导入范围；不要为所有小型内部类机械使用。
- 跨包、插件或长期稳定 API 边界优先使用接口加 DTO，不直接暴露内部实现和可序列化内部状态。
- 修改公共类成员、方法签名、基类、类型参数或序列化字段时，必须评估源码兼容与序列化兼容影响。

## 审查清单

- 对象构造后是否始终有效，非法状态能否被类型系统排除？
- 所有权、可空性、生命周期和失败方式是否能从签名读出？
- 是否可以用值语义或组合替代继承与共享所有权？
- 泛型约束和类型错误是否对调用者可理解？
- 公共类型变化是否评估了 API、版本与序列化影响？
