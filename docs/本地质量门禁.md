# 本地质量门禁

本仓库将可机器判定的团队规则固化为本地质量门禁。Skill 负责解释规则和适用边界，`quality-gates.json` 与 `scripts/quality_gate.py` 负责执行；Git Hook 只提供触发入口，不复制规则。

## 启用与停用

macOS/Linux：

```bash
./scripts/manage-git-hooks.sh
```

Windows PowerShell：

```powershell
./scripts/manage-git-hooks.ps1
```

脚本通过仓库本地的 `core.hooksPath=.githooks` 启用 Hook，不修改用户全局 Git 配置。若仓库已经配置其他 Hook 路径，默认停止并提示；确认替换时使用 `--force` 或 `-Force`。

停用时使用：

```bash
./scripts/manage-git-hooks.sh --uninstall
```

```powershell
./scripts/manage-git-hooks.ps1 -Uninstall
```

## 检查时机

| 时机 | 文件 | 检查内容 |
| --- | --- | --- |
| 提交前 | `.githooks/pre-commit` | 暂存文件名、大小、空白错误、冲突标记、敏感信息和远程前端资源 |
| 提交信息生成后 | `.githooks/commit-msg` | 提交类型、范围、动作摘要和长度 |
| 推送前 | `.githooks/pre-push` | 分支命名、受保护分支及项目配置的完整本地命令 |

检查器读取 Git 暂存区中的真实内容，不以未暂存的工作区文件代替。`pre-push` 默认禁止直接推送 `main` 和 `develop`；仓库管理员处理明确授权的特殊操作时，可以临时设置 `QUALITY_GATE_ALLOW_PROTECTED_PUSH=1`，并在操作记录中说明原因。

## 规则配置

`quality-gates.json` 是本地强制规则的唯一配置入口，包括：

- 受保护分支和分支命名格式；
- 提交类型和摘要长度；
- 禁止提交和允许例外的文件模式；
- 敏感内容、远程资源和禁止内容正则；
- 文件大小上限；
- `pre_commit` 和 `pre_push` 阶段执行的项目命令。

不同项目应明确填写自己的构建、静态检查和测试命令，不由通用 Hook 猜测技术栈。例如：

```json
{
  "commands": {
    "pre_commit": ["npm run lint"],
    "pre_push": ["npm run typecheck", "npm test", "npm run build"]
  }
}
```

命令在仓库根目录执行，任一命令返回非零状态即阻断当前操作。

## Agent 接入

支持命令执行前 Hook 的 Agent，可以将待执行命令传给统一入口：

```bash
./scripts/run-quality-gate.sh agent-command -- git reset --hard HEAD~1
```

返回 `0` 表示允许，返回 `1` 表示规则阻断，返回 `2` 表示配置或运行环境错误。各 Agent 只维护调用适配器，不能另建一套命令黑名单。

当前未在仓库中写入特定 Agent 的私有 Hook 配置。原因是不同客户端的事件协议和配置位置不一致；Git Hook 及统一检查器不依赖任何特定大模型客户端。

## 手工执行

执行完整本地检查：

```bash
./scripts/run-quality-gate.sh check
```

本地 Git Hook 可被 `--no-verify` 绕过，因此后续仍应在 CI 中调用同一个检查器，并将结果设置为受保护分支的必需检查。
