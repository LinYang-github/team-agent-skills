# Skill 合并与发布流程

## 日常合并

1. 从最新 `develop` 创建符合命名规范的短分支。
2. 完成修改并执行 `./scripts/validate-skills.sh`。
3. 在 Pull Request 中记录变更、验证和遗留风险，以 `develop` 为目标分支。
4. Review 通过后合入 `develop` 并删除工作分支。

## 正式发布

发布前：

1. 确认工作区没有未预期文件。
2. 执行 `./scripts/validate-skills.sh`。
3. 检查 `manifest.yaml` 的版本、状态和依赖。
4. 从 `develop` 创建 `release/<版本>`，或直接由 `develop` 向 `main` 发起发布 Pull Request。
5. 在 Pull Request 中记录发布范围、验证结果、兼容影响和已知限制。
6. 合并到 `main` 后按版本策略创建标签，团队成员再执行 `git pull --rebase`。

正式版本紧急修复从 `main` 创建 `hotfix/*`，合入 `main` 后必须将同一修复同步回 `develop`。

仓库初始化、远程创建和首次推送是管理员操作，不是日常 Skill 发布步骤；禁止自动覆盖已有远程仓库或改写共享分支历史。
