# team-standards 插件安装与更新

市场名为 `team-agent-skills`，插件名和 pnpm 包名为 `team-standards`，插件根为仓库根目录 `./`。团队默认跟随 `develop` 分支，初始版本 `0.1.0`。以下示例使用当前 GitHub 仓库；内网使用时替换为团队仓库地址。

## Codex

```sh
codex plugin marketplace add https://github.com/LinYang-github/team-agent-skills.git --ref develop
codex plugin add team-standards@team-agent-skills
```

也可以在 Codex `/plugins` 中从该市场安装。新建会话加载插件；按团队已验证的行为，每次启动会话会自动更新市场与插件，保持绑定 `develop`。插件 Hooks 需要信任后才会运行，而且**信任绑定整个插件的内容**：插件每次更新（哪怕只改了一个 skill 文档）后，钩子状态都会变成 “Modified since last trusted - review required”，需要重新信任。已实测验证（Codex 0.164.0）。

- 交互界面启动时会提示 “N hooks need review before they can run”，选择 **Trust all and continue**（或 Review hooks 逐个查看）即可。
- 选择 “Continue without trusting” 或使用无头 `codex exec` 时，Agent 钩子不会运行；此时由项目 Git 钩子兜底检查实际的提交和推送。
- 不要把 Git 钩子的成功安装当作 Codex Hooks 已经启用的证明。

Codex CLI 的 `add` / `remove` 命令可参见 [官方 CLI 源码](https://github.com/openai/codex/blob/main/codex-rs/cli/src/plugin_cmd.rs)；交互安装见 [官方插件文档](https://developers.openai.com/codex/plugins)。

## ZCode

```sh
zcode plugins marketplace add "https://github.com/LinYang-github/team-agent-skills.git#develop"
zcode plugins install team-standards@team-agent-skills
zcode plugins enable team-standards@team-agent-skills
```

更新时先刷新市场，再更新插件，并新建会话：

```sh
zcode plugins marketplace update
zcode plugins update team-standards@team-agent-skills
```

Windows 和内网地址注意事项：HTTPS 仓库地址必须以 `.git` 结尾，再接 `#develop`。SSH 仅使用 `git@host:group/repository.git#develop` 形式；不要使用 `ssh://` 形式。提前配置 Git 凭据或 SSH key / known_hosts，确保同一用户下 Git 能访问仓库。

ZCode 兼容 `.claude-plugin/marketplace.json` 和 `.claude-plugin/plugin.json`。插件启用后，到设置 → Hooks 检查来源及 `Bash` matcher，然后新建 session。见 [ZCode 插件文档](https://zcode.z.ai/cn/docs/plugin) 和 [官方 CLI 安装示例](https://github.com/zai-org/ZCode/blob/main/UI_PLUGIN.en.md)。

## dsh

将 `<p>` 替换为实际 profile 名称，例如 `web`：

```sh
dsh plugin --profile <p> add "git+https://github.com/LinYang-github/team-agent-skills.git#develop"
dsh plugin --profile <p> update team-standards
```

子组仓库地址务必加 `git+` 前缀，例如 `git+https://git.example.com/group/subgroup/team-agent-skills.git#develop`；SSH 依赖可用 `git+ssh://git@git.example.com/group/subgroup/team-agent-skills.git#develop`。凭据必须提前配置，安装过程不会弹出交互登录框。

本包是无构建步骤的私有 pnpm Git 依赖，提供 skills 和脚本文件。安装依赖后，在实际启用的 `dsh-skill-filesystem` 配置中，把 `customSkillDirs` 加上该 profile 下包的 **绝对路径**：

```json
{
  "customSkillDirs": [
    "/实际/profile/目录/node_modules/team-standards/skills"
  ]
}
```

Windows 示例为 `"C:/实际/profile/目录/node_modules/team-standards/skills"`。这是该 provider 的配置片段，不是整个 dsh 配置文件；保留已有扫描目录和 provider 的其他配置。路径应指向 `node_modules/team-standards/skills`，不要指向 pnpm 内部带哈希的存储目录。通过 `dsh --profile <p> --dump-config` 确认合成配置包含此目录，然后重启对应 profile 并检查技能列表。

dsh 不会因为 pnpm 安装本包就自动运行 Claude 格式的 Agent Hooks；需要按下一节手动安装项目 Git 钩子。dsh 更新包之后，再运行安装器同步项目钩子。CLI 参数透传 pnpm 的行为见 [dsh 官方 CLI 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cli-help.md)，扫描路径配置见 [官方 skill-filesystem 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-filesystem/README.md)。

## 启用项目 Git 钩子

在插件安装目录或本仓库根目录执行以下命令。Windows 请在 **Git Bash** 中运行，不需要 Python：

```sh
sh hooks/lib/install-git-hooks.sh "/项目仓库绝对路径"
```

dsh 安装后也可指定包中脚本：

```sh
sh "/实际/profile/目录/node_modules/team-standards/hooks/lib/install-git-hooks.sh" "/项目仓库绝对路径"
```

Codex / ZCode 第一次在 Git 项目中启动时会输出一行安装提示，里面包含当前插件脚本的完整路径。这行提示会作为上下文交给 Agent，措辞要求 Agent 转告用户、未经用户同意不得自行安装（登录会话实测：旧措辞下 Agent 会自行运行安装器）。安装器复制 `commit-msg`、`pre-push` 及规则运行文件到 Git 的 hooks 目录，并写入 `.team-standards-version`。普通仓库位于 `.git/hooks/`；worktree 通过 `git rev-parse --git-path hooks` 定位共享 hooks。安装结果自包含，即使插件旧缓存目录被删除，提交和推送仍受检查。

安装器遇到 `core.hooksPath`（包括 husky、本仓库 `.githooks`）或已有其他工具生成的同名钩子时，以非零退出并保留原文件。不要为了安装插件而删除现有门禁；由项目维护者在原流程中手动集成检查。本仓库的 `.githooks/` 继续执行现有 Python 全量门禁，插件的轻量钩子只检查 Git 规范，不替代全量质量检查。

已启用本插件 Git 钩子的项目，在 Codex / ZCode 的下一次 SessionStart 会静默升级落后的钩子版本，不会降级较新的版本；未启用时只提示，不自动安装。非 Git 目录没有任何输出。每次发版应递增插件和市场清单、`package.json` 中的版本；同一版本不触发重新同步。本仓库的 pre-push 会运行 `scripts/check-plugin-version-bump.sh`：相对 `origin/develop` 改了 `hooks/lib/` 或 `quality-gates.json` 却没升版本号时拒绝推送。冲突或权限问题导致同步失败时保留静默，可手动运行安装器查看诊断。

规则由 `quality-gates.json` 生成。修改配置后运行：

```sh
./scripts/run-python.sh scripts/generate-git-rules.py
```

将更新后的 `hooks/lib/rules.generated.sh` 一起提交。只有生成阶段依赖 Python，日常 Git 钩子不依赖 Python 或 Perl。摘要按 Unicode 字符计数，最多 72 字；类型和分支正则与 Python 门禁一致，包含 `规范` 类型。自动生成的 `Merge `、`Revert `、`fixup! `、`squash! `、`合并:` 提交跳过摘要格式和长度检查。删除远端分支及推送 tag 与 Python 分支校验器一致，不进入分支检查。

受保护分支 `main` / `develop` 默认禁止直接推送，应走合并请求。已有授权的例外可以在操作环境中设置 `QUALITY_GATE_ALLOW_PROTECTED_PUSH=1`；Agent 预检和项目 pre-push 都尊重此变量。

## Windows 与 Agent 钩子协议

运行环境需要 Git for Windows 提供的 bash/sh、sed、grep、awk、wc 等工具及 UTF-8 locale。`hooks/run-hook.cmd` 是 cmd / bash 双语入口，优先查找 Git for Windows 的系统安装、用户安装，然后查 PATH，排除 WSL bash 启动器。路径带空格受引号保护，退出码原样传回。请保留 LF 行尾；本仓库的 `.gitattributes` 为这些脚本固定 LF。

Agent 预检用 Perl 核心模块 `JSON::PP` 解析 stdin JSON，不使用 Python、jq 或 eval。Git for Windows 通常带 Perl。没有 Perl 时预检放行并向 stderr 警告，此时已安装的 Git 钩子仍独立校验实际提交和推送。配置错误退出 1；违规退出 2，并在 stderr 给出中文规则和示例。

2026-10-28 核对的官方接口结论如下：

| 客户端 | shell 工具匹配 | 输入与阻止 | 插件根变量 |
| --- | --- | --- | --- |
| Codex | `Bash`；统一执行工具 `exec_command` 也映射到 `Bash` | stdin JSON 的 `tool_input.command`；退出 2 + stderr 阻止 | 原生 `PLUGIN_ROOT`，兼容 `CLAUDE_PLUGIN_ROOT` |
| ZCode | `Bash` | 同时提供 camelCase 和 Claude snake_case 字段；读取 `tool_input.command`，兼容 `toolInput.command`；退出 2 阻止 | 原生 `ZCODE_PLUGIN_ROOT`，兼容 `CLAUDE_PLUGIN_ROOT` |
| Claude 格式 | `Bash` | stdin JSON 的 `tool_input.command`；退出 2 + stderr 阻止 | `CLAUDE_PLUGIN_ROOT` |

依据：[Codex Hooks](https://developers.openai.com/codex/hooks)、[ZCode Hooks](https://zcode.z.ai/cn/docs/hooks)、[ZCode 插件 Bash 示例](https://zcode.z.ai/cn/docs/plugin)、[Claude Hooks](https://code.claude.com/docs/en/hooks)。因此共用 `hooks/hooks.json`，入口使用 `${CLAUDE_PLUGIN_ROOT}` 和 `Bash` matcher。Codex 文档链接目前重定向到官方 ChatGPT Learn 对应页。

ZCode 官方说明标准 `hooks/hooks.json` 会自动发现；按本交付的显式清单要求，manifest 同时声明该路径，ZCode 会去重并可能记录重复来源诊断。运行时应只出现一组有效钩子，首次安装请在设置 → Hooks 核对。

预检识别引号、转义、`&&` / `;` / 换行串联中的直接 Git 命令，包括创建分支、`commit -m/--message` 和受保护分支推送。它不会执行命令来解析变量、命令替换、Git alias、自定义包装程序、交互输入或脚本文件；项目 Git 钩子负责校验实际提交和远端推送目标，服务端分支保护仍由仓库平台执行。

双语入口改编自 [obra/superpowers 的 run-hook.cmd](https://github.com/obra/superpowers/blob/main/hooks/run-hook.cmd)，保留 Jesse Vincent 的 MIT 版权声明，完整许可见 `hooks/SUPERPOWERS-LICENSE.txt`。

## 卸载

先在每个启用过的项目中卸载自包含 Git 钩子，卸载器同样不覆盖或删除其他工具的同名钩子：

```sh
sh hooks/lib/install-git-hooks.sh --uninstall "/项目仓库绝对路径"
```

然后删除客户端插件：

```sh
codex plugin remove team-standards@team-agent-skills
dsh plugin --profile <p> remove team-standards
```

ZCode 在设置 → 插件 → 管理已安装中卸载 `team-standards`。不再需要市场时可在各客户端的市场管理界面移除 `team-agent-skills`。dsh 还应从 provider 配置的 `customSkillDirs` 中删除对应路径。只卸载客户端包会保留已复制到项目的 Git 钩子，因此项目卸载应先做。
